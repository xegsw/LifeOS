## 背景

`LIFEOS-P2-010` 已完成技术架构候选综合评审，`LIFEOS-P2-011` 已完成技术架构冻结前条件整改包，`LIFEOS-P2-012` 已完成技术架构独立评审。P2-012 的 PM 验收结论为 `Accepted / Pass with Conditions`，用户已确认采纳，并确认：

1. FTS 维护隔离窄测是技术架构冻结前硬条件。
2. Tauri / IPC 最小安全边界窄测是技术架构冻结前硬条件。
3. 当前仍不冻结技术架构，不进入正式 MVP 开发。

本任务的作用是把 P2-010 / P2-011 / P2-012 中已经通过评审的合同、边界、条件和窄测验收口径整合成“技术架构冻结条件最终补丁”。它不是技术架构冻结决定，也不执行窄测。

## 目标

本任务完成后，需要产出一个可供 PM 后续验收和冻结决策使用的最终补丁，明确：

1. 哪些技术架构内容可以成为冻结候选。
2. 哪些内容明确不冻结。
3. FTS 窄测和 Tauri / IPC 窄测的最小验收合同是什么。
4. 两项窄测失败时，技术架构如何降级、暂停或返工。
5. 后续 PM 何时可以考虑把技术架构标记为 `Frozen`。

## 范围

本任务必须覆盖：

### 1. 技术架构冻结候选范围

请明确哪些内容可以作为后续技术架构冻结候选，例如：

- V1 默认单设备、本地优先。
- 本地权威原文与控制账本优先。
- SQLite + FTS-first 作为本地检索主路径候选。
- 派生可重建，向量后置。
- 权威事实 / 可重建派生 / outbox 与 job 职责分离。
- 发布、展示、索引、再派生、导出、恢复、外发前必须重检授权、来源、版本、tombstone / restriction generation、证据与租约。
- Obsidian 仅作为默认关闭、只读、条件适配器与降级合同，不承诺正式启用。
- 同步 / 服务端具体栈后置，不进入当前技术架构冻结默认范围。

### 2. 明确不冻结范围

请明确不得在本补丁中冻结：

- 技术架构整体 Frozen 状态。
- SQLite Schema、API、Tauri capability 名称、IPC 命令签名。
- FTS 表结构、PRAGMA、调度策略、性能 SLA。
- 同步 / 服务端具体栈、设备数、云端权威范围、冲突 UI、生产同步 SLA。
- Obsidian 正式启用承诺、写回、插件、双向同步、真实 Vault 接入许可。
- 真实云 / 第三方模型上线许可、模型供应商、供应商政策合格性。
- 正式 MVP 开发准入。

### 3. FTS 维护隔离窄测合同

请把 FTS 窄测整理为可执行任务输入，至少明确：

- 验证目标。
- 合成数据规模建议。
- 必测场景。
- P0 断言。
- 指标要求。
- 证据包入口要求。
- Pass / Pass with Conditions / Fail 标准。
- 失败降级或返工路径。

重点覆盖：

- 前台权威捕获不等待长索引事务。
- 全量重建期间捕获 p95 / p99 / 最大等待。
- 误报保存数必须为 0。
- 权限、tombstone、restriction generation 泄漏数必须为 0。
- 影子索引或分块重建切换失败可回退。
- 空间不足、校验失败、重建中断时捕获仍可用或明确失败。

### 4. Tauri / IPC 最小安全边界窄测合同

请把 Tauri / IPC 窄测整理为可执行任务输入，至少明确：

- 验证目标。
- 最小可丢弃集成或等价可执行证据要求。
- 必测场景。
- P0 断言。
- 证据包入口要求。
- Pass / Pass with Conditions / Fail 标准。
- 失败降级或返工路径。

重点覆盖：

- Renderer 无任意文件 API。
- 路径规范化、symlink 越界、隐藏 / 排除项、异常编码默认拒绝。
- Obsidian Vault 零写命令、零删除命令、零重命名命令。
- 导出只能写入用户授权目标。
- IPC 响应必须保留内容身份：用户原文、外部来源、AI 派生、AI 推断 / 建议、用户确认。

### 5. 冻结决策前置条件

请明确 PM 后续何时可以考虑冻结技术架构：

- P2-013 本补丁通过 PM 验收并由用户采纳。
- FTS 窄测通过或条件通过且条件被 PM 接受。
- Tauri / IPC 窄测通过或条件通过且条件被 PM 接受。
- 最终补丁引用两项窄测结果或形成补充附件。
- PM / 用户另行明确作出技术架构冻结决定。
