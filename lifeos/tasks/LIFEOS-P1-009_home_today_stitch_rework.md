## 必须整改项

请逐项关闭以下整改项，不要扩大范围：

### M-01｜清除三张候选中的旧运维 / 团队残留

仅整改三张同名候选画面。

必须移除或替换以下与当前候选主叙事无关的内容：

- “当前领域 · IT 运维”
- eBPF
- Nginx
- AWS 账单
- 团队周报
- 服务器 / 故障节点 / Kubernetes / Calico 等运维默认叙事
- 其他会让首页被误读为 IT 运维台、开发者工具、团队工作台或企业后台的内容

允许保留“技术型独立产品构建者”语境，但应表达为个人 Project、用户访谈、产品发布、设计改版、文案复核、独立产品推进等个人外脑语义。

### M-02｜落实当前 Project 及其选择来源

默认恢复态必须明确表达当前 Project，而不是用“当前领域”替代。

必须至少表达以下之一：

- `用户本次选择`
- `沿用你上次确认`

未选 / 暂无可靠建议态必须保持未选 Project，不得跨 Project 拼装恢复或生成建议。  
系统推测只能作为候选，不能静默成为当前 Project。

### M-03｜重做权限 / 离线态的单一当前事实

权限受限 / 离线态必须说明当前事实：

- 当前是离线、来源权限受限，还是两者同时成立。
- 具体影响哪些恢复、来源、AI 建议或同步能力。
- 用户仍然可以做什么，例如继续查看本地已保存内容、继续记录、稍后同步、继续无 AI。

如果使用复合代表态，必须让“离线”和“来源权限受限”的原因与影响可区分。  
不得只用“AI 建议暂停”概括所有问题。

### M-04｜保存状态按当前状态呈现

候选画面只展示当前成立的保存状态。

例如：

- `已在本地耐久保存，离线待同步`

不得在同一当前画面并列展示互斥状态，例如同时展示：

- 保存中
- 已耐久保存
- 离线待同步
- 保存失败

若需要说明其他状态，只能作为状态说明、附注或后续交互状态清单，不得表现为同一时间同时发生。

### M-05｜校准报告与冻结证据

返工后必须逐项核对：

- 返工报告所述内容是否真实存在于候选画面。
- 三张候选状态名称是否与截图、报告一致。
- 旧历史画面是否被明确排除在候选之外。

必须提供三张无编辑器外壳、可读尺寸一致的预览截图，建议路径：

- `lifeos/deliverables/evidence/LIFEOS-P1-009/01_default_recovery_preview.jpg`
- `lifeos/deliverables/evidence/LIFEOS-P1-009/02_no_reliable_suggestion_preview.jpg`
- `lifeos/deliverables/evidence/LIFEOS-P1-009/03_permission_offline_preview.jpg`

如无法取得无编辑器外壳截图，必须说明原因，并提供当前能取得的最佳替代证据。

### M-06｜复核五类身份的首屏可读性

三张候选状态中，如出现相关内容，必须避免混淆：

- 用户原文
- 外部来源
- AI 整理
- AI 推断 / 建议
- 用户确认内容

默认态应保留并强化现有身份标签。  
降级态和无建议态中的最近痕迹、外部内容或可继续入口，不得被误认为用户确认事实。  
无需把完整 Source、Authorization、AuditEntry 或清理流程平铺在首页。
