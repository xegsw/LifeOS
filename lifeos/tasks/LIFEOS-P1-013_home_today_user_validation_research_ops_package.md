## 背景

LifeOS 当前处于 Stage 1：V1 定义。

当前已冻结：

- V1 范围 V0.1
- 首页 / 今日页 PRD V0.1
- 首页 / 今日页三张 `LifeOS 精修版` 静态关键原型 V0.1

`LIFEOS-P1-012` 已完成首页 / 今日页用户验证计划与测试脚本，并通过 PM 验收为 Accepted。P1-012 只是验证计划，不代表用户验证已执行或通过。

在正式联系外部参与者、执行访谈或处理真实 / 等价中断 Project 材料之前，必须先建立研究运营包，确保招募、筛选、知情同意、补偿、排期、数据保留、删除、录音录屏、内部走查和停止条件都可执行、可审计、可回收。

本任务的目标不是扩大研究设计，也不是执行用户验证，而是把 P1-012 转化为可安全执行的研究运营材料。

## 目标

本任务完成后，应回答：

1. 如何招募并筛选符合 V1 第一目标用户的参与者，而不诱导其说出预期答案？
2. 如何向参与者解释研究目的、数据使用、录音录屏、退出和删除权利？
3. 如何处理真实 / 等价中断 Project 材料，避免泄露敏感信息或让 LifeOS 过早接触不可控隐私数据？
4. 如何安排两批用户验证、内部走查、场次准备、场次结束、数据整理和销毁？
5. 在什么条件下可以启动第一批 4 名正式用户验证？什么条件下必须暂停？

## 范围

本任务必须覆盖：

- 招募文案：面向技术型独立产品构建者，避免过度承诺、避免暴露理想答案。
- 筛选问卷：包含 P1-012 的入组条件、排除条件、样本配额、判定规则和记录字段。
- 知情同意材料：包含研究目的、参与者权利、可跳题 / 可退出 / 可撤回、录音录屏单独同意、补偿、数据使用范围。
- 隐私与数据处理规则：最小采集、脱敏、访问名单、保留期限、删除 / 销毁流程、 accidental secret 处理、真实 / 等价 Project 材料处理边界。
- 研究运营流程：招募 → 筛选 → 排期 → 开场核验 → 静态刺激物哈希核验 → 访谈执行 → 结束确认 → 记录整理 → 数据归档 / 删除。
- 内部走查清单：主持词、计时、刺激物展示、截图哈希、记录表、严重度判定、停止条件。
- 第一批正式验证启动门槛：哪些材料齐备、哪些 PM 确认完成后，才允许联系外部参与者。
- 暂停 / 停止条件：材料哈希不一致、参与者暴露敏感信息、同意缺失、目标用户不匹配、研究者诱导、数据处理边界不清。
- 后续第一批验证报告所需的记录字段和轻量输出结构。
