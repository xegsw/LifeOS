# LIFEOS-P3-082｜三张冻结今日页最小本地 UI 前置验证能力包

## 授权与安全语境

LifeOS 是用户本人拥有并明确授权维护的本地项目。用户已选择“单独授权首项真实能力前置验证”，并明确将目标限定为三张已冻结今日页的最小本地闭环。本任务只在指定本地工作区、新建隔离工程目录、用户主动手动输入的少量非敏感文本与本地浏览器会话内进行防御性软件工程、UI 实现和本地回归验证。

不涉及外部目标、未授权访问、真实凭据、网络扫描、真实攻击、持久化、数据窃取或安全控制规避。任务中的权限、离线、撤回、失败和边界术语仅用于实现并验证本项目内部防御性体验，不授权扩大范围。

## 状态、模型、会话与授权

- 状态：`Ready / Task-card Delivery Authorizes Execution`。用户将本任务卡路径发送至新建隔离 Codex 工程会话，即授权执行本卡范围。
- 推荐会话：新建隔离 Codex 工程执行会话；不得复用 P3-079 工程执行、P3-080 独立评审、P3-081 阶段治理或其 PM 验收会话。
- 推荐模型：`gpt-5.6-terra`；推荐推理强度：`high`。
- 允许降级：`gpt-5.6-luna` + `high`；后备：`gpt-5.5` + `xhigh`。实际降级必须记录原因。
- 禁止降级／必须回报：P0/P1、设计冻结冲突、Evidence 冲突、真实数据范围扩大、任何外部通道、Tauri/IPC、文件写入、网络、风险／冻结／基线／Stage 4 问题。

## 目标与三页冻结设计约束

在新目录 `lifeos/engineering/LIFEOS-P3-082/` 实现一个无需安装依赖、无需网络、可由用户本地打开的最小交互 UI，忠实承接三张已冻结静态关键原型的**状态与信息层级**，而非声称像素级复刻或重新设计：

1. `今日 - 默认恢复态 (LifeOS 精修版)`：当前 Project、从这里继续、用户已确认的今日安排、快速捕获和低打扰的“AI 未启用”边界。
2. `今日 - 暂无可靠建议 (LifeOS 精修版)`：未选 Project／证据不足时明确显示“暂无可靠建议”，并只提供选择 Project 或先记录的继续路径，不虚构建议。
3. `今日 - 权限受限·离线 (LifeOS 精修版)`：明确区分本地保存、离线、来源／处理权限受限和用户已确认行动；不得把任何状态表述为 AI 已确认或已处理。

本包只验证本地 UI 的可操作性与用户理解边界。它不冻结动态交互、视觉实现、响应式、可访问性或技术栈；不构成真实耐久 MVP、真实导出、真实 AI／权限运行链、风险关闭或 Stage 4 准入。

## 允许范围

- 允许修改：仅 `lifeos/engineering/LIFEOS-P3-082/`、本任务交付物、Evidence、局部预检报告；可新建纯本地 HTML/CSS/JavaScript 与无敏感的测试／截图／说明。
- 允许的手动体验数据：用户可在打开本地页面后主动输入**最多三条短文本**（例如 Project 名、当前停点或下一步）；Agent 只可用非敏感占位／合成文本进行自动测试，不得读取、导入、搜索、复制或上传用户既有文件、剪贴板、浏览器资料、真实 DB 或其他项目数据。
- 数据边界：手动输入仅保留在当前浏览器页面会话内；刷新或关闭页面后可丢弃。不得写入用户文件、系统目录、浏览器持久存储、真实 DB 或任何外部服务。
- 允许用户自行以 `file:` 方式打开 `index.html`；不得启动 HTTP／WebSocket 监听器、调用网络、加载远程资源、安装依赖或使用 Tauri/IPC。

## 明确非范围与停止条件

- 不修改三张冻结 Stitch 原型、PRD、设计资产、P3-079／080 工程、历史 Review／Evidence 或任何项目账本。
- 不使用真实个人文件、既有笔记、真实用户 DB、Vault、Tauri/IPC、网络／云／第三方、AI 消费、导出、同步、多设备、L3、外部用户或文件系统读写。
- 若实现需要持久化、HTTP 服务、Tauri/IPC、访问本地文件、读取浏览器／系统资料、真实 AI 或扩展至第四页面，立即停止并回报 PM。
- 不关闭／重开风险、不恢复工程基线、不冻结 Schema/API 或资产、不进入 Stage 4。

## 必须实现与验证

1. 三态页面可从明确、可见的本地状态切换入口进入；状态不能混淆：默认恢复态、无可靠建议、权限受限／离线。
2. 默认恢复态支持用户在当前会话输入原文并经显式确认后显示“你的记录／原文”；未确认、空文本或模拟失败不得声称已保存。
3. “今日安排”只显示用户已确认的行动／承诺；AI 区域必须保持关闭或明确标为“AI 未启用”，不得生成、推断或暗示 AI 建议。
4. 无可靠建议态不得填充虚假重点；必须展示具体缺口与两条受控路径：选择 Project、先记录当前停点。
5. 权限受限／离线态必须分别显示：本地会话中的保存状态、离线状态、受限的来源／处理边界与不生成建议的原因；用户确认内容仍可见。
6. 在干净浏览器会话中人工演练：首次进入、三态切换、确认保存、未确认／失败、关闭态、刷新后不遗留手动内容；保存截图、操作日志、逐项结果、源码 hash、Manifest 与“冻结状态／验收标准 → 测试 → Evidence”矩阵。
7. 静态检查确保没有远程 URL、网络 API、Tauri/IPC、文件 API、浏览器持久存储（`localStorage`、`indexedDB`、Cookie）、AI／模型调用、导出、同步或外部用户通道。
8. 提交前由执行侧完成包内自检；同范围发现的问题在本包内修正。明确 P0/P1/P2/Unknown/Not Implemented 与未覆盖项。
