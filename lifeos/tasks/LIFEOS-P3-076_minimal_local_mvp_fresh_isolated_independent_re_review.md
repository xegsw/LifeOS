# LIFEOS-P3-076｜最小本地 MVP 受控运行时全新隔离独立工程／体验复评

## 授权与安全语境

LifeOS 是用户本人拥有并明确授权维护的本地项目。本任务仅在指定本地工作区、P3-075 当前 hash 的只读工程资产、只读 Evidence 与非敏感测试文本范围内进行防御性代码审查、反例验证与本地回归测试。

不涉及外部目标、未授权访问、真实凭据、网络扫描、真实攻击、持久化、数据窃取或安全控制规避。任务中的权限、失败、攻击性反例、路径或边界术语仅用于发现并修复本项目内部防御性缺陷，不授权扩大范围。所有删除、权限、外部写入和重大行动仍须遵守既有用户确认与安全关卡。

## 状态、独立性与模型路由

- 状态：`Ready / Task-card Delivery Authorizes Execution`。创建任务不构成执行；用户将本任务卡路径发送到符合下方隔离要求的新专项会话，即授权在本任务卡范围内执行，无需额外口令。
- 必须使用全新、与 P3-075 执行会话及 PM 验收会话隔离的 Codex 专项会话；不得复用或继承其测试、反例函数或结论。
- P3-075 工程、交付物、执行侧 Evidence 与 PM Evidence 均只读。独立 runner、结构化结果、日志和 Manifest 必须 task-local 新建。
- 推荐模型：`gpt-5.6-terra`；推荐推理强度：`high`。
- 允许降级模型：`gpt-5.6-luna` + `high`。
- 禁止降级条件：发现 P0/P1、Evidence 冲突、独立性无法证明、真实能力／风险／冻结／阶段问题时停止回报 PM。
- 必须升级条件：发现范围扩大、真实能力默认关闭失效或与冻结合同冲突时停止回报 PM。
- 后备模型：`gpt-5.5` + `xhigh`，仅在记录原因后使用。

## 独立验证要求

1. 自建 task-local 黑盒 runner；不得导入、调用、复制 P3-075 执行侧 `tests/test_runtime.py` 或 `run_self_check.py` 作为主要反例实现。
2. 在新建临时副本运行，覆盖首次操作、幂等重复、关闭重开、空输入、缺保存确认、缺下一步确认、同键冲突、提交前失败、未知项目和审计／半成品边界。
3. 单独静态核查禁止网络、云、Tauri/IPC、真实路径／文件、导出、Vault、AI 消费、同步、多设备、L3 和外部用户通道。
4. 核验 P3-075 当前 hash 与历史 P3-075 提交、P3-075 PM Evidence 均未被覆盖；保存独立 runner、逐项结构化结果、日志、hash、Manifest、复跑命令和验收→反例→Evidence 矩阵。
5. 明确报告 P0、P1、P2、Unknown、Not Implemented 数量。发现 P0/P1、明确合同违反、Evidence 冲突、独立性不足、越权或默认关闭失效，必须判定 Rework 或 Blocked，不得以测试数量抵消。
