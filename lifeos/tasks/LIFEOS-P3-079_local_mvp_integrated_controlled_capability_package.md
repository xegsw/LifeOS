# LIFEOS-P3-079｜本地 MVP 整合受控能力包

## 授权与安全语境

LifeOS 是用户本人拥有并明确授权维护的本地项目。本任务仅在指定本地工作区、新建隔离工程目录、非敏感测试文本、task-local SQLite 与系统临时副本中进行防御性软件工程、集成验证、代码审查与本地回归测试。

不涉及外部目标、未授权访问、真实凭据、网络扫描、真实攻击、持久化、数据窃取或安全控制规避。权限、撤回、恢复、失败、反例与边界术语只用于验证本项目内部的防御性缺陷，不授权扩大范围。

## 状态、模型与隔离

- 状态：`Ready / Task-card Delivery Authorizes Execution`。用户将本任务卡路径发送到新建隔离 Codex 工程会话，即授权本卡范围内执行。
- 推荐模型：`gpt-5.6-terra`；推荐推理强度：`high`；允许降级：`gpt-5.6-luna` + `high`；后备：`gpt-5.5` + `xhigh`，须记录原因。
- 禁止降级／必须回报：P0/P1、Evidence 冲突、越权、默认关闭失效、真实能力、风险／冻结／基线／Stage 4 或冻结合同问题。
- 会话：必须新建隔离 Codex 工程会话；不得复用 P3-063、P3-067、P3-075、P3-077 的执行或独立评审会话。

## 目标与范围

在新目录 `lifeos/engineering/LIFEOS-P3-079/` 交付一个**单一可操作的合成闭环**：操作者通过一个本地 CLI，用固定非敏感测试文本完成“显式确认保存 → 来源／状态可见 → 精确权限预览与 grant／deny／撤回 → 受控恢复预览与确认恢复 → 审计与失败披露”。

该包可合并实现、回归、必要补测、Evidence 整理和文案对齐；P3-063／067／075／077 仅作只读语义与反例输入，不得覆盖或调用其执行侧 runner 作为本包主证据。

## 明确非范围

不得使用真实个人数据、真实用户 DB、真实用户路径／文件、Vault、Tauri/IPC、网络、云／第三方、AI 消费、文件导出、同步、多设备、L3 或外部用户。不得关闭／重开风险、恢复工程基线、冻结 Schema/API 或资产、进入 Stage 4。

## 验收标准与包内自检

1. 只有明确确认后的非敏感测试文本才能保存；失败或未确认不得声称已保存。
2. 操作者可查看来源、当前状态、权限目的／位置／处理者／有效期与恢复预览；所有允许仅返回 `allowed_local_synthetic`，不得产生外部动作。
3. 默认拒绝；唯一精确 grant + `CONFIRM` 才允许；deny 优先；歧义、过期、撤回、错误确认或绑定不匹配均 fail-closed。
4. 保存、拒绝、撤回、恢复、失败与阻断均形成 task-local 审计；重启后审计与撤回／阻断状态仍可追溯。
5. 故障注入时不留下半成品；恢复须显式确认，不能复活已撤回／被阻断内容；重复命令幂等且冲突可见。
6. 在干净临时副本完成端到端首次、重复／幂等、重启、原子失败、拒绝／阻断和静态关闭态演练；保留可运行 runner／测试、逐项结构化结果、日志、快照、hash、Manifest、复跑说明及“验收标准→测试→Evidence”矩阵。
7. 核对历史只读资产未被覆盖；静态检查无网络、云、Tauri/IPC、真实路径／文件、Vault、导出、同步、多设备、AI 消费、L3 或外部用户通道。
