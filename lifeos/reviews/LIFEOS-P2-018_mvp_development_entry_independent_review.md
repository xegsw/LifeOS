## 评审结论摘要

1. **[已验证事实]** 第一目标用户、第一场景、V1 范围、核心领域模型、AI 权限与信任模型、首页 / 今日页 PRD、三张静态关键原型及技术架构 V0.1 合同均已有明确基线；SP-01 至 SP-09 及两项架构窄测已完成并获采纳。
2. **[独立判断]** P2-017 关于“材料足以进入准入评审”的判断成立，但其“硬门槛基本齐备”不能外推为无条件 Stage 3 准入。关键缺口是 Gate 5 只有计划、没有结果，关键原型也没有真实用户或等价行为验证；R-0040 仍为 `Open / Conditional`。
3. **[独立判断]** 在“仅本人自用、单设备、本地优先、非商用、无外部用户、外部能力默认关闭”的严格边界内，可以接受 Gate 5 的有限例外，并建议 PM 进入最终准入决策；例外只允许构建和验证冻结 V1 的最小闭环，不证明目标用户价值、留存、付费或 Beta 准入。
4. **[结论]** R-0040 不阻塞领域核心、合成数据和无广泛文件能力的最小工程实现；它阻塞真实 Tauri 文件能力、真实 Vault、文件导出路径扩权及任何新增 IPC / capability 的启用。首次真实 Tauri 集成本身即触发矩阵迁移复测。
5. **[结论]** Schema、API、具体 Tauri 配置和正式导出格式尚未冻结，不构成启动有限工程实现的阻塞；它们必须受已冻结语义与架构合同约束，并以迁移、合同测试和风险—测试追踪防止实现反向改写冻结资产。
6. **[建议｜需 PM / 用户确认]** 仅作“有限 Stage 3 / 自用 MVP 最小切片”条件准入；在 PM 验收和用户确认前，正式 MVP 开发仍为 `Blocked / Not Allowed`。

## Gate 1-5 逐项评审

### Gate 1｜产品一致性：Pass

有限工程目标仍是个人外脑的“捕获—可信保存—Project 恢复—零或一个候选下一步—用户反馈”闭环，服务第一用户与第一场景。同步、企业后台、运维总览、全局任务墙和连接器广度均不属于准入范围。

### Gate 2｜数据与来源：Pass with Conditions

冻结语义和 Spike 已证明用户原文、外部来源、AI 派生 / 推断 / 建议、用户确认内容可以分离并追溯；四类命令、tombstone / generation、导出不复活和派生可重建也有合同基础。条件是正式实现必须把依赖登记、消费前重检、来源 / 版本 / 身份包络、活跃阻断与导出 / 恢复不复活做成首批端到端验收，不得把领域对象机械固化为一组表或接口。

### Gate 3｜AI 权限与信任：Pass with Conditions

六维授权、强制政策包络、默认拒绝、对象级确认、重大动作确认、Feedback 追加历史和高风险场景边界均已明确。有限准入期真实云 / 第三方模型必须关闭；可使用确定性 stub 或纯规则恢复。任何真实处理者启用前须完成处理者政策、地区 / 子处理者、训练 / 评估、保留 / 删除和最小外发评估，并另经 PM 决策。

### Gate 4｜技术可行性：Pass with Conditions

单设备、本地优先、SQLite + FTS-first、权威 / 派生 / outbox 分责足以支撑最小闭环；R-0039 已关闭。R-0040 不阻塞纯领域逻辑和合成数据实现，但真实 Tauri 集成、能力变化、Obsidian、导出或广泛文件 scope 启用前必须迁移 P2-015 矩阵，P0 失败为零；复测前相关能力关闭。真实数据还必须等待正式实现自身的耐久、备份恢复、删除 / 撤回和基础导出验收，不能直接引用 Spike Pass。

### Gate 5｜用户价值验证：Pass with Conditions（自用 MVP 有限例外）

P1-012 是可执行计划，但没有一手结果，故 Gate 5 不能记为无条件 Pass。考虑用户已明确暂停外部验证，且当前目标是本人自用、非商用、无外部用户，本评审接受一次范围受限的例外：用可运行最小闭环获取本人行为证据。该证据只回答“对当前本人场景是否可用”，不回答目标用户群、学习成本、导入意愿、留存、付费或市场价值。

## Gate 5 自用 MVP 有限例外

### 适用边界

- 单一用户、单设备、本地优先；不邀请外部用户，不发布 Beta，不形成商用 / 开源 / 市场结论。
- 只实现冻结 V1 的最小闭环；Obsidian、同步、真实模型、外部自动化和 L3 自动动作默认关闭。
- 初始只用确定性合成数据：数据不得来自真实个人 / Project，不含真实身份、路径、凭据、秘密或可反向识别内容，并可随时丢弃重建。
- 正式实现完成对应安全门后，最多启用“低敏真实副本”：须由用户逐项筛选，不含凭据 / 私钥、健康 / 财务 / 法律等高风险内容，原系统或已验证备份中仍有可恢复权威副本，且可随时撤回停用；不得接入重要、敏感或唯一副本。
- 任何其他人参与试用、旁观任务测试或提供真实 Project 材料，均视为外部用户参与并使本例外失效，不能以“非公开”规避 Gate 5。

### 补偿机制

- 继承 P1-012 的反证思路，记录代表性 Project 切换中的恢复是否可核对、证据缺口是否诚实、候选是否需纠正、用户能否完成反馈与撤回，以及失败原因；不得只记录页面打开或功能点击。
- 把动态交互、响应式、键盘操作、焦点、可访问性和“减少动态效果”纳入工程验收；冻结静态图不能代替这些检查。
- 建立实现级风险—测试追踪：每条冻结不变量、R-0040 触发器、四类命令、导出 / 恢复和真实数据启用门均须有可复跑证据。

### 失效与退出条件

- 任一用户原文丢失 / 静默覆盖、身份混淆、越权读取 / 外发、删除 / 撤回后仍活跃、旧数据复活、重大动作未经确认：立即停止真实数据和相关能力，回退合成夹具并整改。
- 真实 Tauri 复测出现任一 P0 失败：关闭失败 capability / IPC；Vault 边界失败则 Obsidian 保持关闭，导出边界失败则文件导出保持关闭。
- 在约定的自用验证窗口内仍不能稳定恢复 Project 上下文、核对来源或完成下一步反馈：停止扩功能，回到产品 / 体验问题复核；不得用增加模型或连接器掩盖闭环失败。
- 一旦引入外部用户、商业化 / 开源发布、多人 / 多设备、真实敏感数据或对外价值主张，本例外自动失效，必须恢复正式 Gate 5 验证与相应安全评审。

## 可接受与不可接受的准入条件

### 可接受

- 以合成数据、deterministic stub、默认关闭外部能力进入最小纵向切片实现。
- Schema、API、UI 状态机在冻结合同内逐步演进；实现细节由证据决定，不预先冒充冻结资产。
- 将真实 Tauri、Vault、导出、真实数据与第三方处理拆成独立能力启用门。

### 不可接受

- 以“仅自用”为由降低原文保护、授权默认拒绝、身份区分、重大动作确认、活跃阻断或不复活底线。
- 先接入真实 Vault / 敏感数据 / 云模型，再补权限、删除、导出或 R-0040 复测。
- 把自用日志写成目标用户验证、留存 / 付费证据，或把有限准入写成全部 Stage 3 风险已通过。

## 必须迁移为工程硬约束的清单

1. 冻结 V1 Must / Should / Not Now 与最小纵向闭环，禁止开发中静默扩范围。
2. 用户原文与不可变版本、Source / Artifact、Derivation、Feedback、Authorization、重要 Link、AuditEntry 的身份和追溯不变量。
3. 权威提交后才显示“已保存”；FTS / AI / 队列失败不得影响权威保存或伪造成功。
4. 所有展示、索引、再派生、导出、恢复、外发入口重检当前授权、来源、版本、tombstone / generation、证据与租约。
5. 四类命令分离；撤回 / 删除先活跃阻断，物理清理状态诚实，恢复 / 重导入不得复活。
6. R-0040 触发器、P2-015 矩阵及能力关闭规则；真实 Tauri 复测前无广泛文件、Vault 或导出能力。
7. 合成 → 低敏非唯一副本 → 更高敏感数据的分级门；本次有限准入不授权重要 / 敏感唯一数据。
8. Obsidian、同步、真实云 / 第三方模型、向量和 L3 均默认关闭；启用须独立证据与 PM 决策。
9. 动态关键状态、可访问性、基础导出 / 恢复和自用价值证据纳入最小切片完成定义。
