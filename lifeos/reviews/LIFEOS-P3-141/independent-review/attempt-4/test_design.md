# LIFEOS-P3-141 Phase B Attempt 4 — Independent Test Design

## Scope and independence

This is a fresh Phase B, synthetic-only independent review of fixed candidate
commit `d35a72bf6fbcb9d6cdc905eac100679b69c97e61`.  The candidate and all
engineering evidence are read-only.  This design was written before any
candidate-tree metadata, source, manifest, test, build, runtime, process, or
window contact by this attempt.

Only clearly fictional Work and non-medical Health/Fitness fixtures will be
used.  No real text, real state values, credential, real Provider request,
network call, existing Pilot asset, or protected real-root operand is allowed.
The protected Phase-C root and its database are intentionally absent from every
command, probe, inventory, hash, test fixture, trace, and cleanup operation.

## Review-owned assets and execution boundary

- Review root: `lifeos/reviews/LIFEOS-P3-141/independent-review/attempt-4/`.
- Sole disposable runtime root: `/private/tmp/lifeos-p3-141-controlled-pilot-v1`.

  final manifest are authored in this review root.  No engineering runner,

  used as positive evidence.

## Review-owned verification matrix

### A. Topology, Provider, and identity

- Derive the IPC command set from both Rust registration and UI invocation
  sites; require exactly 20 unique commands and no 21st command.
- Exercise the four permitted Provider kinds with synthetic endpoints only.
  Verify explicit save, test, enable, and send separation; first synthetic
  send creates a persisted lock; changing to any other permitted kind,
  Custom, fallback, background probe, parallel dispatch, and retry are denied.
- Use dispatch counters and a loopback-free synthetic adapter.  Any network
  attempt is a P0 and immediately terminates the run.
- Require every Phase-B source/artifact/request/receipt/UI label and key to be
  P3-141.  Scan review-owned output and the candidate copy for P3-133/P3-131
  runtime identity residues; classify any real-flow residue as P0.

### B. Synthetic Work limits and restart behavior

- Use 14 distinct fictional day tokens generated by the harness, one Work
  record per day.  Confirm 14 accepted writes, never more than one daily,
  never more than 14 total, and stable non-content counts after restart.
- For a duplicate day and a fifteenth total attempt, record state and audit
  counts before the call, require the specified reject code before any write,
  and assert all counts, request IDs, dispatch counters, sentinel files, and
  database snapshot are unchanged.
- Restart from the same disposable database and repeat the two rejected cases;
  no duplicate Work write, request, send, or audit success may appear.

### C. Structured non-medical Health Current State

- Enumerate every allowed sleep-duration band, energy values 1 through 5,
  each soreness/pain boolean, low/medium/high training-load value, and every
  allowed available-time band.  Fixture values remain fictitious and are never
  rendered into review evidence.
- For every accepted input, inspect only schema/enum/non-content object counts
  across UI receipt, SQLite, Today computation, and feedback linkage.
- For each missing required field, out-of-range energy, unknown enum,
  malformed object, and extra `free_text` field, require a pre-write rejection
  and unchanged database/audit/sentinel snapshot.
- Confirm the structured high-risk path produces a conservative stop message
  without diagnosis, treatment, or training-load prescription.

### D. Durable Memory, Context, feedback, and atomicity

- Create three user-confirmed, fictional Durable Memory entries and verify a
  fourth is rejected before persistence.  Restart and prove identity/count
  stability without automatic AI Understanding promotion.
- Test Context Resolver exact, under-budget, and over-budget cases; test
  request-local Health removal, Today recomputation, feedback correction/stale
  behavior, and budget rejection.  Before/after non-content database and
  sentinel snapshots must remain unchanged for every reject.
- Ensure no whole database or unrelated Domain is available to the adapter;
  only request-scoped non-content reference/count receipts are observable.

### E. Receipt/root ownership boundary

- Run an unreceipted real-flow attempt under a path-denying trace wrapper.
  It must reject before root parsing, root ownership check, root creation, or
  database probe.  The wrapper sees no operation outside the disposable root.
- With a correct synthetic Phase-B receipt, exercise a fresh missing synthetic
  root success and reject existing empty directory, regular file, symlink,
  ancestor symlink, unowned database, unknown target, sidecar, noncanonical
  input, and all ownership/identity mismatches.
- Reopen only an owned synthetic database and prove no duplicate write or send.
  All cases use generated paths inside the disposable root; no real root is
  named or resolved.

### F. Independent semantic mutations

Create disposable copies of the candidate copy and alter one semantic control
at a time: receipt gate, root-ownership check, Provider first-send lock, Work
limit, Health validation, Durable Memory limit, feedback stale/budget guard.
The corresponding review-owned assertion must fail for each mutation.  A
mutation that passes is a P0; mutations never touch the fixed candidate.

### G. actual-Tauri dynamic evidence

- Build only from the hash-bound disposable copy and use offline/loopback-free
  configuration.  Each viewport is a new direct app launch returning that
  launch's PID; no process or window enumeration is allowed.
- For 1280x1024, 700x760, and 560x640, bind that PID to the exact P3-141
  title, one AXWindow, and one AXWebView/AXWebArea.  Capture direct AX facts
  and fixed synthetic, content-redacted screenshots; verify actual inner and
  outer geometry separately.
- Exercise provider-lock display, structured Health acceptance/rejection,
  feedback/Today response, and failure-close UI where visible.  Page fixture
  screenshots, static scans, and inherited screenshots cannot substitute for
  these direct bindings.
