## 评审摘要

1. **[事实]** P1-004 继承了已冻结的 V1 第一场景、价值排序、领域语义和 AI 信任边界，没有扩张成企业后台、全局任务墙、完整日历或全知 Agent。
2. **[判断]** “选择 Project → 恢复上下文 → 证据充分时确认一个候选下一步 → 随时捕获”的骨架能回答“今天从哪里继续”；恢复信息是主角，建议只是承接。
3. **[判断]** “一个主候选下一步”合理，但冻结口径必须是“零或一个”。无可靠建议、证据不足或 Project 边界不明时不得凑数。
4. **[事实｜Stitch 只读观察]** 当前项目仍有多个“今日”版本；可见页面和最新精修说明仍以 IT 运维、Kubernetes 为主角，部分版本还包含广泛导航、任务和自动化状态。当前 Stitch 不是已符合 PRD 的基线。
5. **[判断]** 内容身份和证据规则完整，但全部平铺会造成标签 / 权限过载；四类命令若完整展开也会把首页变成清理控制台。
6. **[建议]** 完成 M-01 至 M-04 的有限补丁后，可进入冻结决策；补丁前不建议无条件冻结，也不建议直接修改 Stitch。

## 已通过内容

### 1. 定义、目标与信息结构

**[判断：通过]** “安静、可核对的个人外脑入口”准确承接产品定位。“当前 Project 与恢复上下文 → 候选下一步 → 快速捕获”的前三层符合“找回 > 下一步 > 今日重点”。恢复面覆盖停点、变化、决定 / 开放事项与证据缺口；“今日安排”只容纳用户确认内容，与 AI 候选分区；近期变化可并入恢复包，最近痕迹后置，AI 提示低打扰，能避免任务墙和焦虑堆叠。

### 2. 一个主候选与无建议

**[判断：通过]** 至多一个主候选是注意力预算，不是 AI 产量目标。PRD 已规定证据不足、来源不可达、授权失效、Project 不明或用户拒绝后无新证据时，降级为提问、缺口或“暂无可靠建议”。默认应为“零或一个”；第 2–3 个候选不是首屏常态。

### 3. 领域与 AI 信任基线

**[事实]** PRD 正确映射 `Project`、`Source`、`Artifact`、`Event`、`Decision`、`Action`、`Assertion`、`Derivation`、`Feedback`、`Authorization`、`AuditEntry`、`Link`，并声明它们不等于 UI 模块或数据库表。来源身份、用户认可、业务、证据和派生状态没有混合；候选 Action 未确认前不是承诺，证据失效也不抹去用户确认历史。

**[判断：通过]** AI 建议包含身份、Project、动作、理由、证据、缺口、时效、确认状态和反馈入口；不以伪精确置信度代替不确定性说明。L0–L2、对象级确认、追加式 Feedback、跨 Project 重判及高风险降级均继承冻结基线。

### 4. 交互状态、响应式与验证合同

**[判断：通过]** 默认、空、加载、错误、离线、权限不足、AI 生成中 / 待确认、确认 / 驳回 / 忽略 / 纠正、来源不可达、证据不足、无可靠建议、证据失效及命令处理状态覆盖完整；降级优先保留原文与用户权威内容。

桌面宽屏、窄桌面、极窄窗口的顺序清楚；移动端仅承诺可阅读降级，不承诺完整功能。验收标准可检查单主角、证据可达、零或一个候选、反馈语义、四命令和耐久保存。真实 / 等价中断 Project 与现有方式对照的验证合同可执行，且未冒充一手验证结果。

## 关键问题

### K-01｜可信信息可能变成首屏负担

**[事实]** 主建议被要求同时展示约十类信息，身份还需至少两层视觉语义。

**[推断]** 若逐项平铺，用户会先读标签、状态和权限，而不是恢复 Project；可信机制会被体验成审计后台。PRD 尚缺“首屏必显—详情可达—异常时显”的分层合同。

### K-02｜四类命令的首页责任偏宽

**[事实]** 第 10.2 节要求上下文菜单提供四类命令入口、影响预览和多阶段状态。

**[推断]** `delete_content`、`revoke_processing` 与断源副本处置常需要范围选择、二次确认和完整状态说明。语义必须在首页可达，但完整执行不应挤占恢复主任务或形成一击式破坏操作。

### K-03｜Stitch“继承”可能继承错误叙事

**[事实｜只读观察]** 当前 Stitch 可见内容包含“领域（IT 运维）”“智能体”“自动化”“IT 运维”“同步中”等导航，以及 Kubernetes 排障、服务器巡检、自动化状态和 AI 洞察；最新精修说明仍要求保留“当前领域为 IT 运维”和 Kubernetes 主内容。

**[判断]** 单一主画布、极简侧轨、低打扰 AI 和快速输入可作为空间原则；现有导航、样例、图片比例、颜色 / 玻璃参数和交互实现不可随之冻结。

### K-04｜当前 Project 的选择来源不够明确

**[事实]** PRD 同时写“默认态一个当前 Project”和“无法可靠选择时由用户主动选择”。

**[推断]** 若不显示选择来源，系统可能把最近访问、模型推测或领域静默当作当前 Project，引发错误恢复和跨 Project 误用。

## 必须整改项

### M-01｜补充渐进披露合同

冻结前明确：恢复主面常显当前 Project、停点 / 关键变化、时效、一个关键证据入口及明确缺口；决定理由、完整证据和来源链按需展开。候选常显 AI / 未确认身份、动作、简短理由、时效或关键缺口及主要反馈入口；输入范围、反证、处理位置与完整来源进入证据详情。正常态不常驻展示底层授权维度、模型版本、审计或清理状态机；P0 异常可提高显著性。

**关闭标准：** 原型任务能直接区分“首屏必显”“详情可达”“仅异常时显”。

### M-02｜收紧四类命令的首页表达

首页只承担语义准确的上下文入口、作用对象、影响摘要和完成后的最小回执；完整范围选择、组合命令、副本保留、二次确认、清理进度与失败处理进入专门流程 / 详情层。`delete_content`、扩大范围的 `revoke_processing`、断源并删除副本不得一击执行；`retract_feedback` 仍以追加历史表达。

**关闭标准：** 四命令不互相冒充，任何破坏性或范围不清操作都有影响预览和明确确认，首页不成为权限 / 清理控制台。

### M-03｜限定 Stitch 继承边界

第 8.1 节应明确只继承空间 / 注意力原则，不继承导航广度、领域替代 Project、IT 运维 / Kubernetes 默认样例、全局任务 / 自动化状态、图片比例、视觉参数、AI 文案和现有交互。后续原型至少以一个非运维 Project 为主画面，并以空态或无可靠建议态作第二组关键画面；运维仅可作为普通 Project 样例。

**关闭标准：** “继承 Stitch”不会保留后台 / 开发者工具叙事，也不会提前冻结视觉实现。

### M-04｜明确 Project 选择来源与未选态

V0.1 当前 Project 只可来自用户本次选择或“最近由用户确认”的延续；系统推测只能作为有依据的候选，不能静默生效。页面需显示当前 Project 并可切换；没有可靠 Project 时仍可捕获和手动选择，但不生成跨 Project 恢复或建议。Project 归属不得扩大授权。

**关闭标准：** 默认、未选、候选切换三态不混淆。

- **Gate 2 数据与来源：Pass with Conditions。** 身份、来源、反馈、失效和四命令语义正确；M-01、M-04 需补展示分层与 Project 选择来源。实现未冻结。
- **Gate 3 AI 权限与信任：Pass with Conditions。** 用户权威、证据、确认、撤回、无可靠建议和高风险边界通过；M-01、M-02 需避免信息过载与首页承担高影响命令。首页 V0.1 不放行 L3。

## 最终建议

**最终结论：Pass with Conditions。**

P1-004 已具备冻结基线的主体质量：它以 Project 恢复为主角，以零或一个可核对候选承接行动，并保留低摩擦捕获；它正确继承 V1 范围、领域模型和 AI 信任模型，也足以指导后续 Stitch 修改而未冻结视觉和技术实现。

当前不建议无条件冻结。应先以有限补丁关闭 M-01 至 M-04，重点是减少首屏表达、限定命令责任、明确 Project 选择来源，并切断对 Stitch 运维样例、导航密度和视觉实现的错误继承。补丁通过后，建议 PM 将 P1-004 与补丁联合冻结为首页 / 今日页 PRD V0.1，再启动仅限首页的原型修改与独立原型评审。该冻结不代表用户验证、技术 Spike、Stitch、完整移动端或 Stage 2 / Stage 3 准入已经通过。
