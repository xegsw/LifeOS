6. **[结论]** Gate 2 条件通过；Gate 3 条件通过；Gate 1 通过；Gate 4 仅在最小实现验证合同层通过、实现未通过；Gate 5 未评估。P0-003 是合格的冻结基础，不是可直接无条件冻结的最终文本。

## 已通过内容

以下内容可直接进入冻结候选：

1. **对象集合与逻辑分层。** 原始层、语义层、派生/反馈层、控制层职责清楚；对象独立依据是身份、生命周期与追溯需求，不是物理存储映射。
2. **Source / Artifact / version。** Source 表达来源位置、取得方式、访问状态和权限引用；Artifact 表达具体内容身份与稳定版本。用户原文、用户编辑版本、外部原文、引用摘录和派生内容可持续区分。
3. **Obsidian 只读语义。** Vault 是 Source 容器，Markdown 文件是 external Artifact，路径/块是来源定位而非唯一永久身份；移动不确定时保留候选，不强行合并；AI 派生不写回 Vault。
4. **业务对象边界。** Assertion 表达可判真伪的关键陈述；Decision 保存用户选择及理由；Action 保存可执行与承诺语义；Event 保存现实/项目变化；AuditEntry 不进入用户事件时间线。该划界服务“5 分钟项目恢复与下一步确认”。
5. **用户权威与 AI 来源。** AI inference / proposed Action / candidate Link 可成为业务对象，但必须反向连接 Derivation；用户 Feedback 可改变当前状态，但不能抹去 AI 来源或历史响应。
6. **重要 Link 分层。** 重要关系具有建立者/来源、证据、确认状态和有效期；普通展示关系可轻量化。该规则足以避免全部关系重型化，也不要求图数据库。
7. **Project 恢复包。** “近期 Event—已确认 Decision—开放 Action—关键 Assertion—原始证据—候选下一步—Feedback”的恢复链与 V1 价值排序一致；Project 是上下文边界，不是企业容器或权限根。
8. **Spike / PRD 边界。** P0-003 已明确不冻结 Schema、API、图数据库、事件溯源、搜索或 UI；P0-005 的 SP-02、03、05、06、07、08 为相关语义提供了最小实现验证路径，但尚未提供实测证据。

## 关键问题

### K-01｜P0-003 尚未吸收四类命令的差异化后果

- **[事实]** P0-003 分别提及授权撤回、Source 断开、内容删除和 Feedback 撤回，但没有统一效果矩阵。
- **[判断]** 现有对象足以表达四类命令；缺口是跨对象生命周期合同，而非缺少实体。
- **[风险]** 后续实现可能把“停止处理”误报为“已删除”，把“断开来源”误作删除全部导入资产，或在撤回 Feedback 时篡改历史。

### K-02｜Derivation 最低包络低于已冻结 AI 信任基线

- **[事实]** P0-003 已要求输入版本、目的、位置、Authorization、模型/工作流版本、状态与失效原因。
- **[缺口]** 未把敏感级别、实际处理者及政策版本、接收方类别、保留/删除条件、训练/评估禁用、来源许可、允许 Project/目的/位置等输出约束列为强制可判定包络，也未明确多输入取最严格交集。
- **[风险]** 摘要、候选 Link、排序信号或恢复包可能在保持来源链的同时跨 Project / 目的越权传播。

### K-03｜“来源/证据失效”与“用户确认历史”缺少独立状态维度

- **[事实]** P0-003 要求保留用户确认历史，且来源变化会使派生物 stale / invalid。
- **[判断]** 当前文本容易把对象的认识来源、用户认可、业务状态、证据可用性和派生有效性压进一个 `confirmed/stale/invalid` 状态轴。
- **[风险]** 唯一证据删除后，用户确认对象可能被静默删除，或仍被自动排序/提醒当作证据充分。

### K-04｜删除、恢复、导出和重导入的优先级不完整

- **[事实]** P0-003 已要求删除传播、可迁移导出、备份恢复后不绕过删除的方向。
- **[缺口]** 未明确不可还原墓碑、撤回记录和用户权威状态在恢复/重导入时优先于旧包，亦未明确导出前重新执行来源许可、删除墓碑与 Derivation 输出约束。
- **[风险]** 已删除/撤回内容可能由历史 Derivation、manifest、缓存或旧导出包复活。

### K-05｜AuditEntry 最低字段仍可能反向识别

- **[事实]** P0-003 已禁止审计保存被删除原文，并反对重型企业审计。
- **[缺口]** 其“对象/版本、精确时间、客户端/位置、错误”等字段组合仍可能泄露路径、敏感 Project 或活动存在性。
- **[风险]** 审计和日志成为独立隐私数据库，绕过删除、撤回与最小权限。

## 必须整改项

以下整改应以有限勘误/语义补丁完成，不要求重写 P0-003，也不新增核心对象：

### M-01｜加入四类命令的最低领域效果矩阵

明确 `revoke_processing`、`disconnect_source`、`delete_content`、`retract_feedback` 对 Source、Artifact/版本、Derivation、Link/候选、用户确认 Assertion/Decision/Action、索引/缓存、AuditEntry、备份/离线副本、导出和第三方副本的不同后果；处理许可与保留许可必须分离；组合意图必须组合显式命令。

### M-02｜补齐 Derivation 约束继承合同

在现有最低包络上强制加入 P0-007 第 9 节的输出约束：允许范围/Project、目的、位置/接收方、敏感级别、保留/删除、训练/评估、来源许可、Authorization/政策版本与当前有效状态。多输入取交集和最严格值；跨 Project 展示、保存、再派生必须重判，合法子集变化时产生新 Derivation。

### M-03｜分离来源身份、用户认可、业务状态、证据状态与派生状态

不要求设计数据库字段，但语义补丁必须明确：AI 来源身份不可变；Feedback 追加式计算用户认可；Action/Decision 各自保留业务生命周期；证据可独立标记 `evidence_unavailable/review_required`；Derivation 可 stale/invalid。证据失效不删除用户确认历史，但对象退出自动排序、提醒、建议和“证据充分”表达。

### M-04｜加入墓碑优先与导出不复活不变量

明确 `delete_content` 的不可还原墓碑/最小删除说明、备份恢复与离线重连先重放墓碑和撤回、旧导出包不得覆盖当前删除或用户权威状态；导出前重判许可、墓碑和输出约束。可重建基础设施派生可不导出，但不得借历史包复活。

### M-05｜收紧 AuditEntry 语义

将审计最低原则扩展为：内容不可还原、标识不可枚举且作用域化、时间粒度最小、路径/名称/URL/自由错误上下文禁入、日志/遥测用途分离、访问与保留最小化、删除后解除映射，并继承 P0-007 的关联/重识别测试要求。

## 关卡检查

- **Gate 1 产品一致性评审：Pass。** 模型直接服务技术型独立产品构建者的项目恢复与下一步确认，维持“找回上下文 > 下一步/减少遗漏 > 今日重点”；Project 不是企业容器，代码/Issue/Obsidian 仍是来源类型，没有把长期知识图谱或 Agent 愿景前置进 V1。
- **Gate 2 数据与来源评审：Pass with Conditions。** 原文、外部来源、AI 派生/推断/建议和用户确认事实可区分；Source/Artifact/version、Decision/Action/Feedback、Obsidian 只读、失效与导出方向成立。M-01 至 M-05 未补齐前，不建议无条件冻结生命周期合同。
- **Gate 3 AI 权限与信任评审：Pass with Conditions。** 对象集合能够承接已冻结 P0-004 + P0-007，无需新增对象；但必须通过 M-01 至 M-05 继承四命令、强制政策包络、L3 默认 L1、约束传播、第三方资格、审计最小化和导出不复活。高风险与 L4-L5 边界沿用已冻结基线，不由本模型重新定义。
- **Gate 4 技术可行性评审：验证合同层 Pass；实现层 Not Yet Passed。** SP-02/03/05/06/07/08 已覆盖身份、证据链、清理、同步、恢复包与导出，且允许聚合存储、显式依赖边和 FTS-first；尚无实测，不能冻结 Schema、图数据库、同步、删除 SLA、搜索或技术架构。
- **Gate 5 用户价值验证评审：Not Assessed。** Assertion 独立展示价值、结构化确认成本、四命令理解、L1/L3 区分和审计说明仍需 Stage 1 原型/用户验证。本项不阻止语义基线条件冻结，但阻止 UI 和 V1 物化范围冻结。

## 最终建议

**最终结论：Pass with Conditions。**

P0-003 对核心对象、Source / Artifact 分离、版本、业务语义、Derivation / Feedback、重要 Link、Obsidian 只读和 Project 恢复链的判断可靠，不需要推倒重来。11 个对象 + `Link` 足以表达 LifeOS V0.1；继续增删对象会制造不必要的语义漂移。

但 P0-003 当前文本不能单独无条件冻结，因为已冻结的 P0-007 对命令、权限、派生约束、证据失效、审计和导出提出了更严格且必须继承的语义。建议先完成 M-01 至 M-05 的有限补丁，经 PM 验收和用户确认后，将 **P0-003 + 补丁** 共同冻结为“核心领域模型 V0.1 语义基线”。冻结只约束后续定义线和验证线必须继承这些语义；SP-02/03/05/06/07/08、Stage 1 PRD/原型、任何具体实现和进入 Stage 3 仍需分别通过对应门槛。
