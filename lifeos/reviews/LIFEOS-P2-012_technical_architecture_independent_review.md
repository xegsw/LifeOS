## 1. 评审摘要

1. **[已验证事实]** P2-010 已把 SP-01 至 SP-09 收敛为本地优先、权威原文耐久保存、可重建派生、SQLite + FTS-first、向量后置的候选方向；P2-011 已把五个 P0 主题转成可检查的责任、禁止项、失败语义与降级合同。两份材料足以进入技术架构冻结前最终补丁，不需要返工成新一轮架构方案。
2. **[独立判断]** 当前不存在阻止编写最终补丁的 P0“定义空洞”，但仍有两个阻止技术架构实际冻结的 P0“证据空洞”：FTS 维护隔离尚未证明能修复 SP-09 已出现的约 4 秒捕获阻塞；Tauri / IPC 最小安全边界尚未用可执行证据证明。
3. **[结论]** FTS 与 IPC 窄测均为**技术架构冻结前必做**，不是可以延至正式开发中的普通验证。可先编写最终补丁固化测试合同与冻结范围，但 PM 不得在两项窄测通过、结果被补丁引用前把架构标记为 `Frozen`。
4. **[已验证事实]** D-0114 已确认“V1 默认单设备本地优先、同步 / 服务端具体栈后置”以及“Obsidian 只冻结条件适配器与降级合同”。P2-010/P2-011 对这两条边界继承正确，没有偷渡服务端栈、Vault 写回、插件或双向同步。
5. **[独立判断]** Gate 2、Gate 3 可在合同层通过；Gate 4 为 `Pass with Conditions`。合同层通过不等于 Schema、API、Tauri capability、FTS SLA 或真实处理者已经实现。
6. **[结论]** 正式 MVP 开发继续 `Blocked / Not Allowed`。本评审只允许下一步进行最终补丁、两项窄测及其验收；不构成技术架构冻结，也不替代 Stage 2→3 准入与 Gate 5。

## 2. 评审依据与范围

本评审依据当前状态索引、项目运行规则、角色矩阵、阶段关卡、冻结看板、P2-010/P2-011 任务卡、主交付物与 PM Review、P2-003/P2-006/P2-009 PM Review，以及 D-0109 至 D-0114。按任务卡读取规则，未重跑 Spike、未读取完整 evidence 日志，也未重新比较桌面框架、数据库、向量库或云平台。

评审范围仅判断候选架构与条件整改是否可信、关卡能否在合同层通过、哪些补证阻断冻结以及是否允许进入最终补丁。未评审生产实现质量，未冻结 Schema/API/技术栈/SLA，未处理真实 Vault、云服务或敏感数据。

## 3. 总体结论

**结论：Pass with Conditions。**

P2-010 与 P2-011 已形成一致且范围受控的冻结候选：前者说明“为什么选择这组方向”，后者说明“每条方向必须守住什么边界”。其主要强项不是框架名称，而是把用户原文、控制账本、派生、任务队列、来源、授权、删除与导出恢复的责任分开；即使将来替换桌面壳、模型供应商或增加同步，这些不变量仍可继承。

条件通过的限制是：设计合同只能证明方案没有明显逻辑自相矛盾，不能反证实现边界失效。FTS 已有反例，Tauri/IPC 则完全缺少本项目级可执行证据。两者分别直接影响“记录不被后台维护拖垮”和“Renderer 不能绕过数据主权与授权门”，均属于 V1 地基，不宜在冻结后再赌实现。

## 4. Gate 2 数据与来源评审

**结论：Pass（合同层）。**

- **[已验证事实]** P2-011 明确区分权威事实 / 控制账本、可重建派生、outbox/job；用户原文和不可变版本、Source/Artifact 身份、用户确认与纠正、Authorization、tombstone/restriction、generation、Feedback 与最小审计均有明确归属。
- **[已验证事实]** 派生绑定精确输入版本、Derivation、内容身份、授权 / 政策版本和 generation，可进入 stale/invalid/quarantined/delete/rebuild；恢复与重导入先应用更高 generation 的控制状态，符合“不复活”要求。
- **[独立判断]** “outbox 与权威变更同事务登记、队列非权威、发布前统一重检”的合同足以支持可信搜索、撤回 / 删除、导出 / 恢复和未来离线处理；当前无需冻结表结构或将领域对象一一等同数据库表。
- **保留条件：** 最终补丁须把所有消费入口统一列入重检范围，至少包含展示、索引、再派生、外发、导出与恢复重建；IPC 返回也必须携带来源和内容身份。任何新增旁路若绕过这些入口，Gate 2 结论失效。

## 5. Gate 3 AI 权限与信任评审

**结论：Pass（合同层，真实处理者保持关闭）。**

- **[已验证事实]** P2-010/P2-011 继承六维授权、目的 / 位置 / 处理者边界、最小外发、发布前重检、撤回优先和重大动作明确确认；AI 生成、推断、建议、候选行动与用户确认事实不混淆。
- **[已验证事实]** Project、文件夹、标签、双链或相似性不扩权；连接 Vault 也不自动授予 AI、云端、第三方、全文导出或长期缓存权限。
- **[独立判断]** 对本地 V1 合同而言，授权撤回后的活跃阻断、派生失效和异步物理清理边界已足够清楚。真实云 / 第三方模型默认关闭、供应商可替换，因此未验证真实处理者不构成本次本地架构冻结候选的 P0 空洞。
- **保留条件：** 审计不得保存可还原正文、真实路径、prompt/output、凭据或向量；任何真实外发能力未来启用时必须另做处理者级验证，不能引用本次合同层 Pass 作为上线许可。

## 6. Gate 4 技术可行性评审

**结论：Pass with Conditions。**

- **[已验证事实]** 现有 Spike 支持本地耐久捕获、版本 / 来源链、授权与失效、FTS-first 搜索、导出恢复等候选机制；未发现必须引入微服务、Kafka、Kubernetes、图数据库或专用向量库的证据。
- **[独立判断]** 单设备、本地优先使同步生产化、服务端事务、分布式租约和冲突 UI 不再是本轮冻结阻断项；向量后置也避免将未证明净增益的能力变成硬依赖。
- **[P0 条件]** FTS 维护竞争窄测必须证明权威提交不等待长索引事务、等待门槛满足合同、零误报保存、零权限 / tombstone / generation 泄漏、影子切换可校验和回退。
- **[P0 条件]** Tauri / IPC 窄测必须证明 Renderer 无任意文件 API，路径规范化与 symlink 越界 fail closed，Vault 不存在写 / 删 / 改名命令，导出仅落入授权目标，IPC 响应保留内容身份。
- **保留条件：** 备份、恢复、磁盘峰值、跨平台与生产 SLA 可在实现期继续验证，但最终补丁必须明确最低失败语义和触发后续验证的条件，不能写成已实测承诺。

## 7. 五个重点条件逐项评审

| 条件 | 独立结论 | 冻结前处置 | 失效条件 |
|---|---|---|---|
| FTS 维护隔离 | 合同合理，证据未关闭；现有约 4 秒阻塞是已知反例 | **必须先完成窄测**；最终补丁引用通过结果与回退语义 | 捕获等待超门槛、误报保存、控制状态泄漏或切换不可回退 |
| 权威 / 派生 / outbox | 责任和失败语义清楚，可接受 | 最终补丁固化不变量与所有发布 / 消费入口；实现期复验原子性、幂等与租约 | 队列成为权威、派生覆盖原文、死信解除阻断、入口绕过重检 |
| Tauri 文件 / IPC | 默认拒绝方向正确，但只有文本合同 | **必须先完成最小可执行窄测**；失败则 Tauri 保持未冻结且 Obsidian 不启用 | Renderer 获任意文件权、路径越界、Vault 写能力、身份丢失 |
| Obsidian | 条件适配器 / 降级合同合理，且继承 D-0114 | 冻结默认关闭、只读、来源身份、断源不复活与降级；不冻结正式启用 | 被写成 Must、默认启用、写回 / 插件 / 双向同步或真实 Vault 许可 |
| 同步 / 云端 | 单设备本地优先合理，不损害 Must 闭环 | 排除服务端具体栈、多设备同步和云端权威；保留可迁移合同 | 未经 PM 新决策将 Fastify/PostgreSQL、设备数或同步 SLA写入冻结范围 |

## 8. 对 P2-010 / P2-011 的可接受内容

- 本地权威原文与控制账本优先，派生、索引和任务失败不影响权威保存。
- SQLite + FTS-first 可作为 V1 本地主路径候选；向量仅在真实授权标注集证明稳定净增益后触发。
- 删除 / 撤回先事务内活跃阻断，再异步物理清理；旧索引、旧队列、备份、重导入与重连不得复活。
- outbox/job 仅承载意图和执行状态，不成为事实来源；展示、外发和再派生前必须重检。
- 桌面文件能力经后端白名单与 scope 暴露，Renderer 默认无任意文件、shell、进程或网络能力。
- Obsidian 默认关闭、只读、可降级；同步 / 云端 / 服务端具体栈后置；模型与供应商保持可替换。
- 技术状态必须转译为真实用户状态：“已保存”只代表权威耐久提交，“索引中 / 清理中”不得冒充完成。

## 9. 必须修正、补证或 PM 决策的问题

1. **[必须补证｜P0]** FTS 窄测：覆盖增量消费、全量影子或分段重建、切换失败、空间不足、重建并发捕获，以及查询回连当前权威状态。验收至少报告 p95/p99、最大等待、误报保存数、权限 / 墓碑 / generation 泄漏数和回退结果。
2. **[必须补证｜P0]** Tauri / IPC 窄测：使用最小集成或等价可执行证据覆盖 capability scope、路径规范化、symlink、隐藏 / 排除项、Vault 零写命令、导出目录和 IPC 内容身份；纯配置截图或设计说明不足以关闭条件。
3. **[必须修正｜最终补丁]** 明确区分“冻结的责任与不变量”及“不冻结的实现细节”。不得把 SQLite Schema、FTS 表 / PRAGMA、Tauri capability 名称、IPC 签名、SLA、服务端栈或 Obsidian 正式启用写入冻结范围。
4. **[需 PM 确认]** PM 主会话确认本评审的 `Pass with Conditions`、两项窄测均为架构冻结前硬条件，以及下一任务的顺序和验收入口。
5. **[需 PM 确认]** 最终补丁与两项窄测完成后，仍须由 PM / 用户单独作技术架构冻结决定；不得由任务 Accepted 自动推导为 Frozen。

## 10. 是否允许进入技术架构冻结前最终补丁

**允许，Conditional。** P2-010/P2-011 足以作为最终补丁输入，建议下一步创建范围受限的冻结条件补丁，负责合并冻结范围、非冻结范围、两项窄测验收合同、失败降级和证据引用。为避免文字补丁替代实证，流程应为：最终补丁建立基线 → 执行 FTS / IPC 两项窄测 → 将结果及剩余例外并入补丁或其验收附件 → PM / 用户再决定是否冻结。

若项目流程要求“最终补丁一经完成即进入冻结决策”，则应先完成两项窄测再定稿；无论采用哪种文档顺序，**冻结不得先于两项窄测通过**。

## 11. 是否允许进入正式 MVP 开发

**不允许，维持 `Blocked / Not Allowed`。** 技术架构尚未冻结，FTS 与 IPC 证据条件未关闭；本次独立评审也不替代 Stage 2→3 的独立准入、关键动态体验验证或 Gate 5 用户价值判断。当前只允许文档补丁、合成窄测、评审、PM 决策与项目账本维护。
