## 4. 一条统一流程

`已提交变化 → 去重/免打扰/权限预检 → 有界相关上下文 → 模型候选 → 宿主校验 → silence / question / suggestion → 用户自然回应 → 反馈/状态或已有行动事务 → 重新判断`。

四种触发都进入同一个队列、调度器、上下文选择器、候选校验与投影：

1. 打开 App 或重新进入前台；渲染、轮询、每次读取 Today 不算新变化。
2. 用户确认了安排、当前状态或纠正；必须来自成功提交的领域事件，不以按钮点击代表成功。
3. 已授权资料更新完整提交成功；按来源 generation/version 合并事件，不重新爬取原目录。
4. 用户明确推迟的时间到达；运行中的本地调度器触发重新判断。App 关闭期间无工作，重开时最多合并一次到期检查。

事件带 `eventId/type/subjectRefs/sourceVersions/occurredAt`，Host 从权威记录生成；前端不能伪造 source update 或 user confirmed 权限。事件及待处理标记与相关事务一起持久化；外部资料更新已有提交标记时用持久游标补接，崩溃后不能丢事件或重复调用。

相同事件身份只消费一次；同一主体、版本、策略版本与有效上下文组成持久 evaluation key，跨刷新/重启不重复分析。五秒内相关变化合并；模型调用并发最多 1，忙时只保留相关主体最新变化。用户回应处理优先，不能被主动计算锁住 UI。

程序只判断确定性准入条件，不以关键词打分或固定场景规则决定“你今天应该做什么”。模型比较已获准的有限候选背景，决定是否有介入价值及当前最值得关注的一项。

## 5. 上下文和主动输出

本地先按变化实体、既有链接、当前确认重点、相关未完成安排及反馈获取小集合。每次最多考察 32 个相关身份/版本元数据；完整正文最多 8 个片段；内容不足返回 context insufficient，目标太多返回必要澄清，不能静默截掉其它可能目标来制造唯一性。使用现有检索/Repository 能力，不在每次触发全表读取正文，不做全人生扫描/摘要。

必须优先考虑：当前明确重点、最新变化、已确认安排、用户反馈/限制、有效依据和是否值得此刻打扰。推断始终标为推断；“缺少进展记录”只能说明系统不知道，不得写成“你没有做”。已有合理安排时可保持安静，不能为了占满页面造问题。

输出严格为 `silence | question | suggestion`。question/suggestion 都必须有 `whyNow`、`evidenceRefs`、推断标记和有限的目标引用；silence 有本地可审计 reason code，但不在 Today 展示“我决定保持安静”。模型不能返回操作成功宣称、SQL、文件路径、工具执行命令或权限声明。

Today 的“LifeOS noticed”最多显示一个焦点对象；与既有 Focus 按同一注意力顺序协作，不把今日重点复制成第二张抢占卡。旧未回应内容可保留为静态一条，不重新弹出/抢焦点/通知/催问；若无价值、依据失效或已推迟则不显示。

后台判断仅限 App 进程运行且前台可见、用户已启用该用途。App 隐藏/系统锁定时保留事件，不发新请求；返回前台后按节流合并。运行中的本地计时器只处理到期和事件，不做系统服务、launch agent、App 关闭后执行或系统通知。

## 6. 自然回应、提醒与行动分离

关联依据为当前会话、主动对象稳定 ID/版本、当前话题、用户原文引用及最近有效轮次。单一页面上有一张卡不等于任何新消息都针对它。多个可能目标、明显话题切换或用户引用别人说的话时，不能误写；只有确有歧义才问一个必要问题。

| 用户意图 | 持久结果 | 明确禁止 |
|---|---|---|
| 当前限制，例如“今天只有二十分钟”及其它表达 | 原文入原记录链；模型提出有来源跨度的当前限制，Host 写现有 states；今天的限制默认到本地当日结束，重新生成相关建议 | 改原安排日期、完成状态或生成永久人格记忆 |
| 稍后看、周末再看 | 建议置 snoozed，记录自然时间原文、解析区间、时区与恢复时刻 | 修改 Action due date、提前重现或到时机械重复旧句 |
| 这件事以后别提 | 按主体身份持久 suppressed，挡住同主体的重措辞候选 | 取消安排、仅按文本 hash 去重后换话术重发 |
| 你理解错了 | 记 dispute/correction 反馈，撤下依赖该认识的主动内容；有明确替代事实才保存更正，否则问一次必要澄清 | 静默修改用户原文、编造替代事实、将所有记忆置无效 |
| 没有回应 | 仅保持 shown/awaiting response，不推断其它状态 | 视为同意、拒绝、完成或短时间连续催问 |
| 明确创建/调整/完成/取消 | 经现有行动链的意图、目标、权限、版本与事务校验后执行；反馈关联同一操作回执 | 主动引擎直接写 Action，模型说成功就展示成功 |

自然时间由模型给出时间意图候选，Host 用已提供的本地日期/时区校验和归一化。本合同默认 Asia/Shanghai、周末为周六 09:00 起；若已在该周末，按当前语境的未来合理时间处理，有实际歧义才问；用户明确时间覆盖默认。只有时间到达且权限、依据、事项仍有效才重新判断，已完成/取消则撤下。时区来自现有设置或 OS；不得更改系统时间。跨时区/时钟回拨不能提前解除 snooze 或复用当日预算。

“不再提”采用稳定 `subjectRef`/已知实体集合的控制状态，不依赖建议措辞。主题相同但身份不明时不能绕过 suppression；必要时保守安静。用户主动谈起该事项仍可正常回答，不自动解除拒绝；只有明确“可以再提醒”才恢复。

接受一条问询或讨论建议不等于授权执行。用户当前明确表达动作且与目标无歧义时，不再添加重复同义确认；动作所需的既有真实模型发送许可及本地写入校验仍保留，自动主动许可不替代动作许可。每轮最多一次本地业务事务；混合“推迟提醒并调整任务”必须分别校验两种意图，原子提交关联结果，任何失败不能半成功。

## 7. 模型/Host 协议与存储兼容

复用当前 ModelPort、Provider Adapter、Host Dispatcher 和 Repository。保留现有 14 个 Tauri command；在对应 command 下增加版本化的 `proactive-v1` operation，现有 v5/v7/v8 DTO 不改义。Host 生成请求和解析严格联合类型，拒绝未知字段、重复 JSON key、非法 null、超限、伪造引用、错误版本与跨主体目标。

新增逻辑协议是本合同明确提出的一次性增量，批准即授权实现；不声称旧 v8 已包含这些语义。

- `EvaluationInput`：evaluationId、triggerRefs、now/timezone、contextRefs及最少摘录、候选主体集合、必要反馈、policyVersion、grantVersion、输入版本快照。私有 ID 转请求内 opaque ref，不发送真实磁盘路径。
- `EvaluationCandidate`：tagged union `silence{reasonCode}` / `question{subjectRefs,question,whyNow,evidenceRefs}` / `suggestion{subjectRefs,proposal,whyNow,evidenceRefs,inferenceFlags}`。不含 Action 命令；最多一个候选。正文 proposal/question 最多 1600 字，whyNow 最多 600 字，依据最多 8 项；不以全段截断补成合法候选。
- `ResponseInput`：currentUser 原文、会话/话题引用、当前建议 ID/版本、允许主体集合、相关依据和当前控制状态。
- `ResponseCandidate`：`context_update | snooze | suppress | correct | clarify | discuss | action_intent`；各项有明确 userEvidenceSpans 和目标引用。必要时一个候选可包含与同一主体相关的最多 2 项兼容反馈；含 action_intent 时交原行动链，不由主动 Host 执行。禁止模型任意生成长期记忆或复活已禁用对象。
- `ProactiveReceipt`：operationId、suggestionId/revision、feedbackRefs、status、shownAt/deferredUntil（按分支）、businessChanged、可选 existingActionReceiptRef、errorCode。UI 的“已推迟/不再提醒/已纠正/已完成”分别以真实持久事务结果为准。

模型返回不得直接供 UI 渲染可执行 HTML/Markdown 链接，所有文本按现有转义规则显示。结构化 `userEvidenceSpans` 只能绑定当前用户实际原文；它能证明引用来自用户，不能单独证明语义正确，语义误判须由 B/C 正反样本检出，不能把“有 span”当成用户执行授权。

建议生命周期固定为 `eligible → surfaced → snoozed / suppressed / disputed / resolved / invalidated / superseded`，silent 记录为 evaluation 结果而非可见建议。snoozed 到期进入待重评，不直接回 surfaced；suppressed 仅显式解除后可重评；disputed 待更正或必要澄清；resolved/invalidated 不允许恢复旧版本。shownAt 只在实际投影显示确认后写入，恢复显示只读，不重复增加展示次数。

参数和状态的小范围字段完善可在批准的逻辑语义内写入同任务机器 Schema 并测试；不得藉此增设新的写权限、动作类型或来源范围。若实现发现旧物理 Schema/加密/owner/核心 API 必须改变，先提供精确兼容差异再取得新授权。

operation 映射：`get_today/proactive_view`、`get_context_recovery/proactive_status`、`resolve_request_context/proactive_event|prepare_proactive_response|cancel_proactive_request`、`decide_understanding_feedback/proactive_response`、`save_ai_provider_settings/proactive_policy`。模型发送由 Host 内部经过统一网关及用途校验；前端传入的 `authorized=true` 或 evaluation key 永不构成授权。普通 UI snapshot、get_today 等读取不得隐式发送模型。

现有 `records/memories/states/drafts/questions/packets/derivations/feedback/sources` 已是有类型 JSON 行，`requests/audit/meta` 已有幂等及事务能力；不新增数据库、表、DDL、owner marker 或第二套身份。持久字段不足通过命名空间和 `kind/schemaVersion` 增量表达：

| 现有位置 | 新用途与必需字段 |
|---|---|
| derivations | `proactive_suggestion`：id、subjectRefs、revision、kind、内容、whyNow、evidenceRefs+版本+授权generation、inferenceFlags、createdAt、supersedesRef |
| states | `proactive_state`：建议引用、status、shownAt、deferredUntil、timezone、suppressionSubjectRefs、lastOutcome、correctionRefs、revision；普通 user_statement 仍使用原状态结构 |
| feedback | `proactive_feedback`：用户原文引用、语义类型、作用目标/版本、更正关系、事务回执引用 |
| packets / questions | 既有用途下的请求最小披露、候选、必要澄清与版本快照，不另存一份源资料正文 |
| sources 的既有控制元数据命名空间 | `proactive:policy`、`proactive:event:*`、`proactive:budget:*`、处理游标和请求状态；属于引擎控制数据，不作为 Source 正文或记忆提供给模型 |
