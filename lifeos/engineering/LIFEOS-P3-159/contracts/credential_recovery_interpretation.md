# P3-159 凭据恢复入口解释

2026-09-12；PM 对 D-0675 合同第 8.4、9-B 节的同范围实施解释。原合同和失败证据保持只读，不新增真实用途、凭据写权限或语音许可。

## 事实与结论

工程报告三次 B 尝试的生产预留累计 3、实际 POST 0。最新只得到 credential_unavailable，未命中 -25308 分支；不能据此确诊钥匙串锁定、ACL、系统交互要求或宣称用户解锁即可解决。停止循环凭据尝试。快速失败修复不等于稳定自动读取通过，B/C 仍未通过。

第 8.4 节已明确用户在现有设置处理平台凭据交互。因此允许在当前同身份完整 B App 的现有设置状态区，实现用户亲自触发的一次只读凭据检查；不要求用户切去另一真实 App、不开放 B 配置保存或模型测试。允许实现、离线验证及准备入口，不授权 Agent 代替用户点击系统交互或输入密码。

## 入口的精确边界

1. 只由当前完整 App Host，经现有 CredentialPort，读取本合同既有固定选中 provider/profile 对应的单一凭据。服务名及引用由宿主当前配置确定，不接受前端任意引用、路径、账户或 authorized=true。不得枚举钥匙串、读取其他项或复制真实库。
2. 仅用户在现有设置主动发起时可进行一次交互式只读检查；后台、定时器、重启、状态轮询、重试及语音不能触发。检查不得启动模型 POST、消费模型预留、修改 Provider 配置、重置计数或自动解除主动暂停。
3. 使用原有手动读取语义；不能强行改变原先禁止交互的进程策略。与非交互读取互斥，不持 Store/业务锁等待；只有一个在途检查。取消、窗口关闭、超时或 profile/generation 改变后，晚到结果丢弃，不自动重试或发送。
4. OS 提示由用户处理，Agent 不操作密码。不得引导用户选择会改变 ACL/信任的“始终允许”等选项，不新增缓存、导出/重建凭据或把检查取得的 Key 留给后续模型请求。若系统只可通过新增权限解决，应报告精确差异并另取用户许可，而不是绕过。
5. 临时凭据仅在后端检查作用域存在，结束及时释放并尽可能清零；不返回、日志化、hash、落盘或存入 UI/会话缓存。前端仅得到检查状态和固定错误类别。
6. 一次手动读取成功只证明这次读取成功，不证明后续后台读取成功。保留暂停及使用计数，后续按原设置恢复流程进行一次非交互验证；再次失败则暂停并报告，不形成每条消息手动读取流程。
7. 原文字输入和已有设置行为不得退化。优先复用既有状态/恢复区域，不增加一级导航、凭据管理后台或新的 Provider 体系。

## 离线检查与恢复证据

先补足错误发生阶段的固定非内容分类：配置绑定、并发忙、进程策略、默认钥匙串获取、单项读取、已知 OSStatus、超时。仅保留安全的阶段/数字错误码，不输出系统错误详细描述中的潜在账户或路径，也不能为取得错误码自动重复真实读取。

覆盖：默认不能触发；后台/前端伪造拒绝；只读检查零 POST/零配置写；取消/超时/并发/迟到结果；选中 profile 与授权改变；原手动设置与后台非交互互斥；已有禁止交互策略不被强开；临时 Key 不外泄或跨请求缓存；成功不假称后台恢复。更新源码 delta、受影响回归和构建身份。

准备完成后给出用户可操作的精确完整 App 路径、签名/模式及一个明确设置入口。当前三次历史启动/退出记录和累计预留保留；不得再循环尝试、泛称解锁即可或宣称 B Pass。主动引擎其他离线闭环及语音联合接线继续，不暂停/回滚/重开整个任务。
