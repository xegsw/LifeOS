# SP-03 最小映射候选比较

| 候选 | 能否满足本次追溯/失效 | 优点 | 风险 | 本次处理 |
|---|---|---|---|---|
| 单一聚合 JSON 文档 | 部分 | 最小、便于导出 | 精确依赖查询、局部失效和约束校验易退化为全量扫描 | 不单独采用；只作为证据包络 |
| 语义记录 + 显式 Derivation 输入边 | 是 | 一次回查、依赖闭包、合法子集和状态传播均可直接验证 | 需维护边完整性与查询索引；未来规模成本待测 | 本 Spike 候选 |
| 通用图数据库 / 完整知识图谱 | 可以但过重 | 任意遍历灵活 | 提前引入存储、运维和一致性复杂度，超出 V1 | 拒绝作为 SP-03 前提 |
| 全量事件溯源 | 可以但过重 | 历史完整 | 读取模型、隐私、删除与迁移成本高；任务不要求 | 拒绝作为 SP-03 前提 |
| 11 个语义对象各一张固定表 | 未必 | 表面直观 | 把语义模型误冻结为物理 Schema | 明确拒绝 |

本次候选只证明“显式版本引用 + Derivation 输入边 + 授权/状态包络 + 追加 Feedback/控制事件”足够表达 SP-03 语义。它不决定未来采用多少表、何种索引、是否使用 JSON 列、如何迁移或如何跨设备同步。
