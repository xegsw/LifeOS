## 2. 已验证事实、推断与证据边界

### 2.1 已验证项目事实

1. LifeOS 是用户掌控、可追溯、可迁移的个人终身外脑，不是企业权限后台或长期自主 Agent。
2. V1 AI 总能力上限为“可读、可整理、可建议，不可替用户确认”；主体为 L0-L2，L3 仅为小范围、明确授权、可逆内部候选，L4-L5 不自动执行。
3. 用户原文、外部来源、AI 派生、AI 推断/建议和用户确认状态必须持续区分。
4. 撤回/删除采用“活跃使用立即阻断、物理清理状态追踪”的双层门槛。
5. Authorization 已接受主体、范围、动作、目的、位置、时效六维核心；D-0043 要求叠加强制政策包络。
6. D-0044 正式区分四类命令；D-0045 将 L3 限定为候选上限；D-0046 将第三方资格失败定义为硬拒绝；D-0047 接受 M-06；D-0048 限定可冻结范围。
7. SP-04 至 SP-08 目前是已接受的验证计划，不是实测结果。

### 2.2 合理推断

1. 六维 Authorization 表达“用户允许什么”，强制政策包络表达“系统即使获准也不得越过什么”；两者职责不可互相替代。
2. “撤回处理”与“撤销保留”是两个不同效果；若不显式表达保留指令，产品会在撤回假象与误删资产之间摇摆。
3. 非逐字摘要、向量近邻、候选 Link 和恢复包仍可泄露受限信息，不能因为没有复制原句就视为已去敏。
4. 审计记录越稳定、越细粒度、跨域复用越广，越容易把对象存在性、活动节奏或敏感项目反向识别出来。

### 2.3 本任务没有验证的事项

- 任何本地、云端、离线设备、备份或第三方副本的实际清理时限。
- 任何模型或云供应商当前政策、地区、训练/评估、保留和删除能力。
- L3 持久候选的同步与撤回可行性。
- 授权 UI 是否易懂、是否产生同意疲劳。
- 高风险识别、凭据检测、跨项目泄漏防护的误报/漏报。

## 4. 六维 Authorization + 强制政策包络

### 4.1 组合判定合同

**[建议]** 每次读取、排队、索引、派生、云同步、第三方发送、保存输出、跨 Project 展示/再派生及 L3 候选写入，在真正消费数据前都必须执行：

`ALLOW = six_dimensions_match AND policy_envelope_pass AND runtime_state_valid`

任一部分为 `DENY` 或 `INDETERMINATE`，结果均为 `DENY`。不得以降级日志、事后告知、用户宽泛同意或缓存中的旧判定继续处理。

| 判定层 | 必须同时回答 | 允许条件 | 硬拒绝示例 |
|---|---|---|---|
| 六维 Authorization | 主体、范围、动作、目的、位置、时效 | 六维全部命中同一条当前有效授权；多输入取最严格交集 | 无授权、过期/撤回、排除冲突、用途或位置不匹配、范围扩大、主体实质变化 |
| 强制政策包络 | 敏感级别、实际处理者与政策版本、接收方/子处理者类别、地区边界、训练/评估、保留/删除能力、跨 Project/跨目的传播、来源许可/保密限制 | 每一强制属性均已知且符合当前数据、目的和位置的资格规则 | 凭据、政策未知、默认训练不可关闭、删除能力低于要求、接收方/地区不明、来源禁止外发 |
| 运行时状态 | 输入版本、对象状态、授权版本、撤回/删除墓碑、任务租约、输出目的地 | 执行前仍为最新且可用；长任务关键阶段重检 | 旧授权版本、输入已删、tombstone 存在、任务过期、撤回后竞态结果待发布 |

### 4.2 六维核心不可弱化

| 维度 | 最小语义 | 不得被何物替代 |
|---|---|---|
| 主体 | 授予者与实际执行工作流/服务 | “LifeOS AI”笼统名称 |
| 范围 | Project、Source、Artifact/类型、明确排除项 | Project 归属或全库总开关 |
| 动作 | 读、解析、索引、派生、同步、第三方处理、候选写入等 | “使用 AI”总动作 |
| 目的 | 搜索、恢复、摘要、建议等可理解用途 | “改善体验”或未来用途 |
| 位置 | 本地、LifeOS 云、实际第三方处理位置/接收主体 | “云端”或“供应商类别”泛称 |
| 时效 | 单次、会话、期限、持续至撤回及版本 | 历史同意或无期限默认 |

### 4.3 强制政策包络字段与资格规则

| 强制属性 | 最低要求 | 不满足时 |
|---|---|---|
| 数据敏感级别 | 每次处理有可判定级别；未知按更严格级别处理 | 拒绝当前外发或高影响处理 |
| 实际处理者与政策版本 | 记录实际法人/服务、适用政策版本与生效时间；不可只记类别 | 未知或版本不可核验时拒绝 |
| 接收方/子处理者类别 | 明确是否还有子处理者、人工访问或日志平台接收 | 未知、超出授权或不合格时拒绝 |
| 地区/传输边界 | 能判断处理和保留地区是否满足用户/来源限制 | 地区未知或不符合时拒绝 |
| 训练/评估用途 | 默认禁止；只有独立、具体、可撤回的用途授权才可考虑 | 默认开启、无法关闭或用途混用时拒绝 |
| 保留能力 | 保留内容、提示、输出、日志的期限与目的不超过许可 | 未披露或超过允许期限时拒绝 |
| 删除能力 | 能执行所需删除请求，并诚实返回已删/待删/受限状态 | 当前数据等级要求删除而处理者不支持时拒绝 |
| 跨 Project/跨目的传播 | 输出可见范围、保存范围和再派生目的均受限 | 目的地未获准或规则未知时拒绝 |
| 来源许可/保密限制 | 外部内容许可、客户义务、用户排除项允许当前处理 | 禁止外发或许可未知且不能最小化为合规指针时拒绝 |
| 数据最小化/凭据门槛 | 仅发送必要字段；凭据、私钥、恢复码等被硬拦截 | 检出凭据或无法完成必要最小化时拒绝 |

**不变量：**用户确认只能授予六维范围内的许可，不能把不合格处理者变成合格处理者；政策包络是系统安全下限，不是第七个可自由授权维度。

### 4.4 判定时点与结果记录

1. 入队前判定一次，执行前必须按最新授权、政策和对象版本再判定。
2. 长任务在外发、保存输出、索引/发布等关键阶段重检；中途撤回后产生的竞态结果不得发布、索引或进入恢复包。
3. 允许决定只短期缓存；缓存键必须包含授权版本、政策版本、目的、位置、输入约束摘要和时效，不得跨 Project/主体复用。
4. 拒绝结果仅记录允许列表内的原因码，不把路径、正文、提示或敏感错误上下文写入日志。
5. 处理者政策发生实质变化时，旧资格失效；对应任务暂停，直到重新评估并在必要时重新授权。

## 5. 四类命令及效果矩阵

### 5.1 命令语义与保留许可

**[建议]** 处理许可与保留许可分开表达。每个命令请求至少包含目标范围、发起者、命令版本、当前保留指令和生效状态；UI 文案交 Stage 1 PRD。

| 命令 | 用户真实意图 | 处理许可 | 默认保留效果 | 不能暗示的效果 |
|---|---|---|---|---|
| `revoke_processing` | 停止指定主体/范围/动作/目的/位置的未来与活跃处理 | 撤回指定 Authorization 或其子范围 | 权威原文和用户确认对象不因该命令自动删除；无独立保留依据的可识别派生进入清理 | 不能声称 Source 已断开或所有内容已删除 |
| `disconnect_source` | 停止继续访问、监听或同步某 Source | 撤回继续取源所需权限 | Source 指针和用户主动保留内容可保留；可识别快照必须按连接时的保留选择/许可处理 | 不能默认等于删除所有导入资产，也不能默认永久保留快照 |
| `delete_content` | 删除指定内容/对象及其可识别副本 | 对目标内容撤销活跃使用与保留许可 | 目标原文/对象、可识别副本及依赖派生进入删除；仅留不可还原墓碑/最小审计 | 不能只关闭处理而继续保留可识别内容 |
| `retract_feedback` | 撤销某条用户 Feedback 对当前状态的效力 | 不自动改变 Source/Artifact 的处理授权 | 原 Feedback 历史保留并新增撤回记录；重算目标状态与依赖 | 不能声称已删除内容、撤销历史事实或逆转已发生外部效果 |

若用户希望组合效果，系统应组合执行多个显式命令，例如“断开 Source 并删除已保存快照”，而不是用一个含糊的“移除”推断用户意图。

### 5.2 完整效果矩阵

符号：`阻断` = 提交后退出所有活跃使用；`清理` = 异步物理清理并追踪；`保留` = 仅在仍有独立合法/用户许可时保留；`复核` = 保留历史身份但退出自动依据。

| 影响面 | `revoke_processing` | `disconnect_source` | `delete_content` | `retract_feedback` |
|---|---|---|---|---|
| Source | 仅撤回命中处理，不必断开其他获准用途 | 停止读取/监听/同步，状态 `disconnected`；保留最小指针供解释 | 若 Source 是删除目标，则删除连接资料和可识别元数据；保留不可还原墓碑 | 无直接影响 |
| Artifact / 用户原文 | 默认保留权威内容，但被撤回工作流立即不可用 | 外部原件不变；LifeOS 内容按用户先前保留选择处理 | 删除目标正文、版本及可识别副本；若外部原件不受 LifeOS 控制，明确只删除 LifeOS 持有部分 | 无直接影响 |
| 可识别快照/摘录 | 无独立保留依据则阻断并清理；有依据也不能用于被撤回用途 | 仅在用户明确保留且来源许可允许时保留，否则阻断并清理 | 阻断并清理 | 无直接影响 |
| Derivation 输出 | 依赖被撤回授权且无其他独立合法依据者立即 `invalid_due_to_permission`；退出展示/搜索/再派生，按保留规则清理 | 依赖实时取源者 stale/invalid；保留快照生成物按快照许可重判 | 依赖目标内容者 invalid；会泄露/还原内容的正文清理，仅留最小状态 | 直接依赖被撤回 Feedback 的派生 stale/invalid，按当前有效输入重建或退出 |
| Link / 候选对象 | 候选退出确认、排序和建议；不得迁移到别的用途继续使用 | 证据不可达时 stale/invalid；候选 Project 归属不扩大权限 | 依赖对象的候选 invalid；若自身是删除目标则删除 | 由该 Feedback 确认/拒绝/纠正的当前状态重算；AI 候选身份不变 |
| 向量 / FTS / 缓存 / prompt 副本 | 立即从查询/上下文/队列排除；无独立允许用途则清理或按剩余合法输入重建 | 与不再保留内容关联者清理；保留内容也须按剩余授权重建 | 全部对应分块、posting、向量、缓存、prompt 副本阻断并清理 | 只清理/重建由反馈状态派生的索引和缓存，不影响无关原文索引 |
| 用户确认 Action / Decision / Assertion | 不篡改用户曾确认历史；若唯一证据/处理依据失效，标 `evidence_unavailable/review_required`，退出自动排序、提醒和建议依据 | 同左；来源断开不等于删除确认对象 | 删除证据时同左；若用户删除的正是确认对象，则对象按删除语义处理 | 撤回确认类 Feedback 后，目标不再维持由该反馈产生的确认状态；若还有其他有效反馈则按规则重算 |
| AuditEntry | 追加命令、范围、原因码、阻断与清理状态；不留内容副本 | 追加断开和快照处理结果 | 追加删除/墓碑/清理结果；对象标识不可反推内容 | 保留原反馈事件与新撤回事件以解释状态 |
| 备份 | 恢复前重放授权撤回/墓碑；被撤回用途不得复活 | 恢复后 Source 仍断开；不合规快照不得复活 | 恢复前重放删除墓碑，目标不得复活 | 恢复后重放撤回记录并重算状态 |
| 离线设备 | 下发高优先级撤回/墓碑；重连前禁止旧队列执行相关任务 | 重连后不得恢复 Source 监听或上传旧快照 | 旧版本不得复活或重新入模 | 重连后追加撤回并解决显式冲突；旧确认不能静默胜出 |
| 第三方副本 | 停止新发送；若该授权包含的保留许可一并失效或无独立依据，发起删除/退出并追踪 | 停止从 Source 继续发送；既有副本按其原授权和保留指令处理 | 发起删除；显示已删、待删、失败或供应商受限，不虚报完全删除 | 除非第三方输出/状态直接依赖该反馈，否则不自动删除；再处理必须重判 |
| 导出 | 不得导出为当前有效处理结果；失效派生仅按允许的最小说明表达 | 可导出合法保留的用户内容/指针和断开状态 | 不导出已删除正文或可还原派生，只给不可还原说明 | 导出反馈追加历史与重算后的当前状态 |

### 5.3 用户可见状态合同

四类命令均应区分以下状态，具体名称和 UI 未冻结：

1. `accepted`：命令已耐久记录，但不代表清理完成。
2. `active_blocked`：LifeOS 活跃读取、搜索、建议、队列执行和新模型调用已零遗漏阻断。
3. `physical_cleanup_pending`：缓存、设备、备份或第三方清理仍在进行。
4. `physical_cleanup_failed`：清理失败，可重试且不解除活跃阻断。
5. `vendor_limited`：第三方无法满足完整物理删除；显示实际限制，不写“已完全删除”。
6. `physically_cleaned`：LifeOS 可控范围内的验证已完成；不得外推为无法证明的外部副本已清除。
7. `completed_no_physical_cleanup_required`：例如只撤回 Feedback 且没有可识别副本需要清理。

**P0 不变量：**只有 `active_blocked` 达成，命令才可对用户表达“已停止使用”；清理状态不得掩盖任何活跃路径漏阻断。

## 6. L3 候选白名单冻结边界与降级规则

### 6.1 可冻结的仅是候选上限

**[项目事实]** 以下四类是不得扩大的 L3 候选白名单，不代表 V1 必做或默认开启：

1. 将已展示的 AI 下一步物化为 `candidate/pending_confirmation` 内部 Action。
2. 保存候选 Decision、候选 Project 归属或候选 Link，且不改变任何用户权威状态。
3. 在用户明确指定的 Project、Source、目的、期限与数量内生成可撤销的内部分类/草稿预览。
4. 在当前授权内重建索引、退休失效派生物等内部维护动作；不得改变业务权威状态。

未列入的 L3 默认禁止。L4-L5 仍不进入 V1 自动执行。

### 6.2 L3 永久不变量

- AI 不能自动把候选变成 `confirmed`、`user_committed`、Next Step、已确认 Decision/Assertion 或重要 Link。
- AI 不能覆盖、回退或合并用户确认、拒绝、纠正、删除或撤回状态。
- 每次 L3 必须有对象级触发或工作流级明确授权、限定范围/目的/时效、数量与频率、可见 AI 身份、一键撤销和 AuditEntry。
- 撤销必须恢复到可解释状态；失败不得改写原文或丢失用户权威历史。
- 候选不得以待办、承诺、提醒、排序权重或通知形式伪装成用户已采纳状态。
- 高风险内容、凭据、客户秘密、外部动作、不可逆动作和影响他人的动作不得进入 L3。

### 6.3 强制降级为 L1 Derivation 的条件

任一条件成立，对应能力必须只展示为 L1 `Derivation`，不得写入持久业务集合：

1. SP-06 尚未通过，或未覆盖该对象类型的同步/冲突/撤回测试。
2. PRD 未明确对象级触发、可见身份、数量/频率、撤销和失败体验。
3. 授权或政策包络不完整、目的地 Project 未获准、输入约束无法继承。
4. 候选会进入提醒、排序、承诺、确认或外部流程，或用户可能将其误认成权威状态。
5. 离线重连可能复活墓碑，AI 候选可能覆盖用户反馈，或冲突不能解释。
6. 撤销无法完整恢复、审计无法解释、批量范围异常或实现成本显著破坏 V1 闭环。
7. 输入证据冲突、来源失效、高风险识别不确定或处理者资格失败。

### 6.4 任一 L3 进入 V1 的前置条件

**[需 PM 确认]** 单项 L3 只有同时满足以下条件，才可由后续 PM 决定是否进入 V1：

- Stage 1 PRD 明确指定该单项，而非整类放行；
- SP-06 对该对象类型通过幂等、乱序、离线、tombstone、Feedback 撤回和 AI 不覆盖用户权威状态测试；
- SP-04/05 已证明授权运行时强制与撤回/删除活跃阻断；
- 原型/用户验证证明用户能区分候选与已确认对象，并能找到撤销入口；
- 数量、频率、范围和默认状态已被 PRD 限定；
- PM 明确确认进入范围。否则保持 L1。

## 7. 审计、日志与遥测隐私规范

### 7.1 共同原则

1. **事件可解释**：足以回答何类主体基于何版本授权发起何类动作、结果与清理状态。
2. **内容不可还原**：不得通过记录本身、字典枚举或与其他日志关联还原正文、路径、敏感 Project 或对象存在性。
3. **用途分离**：用户审计、运行日志、安全调查和产品遥测不共用一个无限制明细池。
4. **最小访问**：本地用户可查看与自己相关的审计；云端运维/安全访问按最小职责、临时授权和访问再审计控制。不得借此建设企业监控后台。
5. **最短保留**：每类记录必须有用途绑定的保留规则和到期删除；具体期限交 Spike/PRD/合规确认，不在本文件冻结。

### 7.2 允许记录的字段类别

| 类别 | 允许的最小表达 | 限制 |
|---|---|---|
| 事件 | 允许列表内的动作类别、结果状态、原因码 | 不记录用户内容衍生的自由文本描述 |
| 主体 | 作用域化服务/工作流类别或随机主体引用 | 不记录不必要的账号详情、设备名或跨域稳定标识 |
| 对象/范围 | 随机、不可枚举、按用户/Project/目的作用域化的引用；必要时只记录数量级/类别 | 不记录原始文件名、完整路径、Project 名、URL 查询串或可猜测内容哈希 |
| 授权 | 授权版本引用、政策版本引用、处理位置类别 | 引用需防跨域关联，不能包含授权中的敏感排除项原文 |
| 时间 | 满足事故顺序所需的最低粒度或事件序列号 | 面向遥测优先分桶/聚合；精确时间只在短期受控运行审计中保留 |
| 清理 | `active_blocked/pending/failed/vendor_limited/cleaned` 与允许列表错误码 | 不记录第三方返回的原始错误正文、请求/响应体 |
| 量级 | 分桶后的数量、延迟、成功/失败计数 | 小样本敏感事件抑制或聚合，避免唯一性识别 |

### 7.3 一律禁止进入 AuditEntry、日志或遥测的内容

- 用户原文、摘录、文件内容、完整提示、模型输入/输出、生成正文、向量、embedding 或可逆特征；
- 原始/绝对路径、文件名、Project 名、完整 URL、客户名、邮箱、凭据或密钥；
- 可猜测内容哈希、连续数据库主键或可跨 Project/用户长期关联的稳定 ID；
- 可能包含用户数据的堆栈变量、请求/响应体、SQL 参数、队列 payload、截图和第三方原始错误详情；
- 高风险推断标签、健康/心理/法律/财务结论或“对象存在即泄密”的细粒度事件；
- 为调试临时开启但没有自动到期、访问隔离和内容过滤的原始日志。

### 7.4 标识、访问、导出与删除边界

- 标识符应随机、不可枚举、不可由路径/正文哈希推得，并按用户、Project、目的或时间窗口作用域化；不同遥测域不得共享映射密钥。
- 映射表若存在，应与日志分离、访问最小化、短期保存；删除/撤回后按规则删除或使映射不可恢复。
- 云端支持人员默认不能读取用户级明细；安全调查需临时、按事件授权并留下访问审计。
- 用户导出只包含对用户有解释价值的最小审计说明，不导出内部关联密钥、其他接收方信息或可扩大攻击面的运行日志。
- `delete_content` 后可保留不可还原墓碑与命令结果；若标识仍可与外部数据关联到被删对象，必须轮换、解除映射或删除。
- 遥测以聚合指标为默认；小样本、唯一事件或敏感错误类别须抑制、分桶或留在本地。

### 7.5 必测攻击面

SP-05 至少测试：路径/Project 名字典攻击、时间线关联、对象 ID 枚举、跨日志域拼接、错误堆栈/请求体泄漏、小样本唯一性、删除前后标识链接、客服/导出权限越界。通过标准不仅是“不能逐字重建正文”，还包括不能以合理成本推断敏感对象、活动或 Project 的存在性。

## 8. 第三方发送前资格门槛

### 8.1 发送前必须全部满足

1. 六维 Authorization 对实际处理者、当前目的、当前范围、当前地区/位置和当前时效全匹配。
2. 数据已分类；未知分类按更严格等级，不以“未检测到敏感词”证明低敏。
3. 实际处理者、子处理者/人工访问类别、处理地区、政策版本和生效时间可核验。
4. 训练/评估默认关闭且可证明；任何训练/评估用途必须另有独立授权，不得从“提供服务”继承。
5. 输入、输出、日志的保留期限及删除能力符合该数据等级、来源许可和用户保留指令。
6. 发送字段已最小化；路径、无关元数据、排除内容和凭据未进入 payload。
7. Derivation 能记录实际处理者、政策版本、用途、位置、授权版本和发送字段类别。
8. 首次发送前，用户能理解数据类别、目的、接收方类别、位置、保留/删除限制和撤回后真实效果；披露不替代资格。

### 8.2 必须 fail closed 的情形

| 情形 | V0.1 处理 |
|---|---|
| 没有匹配授权，或授权/对象/政策版本过期、撤回、冲突 | 拒绝发送 |
| 实际处理者、子处理者、地区、政策版本或保留用途未知 | 拒绝发送，不用旧资格推定 |
| 政策实质变化尚未重新评估 | 暂停对应处理；必要时请求新授权 |
| 训练/评估默认开启、无法关闭或用途边界不可证明 | 拒绝发送 |
| 删除能力低于当前数据/许可要求，或无法返回真实清理状态 | 拒绝发送；不得用确认豁免 |
| 来源许可、客户义务或用户排除项禁止外发 | 拒绝发送 |
| 检出密码、API Token、私钥、恢复码等凭据 | 无条件拒绝第三方发送；宽泛授权无效 |
| 客户秘密、未发布商业材料或高风险敏感内容 | V0.1 默认拒绝；除非后续 PM 明确批准目的特定通道、处理者满足更严格资格且用户对象级授权。当前文件不建立该上线通道 |
| 内容等级无法判定，且不能可靠最小化为非敏感指针/结构 | 按更严格等级拒绝 |
| 目的地 Project、保存位置或再派生用途不在输出约束内 | 拒绝保存/传播，即使模型调用本身已完成 |

### 8.3 政策变化与第三方清理状态

- 处理者政策版本变化触发资格重新评估；地区、子处理者、训练/评估、保留或删除能力发生实质变化时，暂停新发送。
- 已发送数据不因暂停而消失；撤回/删除后必须按能力发起删除/退出，并显示 `pending/failed/vendor_limited/cleaned` 的真实状态。
- 若供应商仅能到期清除或无法删除，不能把 `active_blocked` 写成“第三方已删除”。
- 处理者能力矩阵是运行时资格输入和 Spike 证据，不是供应商选型冻结。

## 9. Derivation 限制继承与跨 Project 传播

### 9.1 约束包络继承

每个 Derivation 除 P0-004 已定义的来源包络外，还必须携带可机器判定的输出约束：

- 可用范围与允许 Project；
- 允许目的与禁止再用途；
- 允许处理/保存位置与接收方类别；
- 敏感级别与披露限制；
- 保留/删除条件及到期时间；
- 训练/评估禁用状态；
- 来源许可/外发限制；
- 输入 Authorization 与政策版本引用；
- 当前有效、stale、invalid、待复核状态。

多输入 Derivation 取所有输入约束的交集和最严格值。若约束无法合并，输出只能在更窄范围生成或拒绝；不得以摘要、聚合或模型改写自动解除限制。

### 9.2 跨 Project 展示、保存和再派生

1. Project 归属是上下文组织，不是权限授予；候选 Project Link 不能扩大 Source/Artifact 权限。
2. 跨 Project 展示前，重新判断每个输入与 Derivation 是否允许目标 Project、当前目的、位置和接收主体。
3. 跨 Project 保存属于新的传播动作；必须保留原约束和来源链，不能复制成“目标 Project 自有事实”。
4. 再派生必须按原始输入与中间 Derivation 的最严格约束重新判定；中间摘要不是绕开原授权的洁净输入。
5. 不逐字引用仍可能泄露事实、存在性、关系或敏感推断；否定查询、候选 Link、排序信号、向量近邻和恢复包都按披露处理。
6. 若目标 Project 仅允许部分输入，必须重建为只使用合法子集的新 Derivation，明确缺口；不得裁掉引用后继续使用原输出。
7. 授权撤回、输入删除或来源断开后，跨 Project 副本、缓存和恢复包一并失效传播。

### 9.3 导出不复活

- 导出前重新执行当前授权、来源许可、删除墓碑和输出约束判定。
- 已删除/撤回正文、失效证据和不可导出外部内容不得通过 manifest、历史派生、日志、缓存或重导入复活。
- 用户确认对象可以保留历史，但若证据已失效，导出必须标记 `evidence_unavailable/review_required`，不能把确认状态写成证据仍充分。
- 重导入先应用墓碑、撤回与权限说明，再开放搜索/派生；旧包不得覆盖当前删除或用户权威状态。

### 10.3 SP-06｜用户权威状态与 L3 去留

**新增/强化测试**

- 保留 P0-005 的重复、乱序、离线、tombstone、Feedback 撤回、任务执行前授权重检。
- 分别对候选 Action、Decision、Link 测试 L1 展示与 L3 持久写入的复杂度差异。
- 验证 L3 的对象级触发、数量/频率、撤销、审计和 AI 不覆盖确认/拒绝/纠正。
- 旧设备重连、候选重建和并发 Feedback 不得恢复已删对象或改写用户权威状态。

**补充通过标准**

- 每个拟进入 V1 的 L3 对象类型都有独立通过证据；不能用一种对象的结果外推全部 L3。
- AI 候选覆盖用户确认、墓碑复活、撤回失效或冲突不可解释均为零。

**失败分支**：对应 L3 强制降级为 L1 Derivation；这不删除用户确认闭环，也不代表全部 AI 功能失败。

### 10.4 SP-07｜可信恢复与非逐字泄漏

**新增夹具/测试**

- 权限排除集同时测试原文命中、摘要含义、向量近邻、排序信号、否定查询、候选 Link 和存在性泄漏。
- 删除/撤回唯一证据后，恢复包、今日重点与候选下一步立即降级；用户确认对象显示证据不可用/待复核。
- 候选 Project 关系不得被用于放宽 Source 权限或跨项目过滤。
- 目标 Project 只允许输入子集时，必须用合法子集重建并显式显示缺口。

**补充通过标准**

- 逐字与非逐字权限泄漏均为 0；候选关系不扩大权限。
- 证据撤回后，不生成看似完整的恢复叙述，旧派生不进入模型上下文。
- 所有跨 Project 返回均能证明输出约束与当前授权匹配。

**P0 失败分支**：权限或推断泄漏为 P0，缩小搜索/恢复范围或禁用相关向量/跨项目能力；不得以删除引用展示掩盖输出仍含受限信息。

### 10.5 SP-08｜导出、权限与不复活

**新增夹具/测试**

- 分别覆盖用户原文、外部许可内容、仅来源指针、合法快照、失效派生、已撤回/已删除内容、用户确认但证据失效对象、最小审计说明。
- 导出前执行授权、来源许可、输出约束、墓碑和保留许可检查。
- 校验导出不包含内部映射密钥、可关联标识、路径、日志详情或不可导出的外部内容。
- 用删除前生成的旧导出包重导入当前环境，验证墓碑和撤回优先。

**补充通过标准**

- 100% 合法用户资产身份可定位；外部内容只按许可导出，许可未知时仅导出允许的指针/摘录/说明。
- 已删除/撤回内容不能通过派生、审计、manifest 或重导入复活。
- 审计导出保持最小可解释字段且不能反向识别敏感对象。
- 用户确认对象在证据失效时保持历史身份和复核状态，不伪装证据充分。

**P0 失败分支**：若删除/撤回内容复活，或原文身份/数据主权导出不完整，不得宣称可迁移，需整改后重测。

### 10.6 不由上述 Spike 代替的验证

- 高风险能力降级：后续 AI 安全/PRD 验证必须用混合资料、间接表达和误分类夹具，验证不主动诊断/评分、不持久化未请求敏感推断、高风险 L3-L5 排除。
- 同意疲劳与授权理解：Stage 1 PRD/原型测试应验证本地索引、AI 派生、云同步、第三方处理的关键差异理解、错误授权率、撤回可发现性和任务完成率；不得用点击同意率代替理解。
