## 3. 只读不变量验证

### 3.1 方法与结果

每个扫描窗口依次执行：把 Vault 目录和文件权限切为 `0555/0444`；拍摄相对树、类型、symlink target、内容 SHA-256、大小、`mtime_ns`、mode、`(device,inode)` 快照；执行候选扫描；再次拍快照并逐字段比较；退出窗口后才恢复权限并由测试驱动模拟外部变化。

| 断言 | 结果 |
|---|---:|
| 扫描窗口 | 10 |
| 前后快照完全一致 | 10/10 |
| LifeOS 引起的内容 hash 变化 | 0 |
| 强断言元数据变化 | 0 |
| 写 / 改名 / 删除调用 | 0 / 0 / 0 |
| sidecar / `.obsidian` 修改调用 | 0 / 0 |

**[已验证事实]** 扫描器只暴露枚举、范围判定和读取接口。只读权限阻止常规误写，双快照发现文件变化。`atime`、birth time、Finder/云盘元数据和跨平台 inode 不作强断言；Python 守卫也不是 OS 级 syscall sandbox，正式实现仍需保留权限、快照回归和平台级访问监测。

## 4. Source / Artifact / Version / 候选 Link 最小映射

| 外部观察 | 最小测试语义 | 身份与权限边界 |
|---|---|---|
| 一个获准 Vault | `Source` | 保存作用域化来源身份、连接/可达状态、授权引用；Vault 不等于 Project 或云/AI许可 |
| 一个 Markdown 文件 | 外部原始 `Artifact` | Artifact 身份与路径分开；路径只是当前 locator |
| 一次内容观察 | 来源版本 / `ArtifactVersion` 测试语义 | 精确 hash、大小、来源 mtime、观察时间、路径、解析状态；不冻结核心对象或 Schema |
| frontmatter/标签/目录 | 外部结构片段或候选 Link | 不自动成为 Project、事实、Action、Decision 或 Authorization |
| Markdown 链接/双链/嵌入 | 外部显式关系候选 | 保存原目标字符串和解析状态；不自动读取目标、不扩权 |
| 附件 | 来源指针 | 本任务只保留指针；不提取附件正文 |

**[已验证事实]** 每个初见文件建立独立 Artifact；同路径内容变化生成新版本。路径、hash、mtime、大小和 file key 都只是证据。失败观察可成为 current version，但 `last_valid_version_id` 保留上一完整版本。外部结构只进入片段或 `candidate`、`authorization_effect=none` 的 Link；本 Spike 不创建 Project、Action、Decision、事实或授权，也无 AI/云/第三方处理。

| 场景 | 期望 | 实际 | 结论 |
|---|---:|---:|---|
| 正常增量 | 新增/修改/删除 1/1/1 | 1/1/1 | Pass |

## 6. 移动、重命名、复制、删除身份判断与降级

候选策略按证据强度分层：

1. 同一路径、内容变化：同一 Artifact 新版本。
2. 旧路径消失、新路径出现，且本地平台文件标识唯一连续：可自动记录 locator 移动。
3. 只有 hash / 大小相同：建立新 Artifact，并产生“可能移动或重复”的候选 Link；不得强合并。
4. 多个旧对象或多个新对象共享内容：保持独立身份，候选可多义，等待用户确认。
5. 修改后删除或读取竞态最终只见缺失：标记来源侧缺失，不臆造未读取版本。

**[已验证事实]** 20 个明确样例中，同目录重命名 10 个、跨目录移动 10 个，识别 20/20，达到 Spike 暂定 ≥95% 门槛；错误强合并为 0。同内容 `one.md` 与 `two.md` 从首扫起就是两个 Artifact。复制 `New.md` 后删除原件产生新 Artifact 和 hash 候选，没有自动移动。

**[限制]** file key 在 Windows、网络盘、同步盘、复制恢复或跨卷移动中可能变化，只能作为本环境强证据之一，不能冻结为永久 ID。非唯一或 hash-only 证据必须候选化。

## 7. Markdown 兼容性与解析失败处理

`compatibility_matrix.csv` 覆盖 14 类。正常 frontmatter 保存 raw 与基础键值；重复键、畸形、未闭合及非 UTF-8 明确失败。标签、标题、显式块 ID、链接、双链、嵌入和附件都绑定精确版本；破损/歧义只保留原目标，不形成强 Link，附件不读正文。该最小解析器不代表完整 CommonMark/YAML、社区插件或编码兼容，正式库仍待架构确认。

## 8. 排除、撤回、路径越界、隐藏项和 `.obsidian`

**[已验证事实]** 目录遍历在进入目录前即过滤 `.obsidian`、隐藏目录、`excluded`、`withdrawn` 和 symlink 目录。直接请求层又拒绝：

- 带 `..` 的路径遍历；
- 绝对路径；
- 越界或任意 symlink；
- 隐藏 / `.obsidian`；
- 配置排除与撤回根。

七类探针执行后，读取 0、索引 0、外发 0。外发 mock 在整个 Spike 中没有任何内容事件。链接、嵌入或附件指向排除/越界目标时仅保存来源文件内的原始指针，不获得读取目标的许可。

**[推断]** 双层过滤证明候选路径默认拒绝；SP-04 仍需验证运行时授权，SP-05 仍需验证历史索引/缓存/副本清理。“撤回目录为 0”只代表新使用被阻断。

## 9. 不可达、恢复、断开和来源指针

不可达时返回 `source_unreachable`、读取 0，不等于删除或最新；恢复对账发现期间新增 1 个文件。`disconnect_source` 关闭连接/watcher，断开后新增文件读取 0。历史版本是否保留服从既有许可，物理清理由 SP-05 验证。

来源指针样例覆盖：

- Source + Artifact + 精确 Version + 相对文件路径；
- 标题文本定位，失败时降级到文件与附近文本；
- 显式块 ID，失败时降级到标题或文件；
- 来源不可达时保留最后观察版本和作用域化 token，明确 `source_unavailable_not_latest` 缺口。

指针返回前重检连接、可达、范围和排除；块位置不承诺永久稳定。

## 12. 最终结论：Pass with Conditions

候选脚本在明确范围内的机器结论为 PASS：全部 P0 只读、边界、对账、来源身份、解析失败、断开和隐私断言通过，且可一条命令复跑。但项目级结论为 **Pass with Conditions**，原因是移动身份依赖本地平台文件标识、块定位只验证显式 token 和降级、附件仅指针、且没有跨平台 / 同步盘 / 大 Vault 证据。上述缺口均属于任务卡允许的有限条件，没有绕过不可降级的只读、不越权、不写回和不自动业务化底线。

复验条件：至少一个额外平台验证 file key 与 rename/move/copy；同步盘模拟复制替换/临时文件；代表规模验证 reconciliation；正式解析库继续满足失败不覆盖；非唯一身份始终候选化。任一改写、越界、错误强合并、不可恢复漂移、失败覆盖、断源后读取或隐私泄漏均使结论转为 Fail。

## 13. 对 V1 条件需求、后续 Spike、风险和架构候选的影响

### 13.1 建议

- Obsidian 继续保持 `Should Have + 条件性需求`，不升为 Must，也不因本 Spike 自动进入正式开发。

- watcher 只作低延迟提示，reconciliation 承担最终对账；具体 watcher、调度和存储均不冻结。
- 继续继承 SP-03 的证据包络；Source / Artifact / Version / 候选 Link 的本次 JSON 仅是测试映射，不是 Schema/API。
