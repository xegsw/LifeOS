## 1. 任务边界与结论摘要

**[已验证事实] 本次 Spike 结论为 `Pass`，严格限定于 macOS arm64、Python 3.9.6、标准库、确定性合成夹具和 mock 处理者。** 可复跑测试共 48 项，48/48 PASS，P0 失败 0；真实网络、模型、云、第三方、Vault 和真实敏感数据调用均为 0。

本次证明了一个数据库无关的最小决策契约可以在本地读取 / 解析 / 索引 / 派生、入队、执行、LifeOS 云 mock、指定第三方 mock、保存输出、跨 Project 展示、再派生和候选对象写入前统一执行。任何 Authorization 不满足、政策硬门槛失败或状态不确定都不能进入处理；`INDETERMINATE` 只保留为诊断结果，执行层一律映射为 `DENY`。

## 2. 授权决策契约与最小实现

### 2.1 合同

每次请求形成一个短寿命决策上下文，至少包含：主体、完整输入集合及版本摘要、动作、目的、位置、实际处理者、候选 Authorization、当前时间、授权集版本、政策版本、任务租约、保留上限、地区限制和训练 / 评估选择。

判定公式为：

`ALLOW = 同一条当前有效 Authorization 六维全匹配 ∧ 强制政策包络全部满足 ∧ 运行时状态有效`

原始结果为 `ALLOW / DENY / INDETERMINATE`。只有 `ALLOW` 可执行；`DENY` 与 `INDETERMINATE` 均强制拒绝。允许结果必须返回当时命中的 Authorization；拒绝只返回受控原因码，不写正文、路径或提示词。

### 2.2 六维要求

1. **主体**：实际工作流必须包含在授权主体内，不能使用笼统的“LifeOS AI”。
2. **范围**：Project、Source、Artifact 和排除项共同判定；所有输入必须由同一条授权覆盖。
3. **动作**：`read`、`parse`、`index`、`derive`、`queue`、`execute`、`send`、`save_output`、`display`、`rederive`、`write_candidate` 分开。
4. **目的**：搜索、项目恢复、摘要、下一步、评估等不互相借用。
5. **位置**：本地、LifeOS 云和指定第三方 A 是不同位置 / 接收者；“云端”不是足够精确的位置。
6. **时效**：授权有生效时间、到期时间、状态和版本；过期、撤回或版本变化后不沿用缓存结果。

**[已验证事实]** 允许路径均能指向一条六维全匹配的当前有效授权；无授权、过期、撤回、主体、范围、目的、位置或处理者不匹配全部拒绝。搜索授权不能用于摘要，本地授权不能用于云，云授权不能用于第三方，第三方 A 授权不能用于 B。

### 2.3 为何不是 Schema / API 冻结

实现只使用 Python 内存字典、数据类和 JSON 结果，刻意没有数据库、HTTP、消息中间件或策略服务依赖。它验证的是“输入字段、判定顺序、失败语义和重检点”这一可移植合同。正式实现可落在模块化单体、函数边界、数据库约束或独立政策组件中，但不得弱化断言；本脚本字段名、枚举和缓存形式都不是正式 Schema / API。

## 3. 夹具、数据等级、处理者与政策包络

合成夹具覆盖 LifeOS 用户原文、模拟 Obsidian 外部原文、外部材料、公开内容、个人内容、客户秘密、凭据类、未知敏感级别、Project A / B / 无 Project、排除 Source / 目录 / Artifact，以及已删除、已撤回处理、断源、不可达状态。内容只是无现实含义的确定性 token。

处理者包括本地 runtime、LifeOS 云 mock、第三方 A mock 和未授权的第三方 B mock。授权组合包括本地搜索 / 恢复 / AI 派生、云处理、指定第三方、评估独立授权、过期、撤回和范围冲突。

强制政策包络检查：敏感级别、实际处理者、政策版本、子处理者、地区、训练 / 评估默认值、保留期限、删除能力、来源外发许可、处理者资格、跨 Project / 跨目的传播、数据最小化和凭据门槛。

**[已验证事实]** 政策未知、政策版本变化、子处理者未知、地区未知 / 不符合、训练或评估默认开启但无独立授权、保留超限、删除能力不足、来源禁止外发、处理者资格失败和未知敏感级别外发全部 fail closed。即使请求包含用户授权，也不能覆盖这些硬拒绝。

## 4. 本地 / 云 / 第三方处理边界

统一 evaluator 被用于：

- 本地读取、解析、FTS / 索引和本地派生；
- 入队与队列执行；
- LifeOS 云 mock 与指定第三方模型 mock；
- 输出保存、展示、再派生；
- 候选 Action / Link 写入边界。

允许的远端 mock 请求只含 `purpose`、`processor`、`policy_version`、`location` 和必要合成 `input_tokens` 五类字段。网关证据只保存字段名、数量和输入 token 的 hash，不保留发送正文。路径、无关元数据、排除内容、凭据和未知敏感内容不会进入远端 payload。

**[已验证事实]** 两条允许的远端 mock 路径字段集合与 allowlist 完全相等；全部拒绝路径 `sent_field_count = 0`。`actual_network_sends = 0`，因此本次“发送”只表示 mock 边界后的内存 payload，不是联网事实。

## 5. 入队、执行、外发、保存输出和长任务重检

判定不是一次性设置页状态，而是阶段门：

1. 入队前验证并记录授权 / 政策 / 输入 / 租约版本；
2. 执行前使用最新状态重判；
3. 外发前重判实际处理者、政策版本、地区、训练、保留和最小字段；
4. 保存输出前重判输入墓碑、授权、目的地和租约；
5. 长任务在关键分段、发布、索引和恢复包装配前重判。

竞态测试中，入队时允许，随后撤回 Authorization，执行前变为拒绝。长任务在第一段后撤回，第二段及后续发布、索引、恢复包检查全部拒绝；已计算但来不及取消的结果标为 `quarantined`，不进入任何用户可见或可再利用集合。外发前政策版本改变、保存前输入出现墓碑、保存前租约失效也全部拒绝。

**[推断]** 这证明“检查点 + 版本绑定 + 输出隔离”作为最小候选机制可实现；但并不证明正式队列的跨进程原子性、崩溃恢复或 SP-05 的物理清理覆盖。

## 6. Project / 外部结构 / 用户确认不扩权

`matches_scope` 先检查 Source / Artifact 排除，再检查明确 Scope，最后检查 Project 一致性。Project 只能进一步收窄，不能给 Source 或 Artifact 补授权。文件夹、标签、双链和候选 Link 没有进入授权匹配字段；它们只可形成外部结构或候选关系。用户确认也只可形成或收窄显式 Authorization，不能让不合格处理者合格。

**[已验证事实]** 排除 Source 即使归属 Project A 仍拒绝；排除目录即使有文件夹 / 标签 / 双链关联仍拒绝；排除 Artifact 即使存在候选 Link 仍拒绝；跨 Project 展示拒绝；受限输入形成的候选 Link 写入拒绝。测试中的扩权数为 0。

## 7. 多输入 Derivation 约束继承

两输入 Derivation 使用个人内容与客户秘密。合并输出继承最严格的 `client_secret`、仅本地、禁止外发和 7 天保留约束。本地目的合法时可生成；外部处理因来源禁止外发和授权交集为空而拒绝，且不创建输出。

合法子集只保留个人输入时，必须新建 `derivation-subset-v2`，不能修改旧 Derivation 的输入历史；它显式列出被排除的客户秘密输入，并披露“1 restricted input omitted”。因此用户看到的是“基于合法子集的新结果 + 上下文缺口”，而不是把不合法输入静默抹掉后假装完整。

## 8. 凭据硬拦截、最小化与审计隐私

凭据 / 私钥 / 恢复码类内容使用独立 `credential` 信号；一旦命中，即使六维授权和处理者政策均通过，也返回 `CREDENTIAL_HARD_BLOCK`。该层只负责额外收紧：未检测到凭据仍必须经过完整 Authorization 和政策包络，检测器不能成为“没检出就允许”的替代逻辑。

AuditEntry 只记录动作类别、结果 / 原因码、作用域化主体引用、对象集合摘要、授权集版本、政策版本和序号。隐私扫描检查用户 Home 路径、私钥头、恢复码、API key、提示正文、向量及合成正文 token，命中 0。样例未记录真实 Project 名、Vault 名、路径、正文、完整提示词、模型输出或向量。

**[风险]** 本次只证明固定夹具的日志字段最小化和确定性规则，不证明真实凭据检测的召回率，也不证明 hash / 精确时间组合在大规模真实数据中一定不可关联；这些仍需后续安全测试。

## 9. 测试矩阵与最低验收断言

`test_matrix.csv` 共 48 项，覆盖任务卡建议的 36 类场景并补充解析、评估独立授权、租约、候选写入、非逐字泄漏、否定查询和缓存隔离。结果：48 PASS，0 FAIL，P0 失败 0。

最低断言结果：

- 六维必须命中同一有效 Authorization：PASS。
- Authorization / 政策任一失败或不确定均拒绝，拒绝外发字段为 0：PASS。
- 用户确认不能覆盖处理者资格、未知政策、训练默认、删除能力或来源禁发：PASS。
- Project / 文件夹 / 标签 / 双链 / 候选 Link 不扩权：PASS。
- 搜索、本地、云、第三方 A 的授权不可跨目的 / 位置 / 处理者复用：PASS。
- 多输入最严格继承、合法子集新建并披露、空交集拒绝：PASS。
- 入队、执行、外发、保存和长任务重检：PASS。
- 撤回后竞态输出不可发布、索引或进入恢复包：PASS。
- 政策、供应商、位置、目的和范围变化需重判：PASS。
- 缓存键绑定主体、Project、目的、位置、处理者、授权 / 政策 / 输入 / 租约版本及时效：PASS。
- AuditEntry / 日志隐私扫描：PASS。

## 10. 最终结论及对 V1 的影响

### 10.1 Spike 判定

**`Pass`。** 任务卡规定的运行时授权、政策包络、默认拒绝、处理边界、竞态重检、约束继承、最小化外发和隐私 P0 断言全部通过，证据可一条命令复跑。mock、单进程和合成数据是既定实验边界，不构成本次 P0 失败。

### 10.2 能力建议

- **[建议] 本地读取 / 解析 / FTS / 索引可继续保留为 V1 候选基础能力**，但必须接入同一授权门，并继承 SP-02 的排除 / 断源边界与 SP-05 的清理结果。
- **[建议｜需 PM 确认] 本地 AI 派生继续作为条件能力**；正式本地 runtime、凭据检测误报 / 漏报、资源隔离和输出身份仍未验证，失败时降级为本地搜索与来源恢复。
- **[建议｜需 PM 确认] LifeOS 云处理只保留为“默认关闭、逐目的 / 范围明确授权”的条件候选**；本次只证明网关合同，不证明真实云的保留、删除、地区和子处理者能力。
- **[建议｜需 PM 确认] 第三方模型处理不得因本次 Pass 直接启用。** 在真实处理者能力矩阵、政策版本锁定、地区 / 子处理者、训练 / 评估、保留 / 删除及最小化验证通过前，应保持关闭；若 V1 排期无法完成资格验证，则移出 V1，而不是降低硬门槛。
- **[建议] 客户秘密、凭据和未知敏感级别默认排除云 / 第三方；候选 Action / Decision / Link 在 SP-06 前继续降级为 L1 Derivation 展示。**

本证据足以确认“一个 AI 总开关不可接受”和“统一网关 + 阶段重检 + fail closed”是实现必须继承的候选不变量；不足以决定任何真实供应商上线，也不足以冻结正式架构。

## 11. 风险、限制与后续任务

- **[风险]** 正式策略表达、冲突解释和授权缓存失效在高并发 / 多设备下尚未验证；交 SP-06 与架构验证。
- **[风险]** 撤回后的物理清理、备份、离线设备和第三方副本处置不在 SP-04；交 SP-05。
- **[风险]** 真实供应商政策可能变化或无法满足删除 / 地区 / 子处理者要求；资格未知必须保持关闭。
- **[风险]** 凭据检测会有误报 / 漏报；即使改进检测，也不能移除授权和来源许可判断。
- **[建议]** 后续 SP-05 直接复用本次原因码、阶段检查点、隔离输出和发送 manifest，验证活跃阻断与物理清理状态。

建议 PM 判断是否将“SP-04 mock Pass 被误读为真实云 / 第三方上线许可”和“政策 / 授权缓存版本失配导致旧允许复用”纳入 `RISK_LOG.md`；专项会话未修改 PM 文件。
