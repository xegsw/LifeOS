# LIFEOS-P1-007｜首页 / 今日页 Stitch 原型修改报告

- 任务状态：**Completed，待 PM 验收；原型未冻结。**

- 新状态名称：`今日 - 默认恢复态 (LifeOS)`、`今日 - 暂无可靠建议 (LifeOS)`、`今日 - 权限受限·离线 (LifeOS)`。
- 范围边界：未修改收件箱、知识库、知识详情、项目、IT 运维领域、智能体中心等其他页面；未新增其他产品功能页；未写代码、PRD、Schema、API、技术架构或工程排期；未放行 L3；未执行用户测试或技术 Spike。
- **[事实]** Stitch 的三张新状态画面已经生成；权限 / 离线状态首次生成后残留 Kubernetes 叙事，已进行一次仅限该画面的局部修正。
- **[判断]** 本次交付是冻结 PRD 的原型落实，不代表交互实现可行、用户价值已验证、原型已冻结或允许进入 Stage 2 / Stage 3。

## 2. 修改前问题摘要

修改前首页以“当前领域 · IT 运维”“Kubernetes 节点异常排查”、拓扑图、运维日程和服务器关联提示为首屏主叙事，容易把 LifeOS 解释成运维工作台。恢复摘要、用户原文、外部来源、AI 整理和用户确认状态没有形成稳定的可见区分；AI 提示缺少证据、时效、缺口与完整反馈入口；快速捕获没有诚实表达耐久保存、离线与失败；也缺少未选 / 无建议及权限 / 离线代表态。

## 3. 修改后页面 / 状态清单

### 3.1 默认恢复态

- 默认 Project 改为非运维样例“独立产品发布页改版”，并标示“沿用你上次确认”与切换入口。
- “从这里继续”成为首屏主角，呈现上次停点、关键决定、近期变化、开放问题、更新时间及“查看 3 条关键证据”。
- 恢复信息明确标为“AI 整理”；证据采用“你的记录 · 原文”“外部来源 · 用户访谈纪要”“你已确认 · 决定”等身份标签与差异化卡片语义。
- 仅保留一个候选下一步：“补齐移动端首屏文案，再发给 3 位访谈用户复核”，明确标为“AI 建议 · 未确认”，带简短理由、时效 / 证据入口及“确认、编辑、拒绝、忽略”。
- “今日安排”与 AI 候选分区，只示例用户已确认安排；快速捕获说明保留原文并表达“已耐久保存”。

### 3.2 暂无可靠建议 / 未选态

- 明确显示“尚未选择 Project”，提供“选择 Project”和“先记到 Inbox”。
- 使用中性文案“暂无可靠建议——选择 Project 或补充一条当前停点后再试”，不跨 Project 拼装恢复或建议，也不把无建议表达成系统失败。
- 保留快速捕获与少量最近痕迹，使用户即使未选 Project 仍可继续记录或主动定界。

### 3.3 权限受限 · 离线态

- 画面主 Project 同样改为“独立产品发布页改版”，二次修正后移除了 Kubernetes 拓扑、故障节点、Calico、服务器和运维日程残留。
- 首屏显示“当前离线：你的记录已在本地耐久保存，待同步”，恢复区说明部分来源当前不可访问及影响范围。
- AI 区安全降级为“无法访问用户访谈来源，暂不生成建议”，提供“查看影响 / 继续无 AI”，不伪造下一步、不形成告警墙。
- 快速捕获附近紧凑展示“保存中、已耐久保存、离线待同步、保存失败 · 重试”四种诚实状态；完整权限矩阵、审计和清理状态机未进入首页。

## 4. 模块级修改说明

| 模块 | 实际修改 | 继承规则 |
|---|---|---|
| Project 入口 | “领域”改为当前 Project；覆盖最近确认延续与未选态 | Project 只定界，不扩权；系统候选不能静默成为当前 Project |
| 恢复主面 | “继续进行”改为“从这里继续”，增加停点、决定、变化、开放问题、时效和证据入口 | 找回上下文优先于任务与日程 |
| AI 候选 | 至多一个，标“AI 建议 · 未确认”，增加理由、时效、证据和四类反馈入口 | 确认前不进入今日安排或承诺状态；保持 L1 / L2 |
| 快速捕获 | 强调保留用户原文，并覆盖耐久、离线、失败状态 | 未耐久时不使用含糊“已保存” |
| 近期变化 / 安排 / 痕迹 | 退到恢复之后；安排只示例用户已确认项；痕迹保持少量 | 不形成全局任务墙、完整日历或最近访问长表 |
| 异常提示 | 仅在权限 / 离线实际影响当前恢复和建议时突出 | 正常态不平铺授权、审计或清理控制台 |

## 5. 内容身份与 AI 规则落实

- **[事实]** 新默认画面以文字标签与不同卡片 / 图标语义区分用户原文、外部来源、AI 整理、AI 建议和用户已确认内容；AI 推断 / 建议统一保持候选身份。
- **[事实]** 候选下一步在确认前没有进入“今日安排”，并提供确认、编辑、拒绝和忽略；“完成 / 延期”只属于用户已确认 Action。
- **[判断]** 静态画面已满足最小身份可辨与渐进披露要求：身份、关键证据入口、未确认状态和影响恢复的异常首屏可见，完整来源链、授权、审计和清理信息后置。
- **[边界]** 画面中的来源、时效、耐久保存和权限状态是原型表达，不是 SP-01 / 03 / 04 / 05 / 07 已通过，也不是技术 SLA。

## 6. Stitch 未能充分表达的交互状态

1. Project 在“本次选择、最近确认延续、系统候选、未选态”之间切换后的授权重判、加载与跨 Project 清空过程。
2. “查看 3 条关键证据”展开后的完整 Source / Artifact 定位、支持 / 反证、版本、输入范围和处理位置。
3. 确认、编辑后确认、拒绝、忽略、完成、延期与撤回 Feedback 的追加历史及重新排序结果。
4. `stale`、`invalid`、来源重连、权限恢复、活跃阻断和物理清理状态的真实传播。
5. 保存中到耐久提交、离线同步、失败重试之间的真实动态转换，以及窄窗口 / 键盘 / 焦点 / 减少动态效果表现。

以上均应由后续交互原型、用户理解测试或对应 Spike 验证，不在本任务静态画面中伪装为已实现。
