## 3. 决策选项

### 选项 A：保持现状，仅作为候选，不恢复 / 不冻结

- **含义**：P3-009 继续维持"后续工程基线候选"状态，后续工程任务仍以 P3-001 为主要参照基线。
- **适用条件**：如果 P3-009 的工程链路尚不足以支持后续受控工程任务在其基础上继续扩展。
- **影响**：后续工程任务缺少 TypeScript/SQLite 目标栈的正式基线参照，每次新任务需重新确认参照点。

### 选项 B：恢复为受控工程基线扩展，但不冻结、不关闭 R-0040（推荐）

- **含义**：P3-009 正式成为后续受控工程任务的扩展基线，新工程任务在 P3-009 当前代码基础上继续构建，而非从零开始或仅参照 P3-001。
- **适用条件**：P3-009 evidence 充分、工程链路完整、默认关闭能力不变、R-0040 边界清晰。
- **影响**：后续工程任务可直接在 P3-009 上扩展，减少重复迁移成本；但必须遵守受控边界。
- **限制**：不等于冻结；不关闭 R-0040；不启用真实能力；不进入下一阶段。

### 选项 C：进入冻结准备流程，但需列出冻结前硬条件

- **含义**：启动工程基线冻结准备，列出冻结前必须满足的硬条件清单。
- **适用条件**：P3-009 已接近可冻结状态，只需少量补充验证。
- **影响**：冻结准备流程会引入额外验证任务和用户确认环节。
- **不推荐原因**：当前真实 Tauri/IPC 未验证、R-0040 未关闭、生产 Schema/API 未定义，冻结条件差距过大。

### 选项 D：不建议恢复，需返工或补充验证

- **含义**：P3-009 当前不具备恢复条件，需要返工或补充验证后重新评估。
- **适用条件**：存在未关闭的 P0/P1 缺口，或 evidence 链路存在不一致。
- **不适用原因**：当前无 P0/P1 缺口，evidence 一致，工程链路完整。

## 4. 推荐选项

**推荐 B：恢复 P3-009 为受控工程基线扩展，但不冻结、不关闭 R-0040。**

### 理由

1. **[判断]** Evidence 充分性：37 项测试 + 63 条独立反例攻击 + P1-1 至 P1-8 全量迁移 + P2 清洁项完成，覆盖了 H1-H9 / T-ARCH 核心不变量在合成、单进程、受控测试包边界内的全部验证需求。
2. **[判断]** 工程链路完整性：从 P3-009 骨架建立到 P3-022 P2 清洁，形成了完整的"建立 → 修复 → 迁移 → 清洁"闭环，每个关键节点有独立评审或 PM 复跑，无自证循环。
3. **[判断]** R-0040 兼容性：R-0040 的风险面是"真实 Tauri capability/IPC/路径 scope 绕过领域授权门"，与"在合成、单进程、受控测试包内恢复工程基线扩展"不冲突。恢复工程基线扩展不启用真实 Tauri/IPC，不改变能力关闭状态，不关闭 R-0040。
4. **[判断]** 与 P3-001 的关系：P3-001 作为 Python 基线候选保持不变，P3-009 作为 TypeScript/SQLite 目标栈基线扩展与 P3-001 互补，不替代 P3-001 的历史证据价值。
5. **[判断]** 冻结条件不足：真实 Tauri/IPC 矩阵未迁移、生产 Schema/API 未定义、真实数据/Vault/文件能力未验证、R-0040 未关闭。当前恢复为"基线扩展"而非"冻结"是恰当的中间态。
