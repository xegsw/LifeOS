## 1. 执行摘要

1. **[事实]** SP-01 至 SP-09 均已完成、经 PM 验收并由用户采纳；其中 SP-02、SP-09 为 `Pass with Conditions`，其余为有限实验边界内的 `Pass / Accepted but Not Frozen`。没有任何 Spike 冻结数据库、Schema、API、框架、供应商、SLA 或技术架构。
2. **[结论]** 9 个 Spike 已足以结束“宽泛阻断型技术 Spike”工作线，并进入“技术架构冻结前条件整改与独立评审准备”；不需要为了追求全覆盖继续追加 PostgreSQL、pgvector、真实模型或真实 Vault 的泛化 Spike。
3. **[建议｜需 PM 确认]** V1 候选采用桌面 / 本地优先、权威原文与控制账本本地耐久保存、派生可重建、`SQLite + FTS5` 的 FTS-first 路径；向量不作为默认硬依赖。`Tauri 2 + React/TypeScript/Vite`、`Fastify`、`PostgreSQL`、`pgvector` 仍只是候选，其中后三者仅在少设备同步或经证据证明的语义检索进入 V1 时启用。

5. **[条件]** Obsidian 保持 `Should Have + 条件性需求`。合成 Vault 证据支持只读来源候选，但跨平台、同步盘、大 Vault、正式解析库和真实 Vault 行为未验证；不满足条件时降级为手工导入 / 来源指针，不阻断不依赖 Obsidian 的 Must 闭环。
6. **[结论]** 可收口的是“Stage 2 阻断型技术 Spike 线”，不是 Stage 2→Stage 3 关卡。技术架构尚未整改、独立评审和 PM 冻结；关键动态体验 / 用户价值验证尚未完成。因此正式 MVP 开发继续 `Blocked / Not Allowed`。

### 3.2 必须继承的数据与信任语义

**[事实 / 不可降级]** 用户原文、外部原文、AI 派生、AI 候选与用户确认对象必须分离；Source、精确版本、Derivation、Authorization、Feedback、AuditEntry、Link、墓碑与 generation 必须可表达。Project、文件夹、标签、双链和相似性不得扩权。删除 / 撤回采用“事务内活跃阻断 + 异步物理清理”，恢复 / 导入 / 重连必须先应用更高 generation 的控制状态。派生、FTS posting、向量、缓存和重排特征可失效、可删除、可从当前合法原始数据重建。

### 3.3 能力强度结论

- **Must：** 本地耐久捕获、不可变原文版本、FTS + 元数据找回、证据化恢复包、对象级确认 / Feedback、统一授权门、四类命令、活跃阻断、基础导出、数据库感知备份与安全恢复。
- **Should / 条件：** Obsidian 只读；少设备非实时同步；真实模型；文件正文 / 附件处理；云端索引。任一失败不得拖垮 Must 闭环。
- **Not Now：** Obsidian 写回 / 插件 / 双向同步、默认全量向量、pgvector / ANN 硬依赖、专用向量库、微服务、Kafka、Kubernetes、图数据库、重型 Agent 框架、真实第三方默认启用、生产级灾备或性能 SLA 承诺。

## 5. Stage 2 收口判断

**[建议｜需 PM 确认] 结论：Stage 2 的阻断型技术 Spike 工作线可条件收口；Stage 2 整体及 Stage 2→3 关卡不可收口。**

收口边界是：SP-01 至 SP-09 不再作为开放验证清单继续扩张；它们共同成为技术架构条件整改与独立评审输入。允许下一步只做冻结前整改、窄范围补证、独立评审和 PM 决策，不允许开始产品功能工程实现、真实敏感数据、真实 Vault、真实云 / 第三方或生产承诺。

不能把该收口外推为：SP-02 / SP-09 无条件通过、技术架构 Frozen、Gate 4 无条件通过、关键原型动态验证完成、Gate 5 用户价值证据完成，或 Stage 3 已准入。

**当前状态：`Blocked / Not Allowed`。** 阻塞项为：
