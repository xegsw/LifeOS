## 2. M-01｜四类命令最低领域效果矩阵

处理许可与保留许可必须分别判定；一个命令不得冒充另一个命令的结果。组合意图必须组合显式命令，例如“断开来源并删除快照”同时执行 `disconnect_source` 与 `delete_content`。

| 影响面 | `revoke_processing` | `disconnect_source` | `delete_content` | `retract_feedback` |
|---|---|---|---|---|
| Authorization / Source | 撤回命中范围的处理许可；不自动断源 | 停止 Source 读取、监听、同步；不自动删除已存内容 | 撤销目标内容的使用与保留许可；目标为 Source 时删除可识别连接资料 | 不改变 Source/Artifact 授权 |
| Artifact / 版本 | 权威原文默认保留，但不可再用于被撤回处理 | 外部原件不变；LifeOS 副本按既有保留许可处理 | 删除目标正文、版本及可识别副本；外部原件不受控时明确边界 | 无直接影响 |
| Derivation / Link / 候选 | 依赖命中授权者 invalid，退出展示、检索、排序、建议与再派生 | 实时依赖者 stale/invalid；剩余快照按许可重判 | 依赖目标者 invalid；可还原内容清理 | 直接依赖该 Feedback 者重算、stale 或 invalid；AI 来源身份不变 |
| 用户确认 Assertion / Decision / Action | 不删确认历史；唯一证据失效则待复核并退出自动依据 | 同左；断源不等于撤销用户认可 | 删除证据时同左；若对象本身是删除目标则执行删除 | 追加撤回记录；由有效 Feedback 重算认可状态，不逆写历史 |
| 索引 / 缓存 / 队列 | 活跃路径立即阻断；按剩余合法输入重建或清理 | 不合规副本清理，合法保留内容按剩余授权重建 | 对应 FTS、向量、缓存、prompt 副本阻断并清理 | 仅重建受反馈状态影响的派生索引/缓存 |
| AuditEntry | 记录命令类别、作用域化范围、原因码、阻断与清理状态 | 记录断开及副本处理结果 | 记录删除、不可还原墓碑和清理结果 | 保留原反馈事件并追加撤回事件 |
| 备份 / 离线 / 导出 / 第三方 | 恢复或重连先重放撤回；停止新发送，副本按独立保留依据处置 | 不恢复监听；旧副本按原授权/保留指令处置 | 墓碑优先，禁止复活；第三方删除状态如实标注待删、失败或受限 | 重放撤回并重算；旧确认不得静默胜出 |

四类命令至少区分“已耐久接受、活跃使用已阻断、物理清理中、清理失败、供应商受限、可控范围已清理、无需物理清理”；具体状态命名与 UI 未冻结。

## 3. M-02｜Derivation 约束继承合同

每个 Derivation 除 P0-003 的输入版本、目的、工作流/模型、位置、权限上下文、状态与失效原因外，必须携带可判定的输出约束包络：允许范围/Project，允许目的与禁止再用途，允许处理/保存位置及接收方类别，敏感级别与披露限制，保留/删除条件和到期时间，训练/评估禁用状态，来源许可/外发限制，Authorization 与政策版本引用，以及当前有效、stale、invalid、待复核状态。

多输入取允许集合的交集和各限制的最严格值；不能合并时缩小到合法子集或拒绝，摘要、聚合和改写不得洗掉限制。跨 Project 展示必须重判目标 Project、目的、位置与接收主体；保存是新的传播动作，须保留原来源链和约束；再派生须同时检查原输入和中间 Derivation。合法输入子集变化时必须生成新 Derivation 并声明缺口，不得删引用后沿用旧输出。非逐字事实、存在性、关系、排序、候选 Link、向量近邻和恢复包同样属于披露。

## 4. M-03｜五类状态正交分离

| 维度 | 权威语义 |
|---|---|
| 来源身份 | 内容是用户原文、外部主张、AI 整理/推断/建议等；AI 来源身份不可被 Feedback 改写 |
| 用户认可 | 由追加式 Feedback 计算确认、拒绝、纠正、撤回等当前效力；保留历史链 |
| 业务状态 | Action 的候选/承诺/进行/完成等、Decision 的生效/修订/替代等各自演进 |
| 证据状态 | 证据可用、`evidence_unavailable`、`review_required`，独立于用户是否曾确认 |
| 派生状态 | Derivation 的有效、stale、invalid、待复核与可重建状态 |

证据删除、断开或许可失效不静默删除用户确认历史；若缺少足够有效证据，对象保留历史身份但标记 `evidence_unavailable/review_required`，退出自动排序、提醒、建议、模型依据和“证据充分”表达。新的有效证据或用户复核通过追加 Feedback/Link 恢复效力，不覆盖历史。

## 5. M-04｜墓碑优先与导出不复活

1. `delete_content` 必须产生不可还原、不可枚举的墓碑或最小删除说明；墓碑仅证明删除范围与处理状态，不保存或暗示正文。
2. 备份恢复、同步合并和离线重连须先应用墓碑、授权撤回与 Feedback 撤回，再接纳旧版本、执行队列或开放搜索/派生；旧副本不得覆盖当前删除和用户权威状态。
3. 导出前重新判定当前 Authorization、来源许可、保留许可、墓碑和 Derivation 输出约束。已删除/撤回正文、不可导出外部内容和可还原派生不得进入正文、manifest、缓存或历史记录。
4. 重导入先应用包内及当前环境的墓碑、撤回和权限说明，以更严格且更新的用户权威状态为准。可重建基础设施派生可不导出，但不得从旧包复活。
5. 用户确认对象可保留历史；证据失效时导出必须携带待复核语义，不能伪装为证据充分。

## 6. M-05｜AuditEntry 收紧与防反向识别

AuditEntry 只记录解释关键操作所需的：允许列表动作类别、作用域化主体引用、随机不可枚举对象/范围引用或聚合类别、Authorization/政策版本引用、最低必要时间粒度或序列号、结果/允许列表原因码，以及活跃阻断和清理状态。

禁止记录用户原文、摘要或模型输入输出、向量/可逆特征、文件名和路径、Project 名、完整 URL、可猜测内容哈希、连续 ID、跨域稳定 ID、自由错误文本、请求/响应体、队列 payload、堆栈变量、高风险推断标签及可暴露敏感对象存在性的细粒度事件。用户审计、运行日志、安全调查、产品遥测必须用途分离；标识按用户/Project/目的或时间窗作用域化，映射单独最短保留并最小访问，删除后解除映射、轮换或删除。导出仅含用户可理解的最小说明。

SP-05 必须验证路径/Project 字典攻击、ID 枚举、时间线关联、跨日志域拼接、错误上下文、小样本唯一性、删除前后链接及客服/导出越权；标准是不仅不可还原正文，也不能以合理成本推断敏感对象、活动或 Project 的存在。
