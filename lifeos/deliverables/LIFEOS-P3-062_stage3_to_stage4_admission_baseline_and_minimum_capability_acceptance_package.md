# LIFEOS-P3-062｜Stage 3→4 准入事实基线与最小能力验收包

## 结论与适用边界

### 事实

- 当前为**有限 Stage 3 受控工程线已收口，Stage 4 未准入**。P3-061 的五项阻断仍成立：真实可用 MVP、基础导出、基础权限设置、错误／数据恢复策略、Alpha 用户使用说明均无可验收的真实能力 Evidence。
- 产品定位、目标用户、V1 第一场景、核心领域模型 V0.1、AI 权限与信任模型 V0.1、V1 范围、首页／今日页 PRD 与静态关键原型、技术架构 V0.1 合同仍为 Frozen；Schema/API、工程基线、真实能力及 Stage 4 均未冻结。
- P3-031、P3-050、P3-054、P3-057、P3-060 的 SQL／合成 SQLite／受控测试证据可证明有限 Stage 3 内的候选约束与历史谱系，不能证明真实桌面应用、真实导出、真实恢复、真实权限运行链或 Alpha 可用性。
- R-0043–R-0050 的关闭仅覆盖各自 hash、合成 SQLite、八配置和单用户／单设备／本地受控边界；R-0040 仍为 `Open / Conditional`，真实 Tauri capability、IPC、路径 scope、Vault 与相关文件能力在复测和授权前必须保持关闭。

### 推断

当前可安全开展的工作不是“补一个总测试”或恢复工程基线，而是将每个真实能力拆成可停止、可审计、不可外推的最小工作包。任一工作包成功也不自动满足其他门槛，亦不自动允许 Stage 4。

### 本包状态

本包是 PM／用户后续决定的**非实施性准备输入**。它不作 Stage 4 准入结论，不关闭／重开风险，不恢复工程基线，不冻结资产，也不授权真实能力。

## Stage 3→4 五项硬门槛验收矩阵

所有“通过”均要求：事前获得对应的用户授权与任务卡、使用隔离环境和非真实用户数据（除非用户另行明确授权）、保留输入／版本／测试／失败记录；PM 读取专属 Review 与 Evidence 后，用户再决定是否接受。任何 P0/P1、Evidence 不可复核、权限边界扩大、真实能力默认关闭失效或与冻结合同冲突，立即停止，不以条件通过替代。

| 硬门槛 | 最小可验收结果 | 允许／禁止 Evidence | 责任与独立评审 | 停止条件与用户确认 |
|---|---|---|---|---|
| 1. 可真实使用的 MVP | 在受控真实运行环境完成“本地捕获→保存→来源可见→项目恢复／下一步确认”的最小闭环；原文、AI 内容、建议与用户确认状态可区分；关键失败可见且不会伪称已保存。 | 允许：可复现运行记录、版本锁定、最小场景脚本、失败／恢复记录、可用性观察。禁止：仅 SQL 单测、截图、mock 或合成测试替代端到端闭环。 | 产品架构主责；体验、数据、AI 信任、技术协审；涉及真实桌面壳时须隔离独立技术／体验复评。 | 捕获耐久、来源身份、确认语义或错误提示不成立即停止。用户须确认真实运行能力的启用范围与是否进入下一能力包。 |
| 2. 基础导出 | 用户能发起、预览并确认一次性最小导出；范围、目标、冲突、结果、失败和“非同步／非写回”语义可见；导出内容可由用户核对来源与身份。 | 允许：经授权的隔离文件夹、导出清单、hash、失败／回滚与路径 scope 记录。禁止：把 SP-03/08 包络、模拟 JSON 或候选 SQL 当正式导出；不得写入 Vault 或用户未确认路径。 | 数据／领域模型主责；产品、AI 信任、技术与体验协审；文件能力与 Tauri/IPC 须独立复评。 | 路径 scope、确认、冲突、来源／AI 身份或失败处理缺一即停止；R-0040 未先按专属门满足时不得开始。用户须逐次授权目标范围。 |

| 4. 错误和数据恢复策略 | 明确故障分类、已保存语义、备份／恢复前提、恢复步骤、完整性校验、失败披露与不可恢复边界；演练证明不会静默丢失或复活已撤回内容。 | 允许：隔离故障演练、恢复 runbook、校验结果、失败日志、恢复后授权／tombstone 负测。禁止：以 SP-01 或 P3-060 通过、备份存在或口头策略替代真实恢复演练。 | 技术架构主责；数据、AI 信任、产品与体验协审；涉及真实 DB、并发或恢复时独立复评。 | 任一恢复造成原文丢失、错误“已保存”、越过 tombstone／授权、Evidence 缺失即停止。用户须确认可接受的数据丢失／恢复提示边界。 |

## Gate 1–5 差距判断

| Gate | 已可用的定义层输入 | 尚缺的运行／用户 Evidence | 不可被替代的部分 |
|---|---|---|---|
| Gate 1 产品一致性 | Frozen 定位、目标用户、第一场景、V1 范围、首页／今日页规则。 | 真实 MVP 中“捕获—恢复—下一步确认”闭环及错误态是否仍服务个人外脑。 | 合成 SQL、风险关闭或功能清单不能证明产品闭环。 |
| Gate 2 数据与来源 | Frozen 领域模型、来源／派生／确认语义；受控谱系约束。 | 真实导出与恢复时原文、外部来源、AI 生成／推断／建议、确认事实的可见性与可追溯性。 | 候选数据库表和 hash 不等于运行时语义。 |
| Gate 3 AI 权限与信任 | Frozen 信任模型与候选 fail-closed 约束。 | 可理解的真实设置、撤回运行链、审计、处理位置边界及用户纠正体验。 | mock 或离线 trigger 不等于真实能力启用许可。 |
| Gate 4 技术可行性 | 技术架构 V0.1 合同、P3 受控回归与 R-0040 停止边界。 | 真实桌面壳、IPC／path scope、导出、恢复、故障处理的专属复测与 Evidence。 | 有限 SQLite 八配置不能替代真实 Tauri/IPC 或文件能力。 |
| Gate 5 用户价值 | Frozen 目标用户／场景与既有验证计划。 | Alpha 使用说明、受控 Alpha 使用、理解度／价值／反证证据；外部验证暂停时至少需用户明确恢复条件。 | 内部自评、活跃量或工程通过数不能证明价值。 |

本任务仅表明 Gate 1–5 的定义层输入可供后续设计；**没有任何 Gate 可被判定为 Stage 4 已通过**。

## 开放风险与确认节点

- **R-0040：** 对真实 Tauri/IPC、路径 scope、Vault 与文件导出具有阻断效力。未完成专属、隔离、授权的真实能力复测前，相关功能默认关闭。

- **需要 PM／用户确认：** (1) 是否授权任何一项真实能力的前置验证；(2) 每项的真实数据、环境、参与者与退出范围；(3) Alpha 是否恢复、对象与暂停条件；(4) 在全部专属 Evidence、独立 Review 与 Gate 1/3/4/5 通过前，是否仍维持 Stage 4 未准入。以上均非本包可代为确认。
