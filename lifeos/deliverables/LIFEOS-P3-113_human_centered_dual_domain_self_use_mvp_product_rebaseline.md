## 1. 一句话产品定义与首个用户结果

### 1.1 候选的一句话定义

> LifeOS 是由用户控制、可追溯、可纠错的长期外脑；它以「人」为主要主体，在工作与健康／健身两个生活领域中连接长期记忆和今日状态，主动提出会改变判断的少量问题，并给出可解释、可反馈的少量建议。

这一定义并不把 Project 删除或降级成无关对象：Project 是工作领域内重要的上下文、目标和承诺组织方式，但不能再成为默认首页中心或全局价值代理。

### 1.2 首个用户可感知结果（候选）

用户打开首页时，不必先选择 Project。首页应让用户在一个可控制的视图中看见 **1–3 件值得记录、回答、决定或行动的事**；每一项可见来源／时间／确定性／适用范围和「为何现在出现」。首页最多提出 **0–1 个问题**，且只有答案会实质改变排序、建议或安全降级时才提出。信息不足时，系统明确说「目前不能可靠建议」或给出更保守的非医疗行动，而非伪装确定性。

## 2. 双领域闭环与范围

### 2.1 必须成立的七段闭环（候选合同）

`多源感知 → 长期记忆 → 当前理解 → 主动提问 → 个性化建议 → 用户反馈 → 记忆／理解更新`

| 环节 | 候选最低要求 | 失败关闭／用户控制 |
|---|---|---|
| 多源感知 | 仅接收用户授权的记录、用户明确输入或未来经单独授权的来源；本轮只定义固定合成情境。 | 无来源、身份或授权即不进入判断。 |
| 长期记忆 | 每条重要记忆保留内容身份、来源、时间、确认状态、事实/推断、有效性、范围、时效和更正链。 | 推断不得覆盖原文；冲突／过期必须可见。 |
| 当前理解 | 把工作、健康／健身的已确认事实与不确定性分开，并显示判断依据。 | 无法可靠合成时不输出个性化结论。 |
| 主动提问 | 最多一个、可跳过、答案会改变决策的问题。 | 未回答不追问轰炸；高风险信息缺失则停止相关建议。 |
| 个性化建议 | 首页只呈现 1–3 条，逐条说明理由、证据、确定性、适用范围、时间、可行动步骤和停止条件。 | 不做自动执行；健康相关只保守低风险生活方式／健身信息。 |
| 用户反馈 | 采纳、跳过、无帮助、纠正、暂停／撤销可见且可选。 | 反馈是新证据，不是静默改写或全局规律。 |
| 记忆／理解更新 | 以可追溯的新版本、Feedback 和 Derivation 更新；支持确认、更正、过期、删除。 | 更正保留历史；删除遵守既有授权、审计与清理合同。 |

## 3. 最小语义与历史领域模型的映射

下列是**产品语义候选**，不是数据表、Schema、API 或页面冻结。

| 新语义 | 候选定义 | 与既有冻结语义的最小映射 | 禁止误读 |
|---|---|---|---|
| Person | 被 LifeOS 服务的单一用户主体；不是认证账户或数据库根对象。 | 通过既有 Authorization 表达用户控制，通过 Source/Artifact 保留其记录。 | 不新增身份系统。 |
| Life domain | 用户命名的持久生活语境；本候选为工作、健康／健身。 | Project 仅可作为工作领域里的上下文／目标组织；Link 表达关联。 | Project 不再默认等于 Person 或首页。 |
| Goal | 用户希望维持、完成或改变的结果。 | 可关联既有 Project、Action、Decision、Assertion 和 Link。 | 不把建议自动转为目标或行动。 |
| State | 某时点的已确认观察、用户报告或显式 AI 推断。 | 使用 Assertion/Event 的来源与时间，并由 Derivation 区分推断。 | 不把推断写回用户事实。 |
| Constraint | 会影响建议的已确认限制、边界或时效条件。 | 作为带来源、有效期与范围的 Assertion；相关授权仍受 Authorization 控制。 | 不从一次反馈全局泛化。 |
| Preference | 用户明确表达或确认的偏好，且有范围、时效和可撤销性。 | 由 Feedback 或用户输入形成可审计证据链。 | 不能由点击／沉默自动升级为永久偏好。 |
| Memory | 可检索、可回顾的长期理解单元；由 Source、Artifact、Derivation、Feedback 和 Link 组成的可追溯视图。 | 复用内容身份、来源、派生、反馈、授权、审计原则。 | 不是脱离原文的黑箱画像。 |

每条重要 Memory 至少暴露：`content identity`、来源、记录／观察时间、确认状态、事实或推断、有效性、适用范围、时效、关联 Feedback／Derivation、以及可执行控制。其状态变迁为：候选记录或推断 → 用户查看 → 确认／更正／标为过期／删除；更正创建可追溯新版本，反馈撤销会重新计算相关理解但不静默抹除历史。

## 4. 首页、问题、建议与反馈合同

### 4.1 首页合同（候选）

1. 首页以 Person 的「今天」为焦点，不能要求先进入 Project，不能将 Project 卡片固定为第一主轴。
2. 首页最多 1–3 条建议。每条都必须显示：建议文本、为何现在、来源与内容身份、时间／时效、确定性、适用范围、可执行下一步、停止或降级条件、查看证据、反馈与暂停入口。
3. 首页最多 0–1 个主动问题。提出阈值是：回答会改变安全分类、建议是否出现、建议排序或具体下一步；否则不提问。
4. 未回答问题时，系统不得施压、伪装已知，也不得在健康限制不清时继续给训练建议。
5. 每条建议可反馈「有帮助」「不适用」「跳过」「纠正依据」「暂停此类建议」。反馈以 Feedback 追加，且只有用户明确确认时才可形成跨日期的偏好或约束。
6. 用户可展开理由、检查来源、确认／更正／过期／删除相关记忆；任何建议不自动执行行动，不改变用户原文。

### 4.2 进入候选的建议字段

| 字段 | 合同 |
|---|---|
| 建议与下一步 | 简短、可选、可拒绝的行动或记录提示。 |
| Why now | 指明当前状态、时效和跨领域关系，不使用隐形排名。 |
| Evidence | 指向可见的来源、内容身份、时间、确认状态。 |
| Certainty | 确定／不确定／信息不足；不确定不得伪装为事实。 |
| Scope | 仅对说明的 Person、领域、日期／情境有效。 |
| Safety | 健康／健身场景的停止、降级或转专业人士条件。 |
| Feedback effect | 显示反馈会怎样被记录，且不把一次反馈自动推广。 |

## 5. 固定合成跨领域情境与安全退化

### 5.1 情境（仅候选核验，不是用户数据）

虚构用户「Y」在同一天拥有以下**合成、非敏感、不可用于医疗判断**的已确认输入：

- 工作：10:00–16:00 有两段各 60 分钟的产品演示准备；当天工作负荷标为「高」。
- 健康／健身：自报睡眠 5.5 小时、疲劳 7/10；已确认的限制是「避免跳跃／冲击动作」；18:30 仅有 20 分钟。
- 未知的高价值信息：膝部不适是否相对已确认限制明显加重，或是否出现无法承重、明显肿胀、受伤后恶化等需要停止训练并寻求专业意见的信号。

首页可问的唯一问题是：**「今天的膝部不适是否比已确认限制明显加重，或出现无法承重、明显肿胀、受伤后恶化？若有，请不要安排训练并考虑联系合适专业人士。」**

| 情况 | 候选输出 | 不允许的输出 |
|---|---|---|
| 未回答 | 不提供训练处方；建议将 20 分钟留给休息、记录状态或在用户自行判断舒适且不加重的前提下进行非冲击的日常恢复活动。 | 诊断、训练强度处方、保证安全、继续追问。 |
| 回答有高风险信号 | 停止健康／健身建议；明确建议寻求合适专业人士支持。 | 判断伤病、推荐治疗、替代医疗建议。 |
| 回答无加重／无警示且无专业限制 | 可给一条保守、非医疗的 10 分钟低强度非冲击恢复活动建议；说明随时停止、不做跳跃／跑步、以舒适为限。 | 以疲劳分数推断疾病或开具训练方案。 |
| 用户反馈「今天超载，休息更合适」 | 将反馈作为当日情境证据，保留在建议链中；只有确认后才可形成有限范围偏好。 | 把一次反馈静默写成永久健康规则。 |

工作负荷、睡眠、疲劳、膝部限制和可用时间只共同影响建议的**保守程度、排序及是否停止**。它们不能被系统扩展为医学诊断，也不能据此自动安排工作或健身。

### 5.2 安全降级矩阵（候选）

| 触发 | 必须动作 |
|---|---|
| 来源、内容身份、授权或时效缺失 | 不进入个性化判断；展示缺失和可补充入口。 |
| 记忆是未确认推断、相互冲突或超期 | 降低确定性；不据此触发高影响建议；必要时只问一个会改变判断的问题。 |
| 健康高风险信号、专业限制不明或问题未答 | 停止训练建议／降为休息、记录、寻求专业意见；不作医学判断。 |
| 用户撤销、暂停、删除或反馈纠正 | 即时停止相应推断／建议并保留可审计授权与更正链。 |
| 真实模型、第三方、网络或真实数据 | 本任务没有权限；必须在单独任务和明确用户确认后才可讨论。 |
