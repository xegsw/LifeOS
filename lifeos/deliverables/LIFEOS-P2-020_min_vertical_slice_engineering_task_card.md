## 5. 测试阈值、DoD 与结论

- 最小测试集：`T-SCOPE`、`T-ID`、`T-SAVE`、`T-GATE`、`T-DEL`、`T-IPC-OFF`、`T-DATA`、`T-OFF`、`T-UX`、`T-EXPORT`、`T-ARCH`；每项须有确定性夹具、环境、复跑方法与断言。
- **P0 阈值：零失败。任何 P0 失败不得判 `Pass with Conditions`。** P1 仅限不破坏底线的可用性、文案或非关键证据缺口，且必须有明确降级 / 关闭能力、责任人、期限并获 PM 接受。
- DoD：Must 主路径与全部规定异常路径可复跑；适用测试 P0=0；证据 manifest 完整；默认关闭能力不可达；删除 / 撤回活跃阻断、导出 / 恢复与不复活通过；动态状态和基础可访问性走查完成；没有把合成 / mock 写成真实能力、生产 SLA、Gate 5 结果或新冻结。
- `Pass`：DoD 全满足且适用 P0 全通过；`Pass with Conditions`：仅非底线 P1 遗留且 PM 接受关闭 / 降级；`Fail`：可修复但未达 DoD；`Paused`：出现原文丢失 / 静默覆盖、身份混淆、越权、重大动作未确认、撤回 / 删除后仍活跃、复活、默认关闭能力旁路，或闭环在约定自用窗口内无法稳定恢复上下文与完成反馈。

## 6. 失败、降级、回退与暂停规则

- 发生 P0：立即停止受影响路径，保留证据，关闭相关能力，回退到最近通过的合成夹具 / 确定性实现；不得继续扩功能。
- 允许降级：手选 Project、FTS + 元数据、规则 / stub 或无候选、手工来源指针、内存或受控测试包导出、L3 降为 L1 展示。
- 不可降级：原文保护、身份区分、证据追溯、默认拒绝、对象级 / 重大动作确认、四命令分离、活跃阻断、不复活和基础导出责任。
- 代码完成不等于任务验收；任务验收不等于能力启用；本任务通过不等于无条件 Stage 3、Gate 5 结果层、Beta 或商业化通过。
