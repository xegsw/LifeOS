# LifeOS Codex Cyber 安全提示语境整改方案

日期：2026-08-21  
任务类型：PM 流程治理 / 提示语境整改方案  
当前状态：Implemented / User Authorized  
执行范围：已修改未来任务模板、PM 稳定下发规则、跨 Agent 简报和 PM 决策记录；未追溯修改历史任务卡、Evidence、冻结或风险状态

## 1. PM 结论

LifeOS 当前反复出现 Trusted Access / Cyber safeguards 提示，最合理的解释不是普通网络连接或 macOS 局域网权限失败，而是近期工程任务包含高密度双用途安全语义，并且授权、本地范围和防御性用途没有在任务提示最前部一次性说明。

整改应保留准确技术术语和现有高风险关卡，在任务启动语之后、任务详情之前加入一段简短且可审计的“授权与安全语境”。不应通过删除关键术语、模糊化测试目的、降低模型、关闭检查或改变测试预期来减少提示。

## 2. 已验证事实

### 2.1 Codex / OpenAI 侧

- 截图对应 Codex 客户端的 Cyber safety banner，而不是一般网络访问许可提示。客户端英文原文明确提到部分 cybersecurity 请求受额外 safeguards 约束，并引导用户前往 Trusted Access 验证身份。
- OpenAI 官方模型指南说明，GPT-5.6 使用实时 cyber / biology misuse classifiers；在防御性与攻击性用途外观相似的双用途任务中，正当代码审查、漏洞研究、补丁开发、调试和防御性测试也可能被额外检查或拦截。
- 官方提示建议提供明确的领域上下文、硬约束、授权边界和成功标准；同时建议保持提示精简、每条规则只陈述一次，避免长会话放大重复内容。
- 官方依据：<https://developers.openai.com/api/docs/guides/latest-model#safeguards>。

### 2.2 LifeOS 项目侧

- 本整改最初盘点时，`LIFEOS-P3-049` 是 P0 整改链的隔离独立工程复评，任务卡开头集中出现“反例攻击、权限撤回、删除历史、旁路、主动寻找执行侧矩阵之外反例”等双用途语义。
- P3-049 现已完成 PM 验收并因会话复用被校正为 Rework；其任务卡、Evidence 和 hash 已成为历史审计链，本次实施不追溯修改。
- P3-049 的后半部分已经包含严格的本地和非范围限制：工程资产只读、仅隔离临时副本、不连接真实 DB/Vault/用户文件/Tauri/IPC、不启用网络或云服务、不修改 PM 账本、不关闭风险、不冻结资产。
- 现有安全边界本身充分且严格；缺口是这些边界出现得较晚，任务开头没有先声明“用户拥有并授权、本地合成环境、防御性验证、不得扩展到外部目标”。
- 实施前，`lifeos/templates/TASK_BRIEF_TEMPLATE.md` 没有统一的“授权与安全语境”区块。
- 实施前，`lifeos/AGENT_BRIEFING_PACK.md` 已说明 Agent 权限边界，但没有用一段紧凑文案明确声明 LifeOS 工作区由用户拥有并授权维护，安全相关术语用于本地防御性工程验证。
- 实施前，`lifeos/PM_OPERATING_MODEL.md` 已要求任务写清范围、非范围、权限和确认边界，但没有规定双用途工程任务必须把授权语境前置到提示词首部。

## 3. 合理推断

- P3-040 至 P3-049 工程线反复包含 `bypass`、反例攻击、权限、改绑、重建、撤回、删除、控制包络等词；单个词不构成问题，但在缺乏首段授权语境时组合成较强的双用途外观。
- P3-049 使用 `gpt-5.6-sol` + `xhigh` 且属于长上下文独立复评。官方资料提示长会话可能放大重复提示内容，因此已经多次被标记的会话不适合作为“清理语境后继续执行”的首选。
- 在任务提示最前部加入真实、具体、可核对的授权与范围声明，能够帮助模型更早理解正当用途，但不能保证完全不再触发 safeguards；Trusted Access 是否获批仍由 OpenAI 的身份与安全机制决定。

## 4. 已采用的标准授权声明

已采用以下紧凑版本，并要求只在任务开头完整出现一次：

> **授权与安全语境：** LifeOS 是用户本人拥有并明确授权维护的本地项目。本任务仅限任务卡指定工作区、候选代码和合成测试数据，用于防御性代码审查、缺陷复现、修复验证与本地回归测试；不授权访问外部或第三方目标、真实用户数据或真实凭据，也不涉及未授权访问、网络扫描、真实攻击、持久化、数据窃取或安全控制规避，不授权把测试能力用于本项目范围之外。文中“攻击、反例、旁路、改绑、权限提升”等术语仅指本地合成环境中的负向验证。任务卡既有目录权限、只读资产、用户确认、独立评审和停止条件继续完整有效；如实际操作需要超出这些边界，立即停止并回报 PM。

设计理由：

- 先陈述所有权、明确授权、具体范围和防御性目的。
- 明确负向测试术语的项目内含义，但不改写或回避准确技术术语。
- 不把所有可能的危险行为逐项重复罗列，避免提示臃肿和重复放大。
- 明确声明本段不取代任务卡权限、确认、隔离和停止条件。

## 5. 实际修改的文件与影响

### 5.1 第一优先级：`lifeos/templates/TASK_BRIEF_TEMPLATE.md`

已在“启动语”之后、“任务信息”之前新增固定区块：

```markdown
## 授权与安全语境

对于涉及权限、撤回、删除、安全边界、反例或其他双用途技术语义的任务，PM 必须在此填写真实、具体、可核对的授权与防御性用途声明。声明应位于任务提示前部，只陈述一次，不得用于扩大范围或规避安全机制。

授权声明：
```

影响：所有新任务卡获得显式字段；普通低风险任务可填 `N/A — 不涉及双用途安全语义`。不追溯重写历史 Accepted 任务卡。

### 5.2 历史任务 `LIFEOS-P3-049`

不追溯修改 P3-049 任务卡。该任务现已形成专项 Review、Evidence、PM Review 和主账本记录，倒改任务提示会破坏历史可审计性，并不能补足已经缺失的全新会话隔离。

影响：P3-049 继续保持 `Accepted / PM Adjusted to Rework`。若用户以后授权再次复评，必须创建新任务卡，并从本次更新后的模板生成真实、前置、任务特定的授权声明；模型、推理强度、工程只读、独立性和判定条件均不得降低。

### 5.3 第二优先级：`lifeos/PM_OPERATING_MODEL.md`

已在“任务下发标准”附近新增“涉及双用途安全语义时必须前置授权与用途声明”的 PM 规则，并明确：

- 只描述真实授权，不为通过分类器编造背景。
- 不删除必要技术术语，不更改测试预期，不弱化 evidence。
- 声明不扩大目录、外部系统、真实数据或破坏性操作权限。
- 任务实际越界时必须停止并回 PM，而不是依赖通用授权句继续。

影响：形成 PM 稳定下发规则；不改变任何产品、架构、数据模型或 AI 权限冻结结论。

### 5.4 第二优先级：`lifeos/AGENT_BRIEFING_PACK.md`

已在“当前组织方式”前部增加一段项目级授权事实：LifeOS 工作区由用户拥有并授权维护；涉及安全和权限的工程任务默认只在任务卡指定本地/合成边界内用于防御性验证；具体授权仍以当前任务卡为准。

影响：跨 Agent 同步时不再依赖用户手动补充同一背景，但不会给予专项 Agent 新权限。

### 5.5 本次不修改

- 根目录 `AGENTS.md`：它影响所有会话且当前已有完整安全与范围规则。为遵守“规则只陈述一次、提示保持精简”，本次先在任务模板、PM 规则和 Agent briefing 落地；若后续仍持续误判，再评估是否需要根规则补充。
- `TASK_REGISTRY.md`、`FREEZE_STATUS.md`、`RISK_LOG.md`：本轮不改变任务、冻结、风险或阶段状态，不更新这些账本。`DECISION_LOG.md` 仅记录用户已授权稳定流程修改；`CURRENT_STATUS.md` 仅同步该治理决策，不改变当前任务指针。
- 历史 Accepted 任务卡：不追溯修改，避免破坏历史 evidence 与 hash 语义。

## 6. 当前 P3-049 任务线的处理方式

1. P3-049 保持 `Accepted / PM Adjusted to Rework`，不倒改任务卡、Review、Evidence 或 hash。
2. 本次整改不自动创建再次复评任务，也不恢复工程基线、关闭风险、冻结资产或进入下一阶段。
3. 如果用户以后采纳 Rework 并授权再次复评，PM 应创建真正全新的隔离 Codex 任务，继续使用 `gpt-5.6-sol` + `xhigh`，不得为减少提示切换到低配模型。
4. 新任务提示依次呈现：授权与安全语境 → 任务信息 → 本地/只读范围 → 具体反例矩阵 → 停止条件。
5. 若新会话仍触发 safeguard：保留原任务范围，不循环重发同一高密度提示；检查 Trusted Access 状态，使用产品反馈入口报告正当防御性任务误判，并回 PM 记录“外部安全机制阻塞”。不得通过删掉安全边界、模糊测试目标或拆成隐蔽步骤规避。

## 7. 风险与控制

| 风险 | 影响 | 控制 |
|---|---|---|
| 通用声明被误解为无限授权 | Agent 可能扩大范围 | 声明明确仅限任务卡目录、合成数据和当前目的；越界立即停止 |
| 为降低误判而弱化技术术语 | 独立复评质量下降 | 保留 attack/bypass 等准确词，并说明它们仅指本地负测 |
| 声明重复出现在多处 | 长提示反而放大相关语义 | 任务提示内完整声明只出现一次；稳定文件只定义规则和默认事实 |
| 追溯修改历史任务卡 | 破坏 evidence/hash 与历史可审计性 | 只修改未来模板，不回写 P3-049 或其他历史任务 |
| 通过换模型回避安全检查 | 降低 P0 独立复评质量 | P3-049 模型路由保持不变，安全提示不作为降级理由 |
| 将语境整改误写成风险关闭 | 项目状态失真 | 本轮不更新任何风险、冻结、阶段或任务状态账本 |
