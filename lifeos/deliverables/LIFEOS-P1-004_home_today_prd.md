## 1. 结论标记与一句话定义

- **[事实]** V1 服务技术型独立产品构建者的“5 分钟上下文恢复与下一步确认”，价值排序为“找回 > 下一步 > 今日重点”。Must 要求以 Project 恢复上下文，证据充分时提供至多 1 个候选，否则显示缺口；1–3 个仅是呈现上限。
- **[建议]** 一句话定义：**安静、可核对的个人外脑入口，帮助用户选择 Project、恢复上下文，在证据充分时确认下一步，并随时捕获原文。**
- **[推断]** “今日”表达可继续的上下文，不汇总全部任务、日程和告警。

## 2. 背景

首页承接“找回—确认行动—反馈”并保留捕获；其差异是恢复跨工具上下文、呈现来源与缺口，再由用户决定下一步。

**[事实｜Stitch 只读观察]** 最新原型采用极简侧轨、单一主画布、底部输入和右侧 AI 提示；含问候、当前领域、继续进行、今日安排、最近痕迹 / 访问和 AI 关联。Kubernetes 排障主导首屏。

**[风险]** 运维内容主导会延续 R-0003、R-0011；AI 只说“我发现”却不显示来源、时效和缺口，会延续 R-0002。

## 3. 用户与场景

### 3.1 目标用户

V1 主用户维护 1–3 个项目，频繁跨工具切换，重视本地保存、来源、导出和模型边界；不服务团队运营。

### 3.2 核心触发时机

1. 早晨开工 / 午后恢复：选择 Project，看见停点、变化和已确认下一步。
2. 跨 Project 切换：明确边界，避免材料泄漏或误用。
3. 离开数日后返回：恢复决定、行动、变化、未处理材料和证据时效。
4. 收到新反馈 / 材料：判断是否改变原计划，必要时重新确认。
5. 无明确 Project：先捕获或主动选择；不得为填满页面编造重点。

## 4. 用户目标与产品目标

### 4.1 用户目标

- 在一次短暂浏览中回答：我正在继续哪个 Project、上次停在哪里、最近有什么有意义变化、当时为何这样决定、现在最合适的下一步是什么。
- 能回到原文 / 外部来源，分辨 AI 身份、确认状态和证据缺口。
- 能反馈和撤回，且不被 AI 代替承诺；能低摩擦记录并收到诚实保存回执。
- 感到掌控而非被“未完成数量、红点、告警、连续打卡”施压。

### 4.2 产品目标

- 验证首页能否成为可信的“项目恢复 + 下一步确认”入口，完成最小闭环。
- 让来源、AI 身份、证据、授权和反馈可理解、可追溯、可撤回，并提供可测流程。

## 5. 范围

V0.1 包含：Project 入口与恢复摘要、有意义变化、候选下一步、快速捕获、最低来源 / 证据 / 权限 / 确认状态、交互状态和桌面优先响应式规则。

### 非范围

- 全局任务墙、完整日历、企业仪表盘、KPI、工单、运维 / 自动化运行台。
- 自动决定用户今天做什么，自动确认 Action / Decision / Assertion，或自动对外执行。
- 完整移动端功能、全量连接器、Obsidian 写回、跨 Project 全局智能排序。
- 其他页面、视觉设计稿、数据库 / API / 技术架构与真实用户测试。

## 6. 核心流程

1. **进入与定界**：显示当前 Project 及切换入口；无法可靠选择时由用户主动选择，不以“领域”替代 Project。
2. **恢复上下文**：显示停点、变化、决定 / 开放事项和证据缺口；可回到 Source / Artifact。
3. **评估建议**：证据充分时显示 1 个主候选下一步；只有确有独立价值时再显示第 2–3 个，且不抢占恢复信息。
4. **核对与反馈**：用户查看理由、关键证据、反证 / 缺口、生成时间和适用 Project；确认、编辑后确认、拒绝、忽略或稍后处理。
5. **执行后反馈**：仅已确认 Action 可完成 / 延期并保留反馈；候选不能直接“完成”。
6. **随时捕获**：输入原文后选择最小去向或默认进入 Inbox / 当前 Project 候选归属；只有耐久提交后显示“已保存”。
7. **条件降级**：来源、权限、证据、网络或生成异常时保留用户权威内容，标明缺口，不展示貌似完整的旧建议。

## 7. 信息结构与模块需求

页面信息优先级固定为：**当前 Project 与恢复上下文（P0）→ 候选下一步（P0）→ 快速捕获（P0）→ 近期变化（P1，可并入恢复包）→ 今日安排（P1，仅与当前 Project / 用户确认行动相关）→ 最近痕迹（P2，首屏以下）**。

| 模块 | 用户问题 | 最低内容 | 关键规则 |
|---|---|---|---|
| A. Project 选择 | “我在哪个上下文？” | 日期、当前 Project、切换、必要状态 | 领域仅作次级归属，不替代 Project |
| B. 从这里继续 | “上次做到哪、为何？” | 停点、时间、关键决定、开放事项、证据与缺口 | 首屏唯一主角；原文与“AI 整理”不可混写；可回证据 |
| C. 有意义变化 | “离开后发生了什么？” | Project 内 Event、来源、新材料 / 反馈、状态变化 | 只呈现会改变理解或下一步的变化，不堆日志 |
| D. 候选下一步 / 今日重点 | “现在最值得做什么？” | 动作 + 对象、Project、AI 建议身份、理由、关键证据、时效、缺口、确认状态 | Must 最低为证据充分时 1 个；确认前不是承诺或当前 Next Step；可无建议 |
| E. 今日安排 | “我已经确认今天要做什么？” | 用户已确认 Action / Commitment、时间条件；可完成 / 延期 | 与 AI 候选分区；不拉取全局所有任务；不得用红色欠债式数字施压 |
| F. 快速捕获 | “我想先记下来。” | 文本、附件 / 来源指针、保存状态 | 原文身份明确；输入后再展开去向；AI 不静默改写 |
| G. 最近留下的痕迹 | “我最近接触过什么？” | 2–3 个有意义 Artifact / Project 入口、来源身份、相对时间 | 首屏以下；不以图库装饰替代真实内容，不展示与恢复无关的最近访问长列表 |
| H. AI 边缘提示 | “有无值得我注意的新关联？” | 一次一条低打扰提示、AI 身份、关联理由、来源、时效、查看 / 忽略 | 默认收起或靠边；无新证据时不重复被拒建议；不使用告警语气制造紧迫感 |

### 7.1 内容身份的最低视觉语义

不在本文冻结颜色或组件，但身份必须在文字、图标 / 标签和操作逻辑至少两层可辨：

| 身份 | 必显信息 | 不得表达为 |
|---|---|---|
| 用户原文 | “你的记录 / 原文”、保存时间、所属 Project、打开原文 | AI 摘要或已确认事实 |
| 外部来源 | 来源名称 / 类型、定位、版本 / 访问时间、当前可达性 | LifeOS 自有原文；外部主张也不是用户确认事实 |
| AI 整理 / 生成 | “AI 整理”、输入范围、生成时间、来源入口 | 原文、事实或用户决定 |
| AI 推断 | “AI 推断”、支持与反对证据 / 缺口、适用范围、时效 | 确定事实 |
| AI 建议 / 候选 Action | “AI 建议 / 未确认”、动作、理由、证据、依赖、时效 | 用户承诺、已排定任务或系统命令 |
| 用户确认内容 | “你已确认”、确认对象 / 版本、时间；仍保留最初身份 | 把 AI 来源历史改写成“用户原本说过” |

## 8. 当前 Stitch 继承 / 调整 / 移出清单

### 8.1 建议继承

- 极简侧轨、单一主画布及实体 / 悬浮层级，避免后台感。
- “继续进行”单一主面改名“从这里继续”，作为恢复入口。
- 底部快速输入仅在输入后展开去向；右侧 AI 提示保持低打扰。
- 首屏以下少量“不对称最近痕迹”，仅展示真实可追溯内容。

### 8.2 必须调整

- “当前领域 · IT 运维”改为可理解的当前 Project；领域仅作次级信息。样例需覆盖产品构建、学习 / 研究和个人事务，不让 IT 运维成为默认身份。
- 运维排障可作一个 Project 样例，不可垄断首页；主面须补充停点、变化、决定理由、未处理项和证据缺口。
- “今日安排”拆清用户已确认行动与 AI 候选；未确认建议不得进入同一时间流。
- AI 关联提示须显示 Source / Artifact、时间、理由、缺口、AI 身份与反馈入口；不显示未经校准的伪精确置信度。
- “关联 4 条知识”等数量改为可展开证据概览，数量不能代替可靠性。
- 快速输入须显示保存中、已耐久保存、离线待同步 / 未耐久、失败重试等诚实状态。
- 原型缺失的空态、权限 / 证据 / 来源失效态、反馈后状态和响应式行为须后续验证。

### 8.3 建议移出首页首屏

- 最近访问长列表、自动化 / 服务状态、工单 / 告警、节点监控及 KPI。
- 与当前 Project 恢复无关的全局日程与所有未完成任务。
- 装饰性架构图或图库图片；图片仅在作为可追溯 Artifact / 证据时进入主面。
- 智能体日志、模型运行状态、内部审计明细；必要状态只以用户可理解的最小说明出现。

## 9. AI 规则

1. 首页 AI 限 L0–L2：检索、整理、恢复摘要、少量建议。L3 未被 PRD逐项指定且 SP-04/05/06 与理解验证未通过时降为 L1 展示。**本文不建议 V0.1 放行 L3。**
2. 每条主建议必须呈现：输出身份、所属 Project、动作与对象、生成 / 更新时刻、时效、理由、关键证据入口、反证 / 证据缺口、当前确认状态、确认 / 编辑 / 拒绝 / 忽略入口。
3. 不强制显示数值置信度；优先说明不确定原因，例如“仅依据一条两周前的记录”“两个来源冲突”。
4. 证据充分才建议；证据不足、来源不可达、授权失效、Project 边界不明、高风险判断或用户已拒绝且无新证据时，降级为提问、证据缺口或“暂无可靠建议”。
5. 接受只确认当前对象、版本和用途；编辑后接受保留差异。忽略不等于拒绝 / 完成；完成仅适用于已确认 Action；撤回追加 Feedback，不覆盖历史。
6. AI 输出因输入变化可 stale；因权限 / 删除 / 安全条件失效必须 invalid，并退出正常展示、搜索、排序、建议和再派生。用户曾确认但证据失效的对象保留历史，标“证据不可用 / 待复核”。
7. 心理、医疗、法律、财务等高风险内容不做主动诊断、评分或 L3–L5；首页最多谨慎显示信息辅助 / 草稿，并提示人工或专业复核。

## 10. 数据、来源与权限

### 10.1 领域语义映射

- `Project`：页面的首要上下文边界；不是企业容器，也不自动授予权限。
- `Source / Artifact`：恢复、变化和建议的证据；用户能打开可访问原文或定位。
- `Event / Decision / Action / Assertion`：组成停点、变化、理由、开放行动与陈述；各状态分离。
- `Derivation`：恢复包、摘要、推断、建议与关联；保留来源、授权、版本、时间和状态。
- `Feedback`：确认、拒绝、纠正、忽略、完成、延期、撤回的追加历史。
- `Authorization`：限定主体、范围、动作、目的、位置和时效；政策包络不合格时拒绝。
- `Link`：建议与证据、内容与 Project 的关系；候选 Link 不扩大授权。
- `AuditEntry`：记录关键操作的最小不可还原说明；首页不展示企业式日志流。

上述对象仅是语义映射，不代表每个对象都成为 UI 模块或数据库表。

### 10.2 四类命令在首页的最低表达

首页不承担完整设置，但相关上下文菜单必须使用清楚名称和结果预览；不得只写“移除”：

| 命令 | 首页最低入口 / 反馈 | 必须明确不等于 |
|---|---|---|
| `revoke_processing` 撤回处理许可 | 从 AI 证据 / 权限提示进入；说明哪些搜索、建议和模型处理将停止，并显示已接受、活跃已阻断、清理中 / 失败 / 供应商受限 | 不等于断开 Source 或删除原文 |
| `disconnect_source` 断开来源 | 从来源不可达 / 来源菜单进入；说明停止继续读取，同步及既有副本将按独立保留选择处理 | 不等于删除已保存内容或撤回 Feedback |
| `delete_content` 删除内容 | 从用户原文 / LifeOS 副本菜单进入；显示 LifeOS 可控范围、外部原件边界、依赖派生失效和清理状态 | 不得只停用却保留可识别副本；不得声称删除外部原件 |
| `retract_feedback` 撤回反馈 | 从“你已确认 / 拒绝 / 纠正”状态进入；追加撤回并重算当前状态 | 不删除内容、不断开来源、不抹去历史反馈 |

组合意图须组合命令。只有活跃读取、搜索、建议、队列和新模型调用均已阻断，才可表达“已停止使用”；物理清理状态另行显示。

### 10.3 条件性能力

- 本地耐久保存与诚实回执依赖 SP-01；失败阻断 Stage 3。
- Obsidian 仅为 Should + 条件项，依赖 SP-02/03；失败降级为手工导入 / 来源指针或移出 V1，不影响最小首页闭环。
- 来源链 / 派生证据依赖 SP-03；授权与第三方边界依赖 SP-04；四命令传播依赖 SP-05；持久 L3 依赖 SP-06；可信恢复与非逐字泄漏依赖 SP-07；导出不复活依赖 SP-08；容量依赖 SP-09。
- 向量 / 跨源关联未证明增益时降级为 FTS + 元数据和用户选定 Project；证据身份与权限过滤不可降级。

## 11. 交互状态

| 状态 | 最低体验要求 |
|---|---|
| 默认态 | 一个当前 Project、一个恢复主面、至多一个主候选下一步和快速捕获；次级内容后置 |
| 首次 / 数据空状态 | 解释“先记录或选择一个 Project”；提供快速捕获与导入 / 来源指针入口，不展示伪建议 |
| Project 无历史 | 显示已选择 Project 但暂无可恢复内容；引导记录当前停点，不自动填充通用任务 |
| 加载态 | 保持已有内容；区分正在读来源 / 生成 AI，不全屏阻塞 |
| 错误态 | 区分保存失败、读取失败、AI 失败；用户原文和既有确认内容仍可用，提供重试与问题范围 |
| 离线态 | 可捕获；明确“已本地耐久保存 / 待同步”或“尚未保存”，禁止含糊“已保存”；云 / 第三方 AI降级并说明 |
| 权限不足态 | 指明缺少哪个 Source / Project / 用途 / 位置许可；提供最小授权或继续无 AI，不用一个总开关替代数据流 |
| AI 生成中 | 可中断；简述输入范围与处理位置；旧结果过期须标记 |
| AI 结果待确认 | 明示 AI 身份、证据、时效、缺口与确认 / 编辑 / 拒绝 / 忽略；不进入“今日已安排” |
| 用户已确认 | 显示确认时间和具体版本；保留 AI / 外部来源身份；可完成、延期、撤回确认 |
| 用户已驳回 | 退出主位置；无新证据不重复推送；可查看历史或撤回拒绝 |
| 用户已忽略 | 本次隐藏或按用户选择稍后显示；不标记为错误、拒绝或完成 |
| 用户已纠正 | 显示用户修正版及其适用范围；旧 AI 版本可追溯但不再作为当前结果 |
| 来源不可达 | 标记相关证据不可打开、上次可用时间；恢复包 / 建议 stale 或重建为合法子集，提供重连或断开来源 |
| 证据不足 / 冲突 | 显示具体缺口 / 冲突和可补充动作；不通过肯定语气或伪置信度掩盖 |
| 无可靠建议 | 使用中性文案“暂无可靠建议”；允许继续查看原文、主动选择下一步或捕获，不视作系统失败 |
| 证据失效待复核 | 用户确认历史仍可见，但退出自动排序 / 建议依据；提供补证或重新确认入口 |
| 命令处理中 | 区分已接受、活跃已阻断、清理中 / 失败 / 受限 / 完成；不虚报完全清理 |

## 12. 响应式要求

- **桌面宽屏**：单一主列承担恢复和行动；侧轨窄；AI 提示按需出现，不形成永久第三栏。真实证据图可内部左右排布。
- **窄桌面 / 窗口缩放**：侧轨收为图标或菜单；主恢复面的图片移到文字下方；AI 边缘提示变为可关闭浮层 / 内联提示；底部输入宽度随容器变化，不遮挡主操作。
- **移动端 / 极窄窗口**：仅定义可阅读降级，不承诺完整移动端。顺序固定为 Project → 恢复 → 候选下一步 → 已确认安排 → 最近痕迹；快速捕获为底部单入口，详细证据和反馈动作进入抽屉 / 次级页。
- 任意宽度不得隐藏 AI 身份、来源、确认、缺口或离线 / 权限状态；键盘、焦点、触控和减少动态效果待原型验收。

## 13. 验收标准

1. 用户能识别当前 Project，并找到停点、关键变化和下一步候选 / 无建议原因。
2. 首屏只有一个恢复主角；不出现 KPI、运维监控、自动化日志或全局任务墙。
3. 恢复摘要 / AI 建议能区分各内容身份与确认状态，并可定位证据。
4. 证据充分时默认最多 1 个主候选；可少于 1 个；任何候选在确认前不进入用户已安排 / 已承诺状态。
5. 用户能完成确认、编辑后确认、拒绝、忽略、纠正、完成、延期和撤回的适用动作；系统不混淆其语义。
6. 四类命令在相关上下文中名称、影响预览和状态反馈清楚，不用“移除”互相冒充。
7. 覆盖第 11 节全部状态；证据不足、来源不可达、权限不足、离线与 AI 失败均有不误导的降级。
8. 快速捕获保留原文，只有耐久提交后显示“已保存”；AI 整理不覆盖原文。
9. 各宽度均保持身份、来源、证据和反馈入口可达。
10. 所有条件性能力标注 Spike 依赖和失败降级；未把计划写成实测承诺。
11. 原型测试能使用真实或等价中断 Project，与用户现有拼接方式比较，而非仅评价美观。

## 14. 指标与验证合同

数字阈值尚无一手证据，**不在本 PRD 虚构冻结**。原型 / 上线后联合观察：

- **恢复 / 行动价值**：能否找到停点、变化、理由与证据并确认下一步；相较现有方式的回查、跳转和犹豫是否减少。采用率须与纠正、拒绝和结果一起解释。
- **信任质量**：身份 / 来源 / 状态理解，证据定位，证据不足时的误信及撤回可发现性。
- **护栏**：原文静默改写、越权返回、未经确认重大动作、撤回后活跃使用遗漏、跨 Project 非逐字泄漏均为零容忍底线。
- **健康 / 反证**：认知负担、未完成焦虑和重复打扰；若仍需回原工具重拼、不愿连接来源、核对成本过高、首页被视作运维工具或信任底线失败，则价值未证实。

验证须使用真实或等价中断 Project，与现有工具基线对比。未改善时先收窄来源 / 信息面，再把 AI 收缩到恢复信息、缺口或单一候选。
