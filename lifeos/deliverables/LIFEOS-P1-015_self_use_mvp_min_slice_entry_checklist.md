# LIFEOS-P1-015｜自用版 MVP 最小切片准入清单

## 1. 任务边界与结论摘要

- **[事实]** 自用版开发准备已准入，技术 Spike 条件准入；正式 Stage 3 MVP 工程实现仍为 `Blocked / Not Allowed`。V1 范围、核心领域语义、AI 信任语义及首页 / 今日页 PRD 已冻结，但技术能力尚未实测。
- **[建议]** 后续 IA、Obsidian 条件需求与 SP-01 / SP-03 共用同一份最小切片合同：先证明“可信保存与可追溯恢复”，再增加来源、模型或同步广度。
- **[推断]** 对单人自用，单设备、本地优先、手选 Project、FTS-first、假模型足以验证闭环；若用户仍不能恢复上下文、核对证据并反馈，则增加模型或连接器没有准入价值。
- 本清单不冻结 PRD、Schema、API、技术栈或架构，不授权生产开发、真实敏感数据处理或外部用户验证。

## 2. 最小切片一句话定义

**[建议｜需 PM 确认]** 自用版 MVP 最小切片是：用户在单设备上捕获并耐久保存原文及来源指针，手动归入 / 选择 Project，以 FTS 与元数据恢复可核对的项目上下文，在有效授权和证据充分时获得至多一个明确标为未确认的 AI 候选下一步，完成确认、编辑、拒绝、纠正、完成或延期，并始终保有基础导出、删除及撤回后的活跃阻断。

## 3. Must / Should / Not Now

| 优先级 | 清单 |
|---|---|
| **Must** | 文本、链接、文件 / 来源指针捕获；耐久回执、原文与版本保护；`Source / Artifact` 分离及手选 Project；FTS + 元数据找回；可核对的恢复信息、证据缺口与“暂无可靠建议”；零或一个未确认候选（可用假模型）；`Derivation / Feedback / Authorization / AuditEntry` 最低语义与重要 `Link`；对象级确认与反馈；默认拒绝授权；四类命令语义分离；撤回 / 删除活跃阻断；基础导出。 |
| **Should** | Obsidian 只读接入（仅 SP-02 / SP-03 通过后）；文件正文解析；真实模型；来源变化提示；经证据证明有增益的向量 / 轻量重排；少设备同步。 |
| **Not Now** | Obsidian 写回 / 插件 / 双向同步；全量连接器；完整移动端、多人协作、企业后台；全局任务墙；自动替用户确认或执行重大行动；L4-L5 与长期自主 Agent；高风险诊断；微服务、Kubernetes、图数据库或独立向量库的提前建设。 |

## 4. 四类准入门槛

| 门槛 | 准入条件 | 退出 / 阻断条件 |
|---|---|---|
| **自用版开发准备** | 本清单经 PM 验收；后续任务明确继承 Must、非范围、证据与降级；只产出 IA / 流程、条件需求、任务卡、夹具和可丢弃验证。 | 任一任务把准备写成生产开发、扩大 V1、冻结架构或绕过底线时退出并返工。 |
| **技术 Spike** | 有单一假设、依赖、通过 / Partial / 失败标准与清理说明；复用无真实敏感数据的确定性夹具；环境可重复；故障注入和原始日志纳入证据；不调用付费资源、不建设生产系统。SP-01 与 SP-03 可作为首批并行骨架。 | 无法复现、只做顺畅演示、使用重要真实数据、缺失败分支，或 P0 不变量无法测量时不得开跑 / 不得判 Pass。 |
| **真实自用数据启用** | SP-01 Pass 前仅用合成、脱敏或可丢弃数据。SP-01 Pass 后，可在**本地且不作为唯一副本**的前提下启用低敏真实副本；进入恢复 / AI 链路前还须 SP-03 Pass。重要、不可重建或敏感数据须已有可验证备份恢复、基础导出与删除 / 撤回活跃阻断；任何云 / 第三方处理另须 SP-04 对对应路径 Pass，并取得具体授权。 | 丢失 / 覆盖、来源或身份混淆、越权入模、撤回后仍可活跃使用、无法导出，或把副本误作唯一权威数据时立即停用真实数据并回退夹具。 |
| **正式 MVP 开发** | SP-01 至 SP-09 完成；P0 底线全部 Pass，其余 Partial 有 PM 记录的范围调整；Gate 2/3/4 实测复审通过；技术架构完成独立评审并由 PM 冻结；Stage 2→3 其余硬门槛满足。 | 当前不满足，持续 `Blocked / Not Allowed`；本清单、IA、Obsidian 需求或单个 Spike 通过均不能解除阻塞。 |

## 5. 关键能力准入矩阵

| 能力 | 完成定义 | 验收证据 | 失败降级 | 阻断 |
|---|---|---|---|---|
| 捕获 / 保存 | 离线可捕获；仅耐久提交后显示“已保存”；原文版本不被覆盖 | SP-01 强杀、磁盘满、备份恢复、hash / 完整性报告 | 单写入者、缩小文件范围 | **是**；SP-01 前禁重要真实数据 |
| 来源 / Project | Source 与 Artifact 可分辨、版本可回溯；Project 由用户选择 / 确认且不扩权 | 夹具中跨 Project、无 Project、版本变化与来源定位查询 | 手选 Project、手工导入 / 指针 | 身份或跨 Project 泄漏为**是**；自动归类失败可降级 |
| 找回 / 今日恢复 | FTS + 元数据回答停点、变化、决定、未处理材料；证据不可达 / 冲突时显式缺口 | 固定查询集、恢复包及来源回查；首页默认 / 无建议 / 受限态走查 | FTS-first、减少恢复字段，不得删除证据 | 找不到可信来源或伪完整叙述为**是** |
| AI 候选 | 有效授权内生成零或一个未确认候选；证据不足时不生成 | SP-03 证据链；假模型确定性输出；输入版本变化失效 | 假模型、规则模板、仅显示恢复信息 / 缺口 | 身份、证据、授权失败为**是**；模型质量可降级 |
| 用户反馈 | 确认、编辑、拒绝、纠正、完成、延期、撤回均追加 Feedback；不逆写原文 / AI 身份 | 状态转换与历史重放；候选不经对象级确认不得转正 | L1 派生展示，不物化 L3 对象 | 用户权威被覆盖为**是** |
| 授权 | 主体、范围、动作、目的、位置、时效判定；默认拒绝，Project 不扩权 | 允许 / 拒绝 / 过期 / 撤回矩阵及实际发送字段 | 仅本地；禁用云 / 第三方 / 对应 AI | 越权路径为**是** |
| 撤回 / 删除 | 四命令不互相冒充；提交后读取、搜索、建议、队列与新模型调用零遗漏阻断；清理状态诚实 | 依赖传播、墓碑、备份恢复 / 重连“不复活”和故障日志 | 物理清理可异步追踪；活跃阻断不可降级 | **是** |
| 导出 | 导出原文、来源、版本、确认状态、业务重要派生 / 关系；可读且删除对象不复活 | 固定夹具导出核对；后续 SP-08 重导入 / 不复活报告 | 索引、向量、缓存不导出并可重建 | 基础导出失败为**是**；高级迁移可后置 |

## 6. 不可降级底线

可靠落盘；原文与不可覆盖版本；用户原文、外部来源、AI 派生 / 推断 / 建议、用户确认身份分离；关键输出可追溯；对象级确认；授权默认拒绝；四类命令分离；撤回 / 删除活跃阻断零遗漏及墓碑优先；基础导出；重大行动不得自动执行。任何底线失败均不得以“仅自用”“后续再补”放行。

## 7. 可接受降级项

单设备、本地优先、无云同步；用户手选 Project；FTS + 元数据优先且无向量；确定性假模型或仅恢复信息；手工导入 / 来源指针替代 Obsidian；文件只保留指针与元数据；L3 候选降为 L1 派生展示。降级不得改变内容身份、证据、权限、反馈或数据主权。

## 8. 后续任务依赖与输入要求

1. **核心 IA / 端到端流程**：只覆盖捕获、保存回执、Project 选择、恢复 / 无可靠建议、候选、反馈、四命令入口、导出；必须表达正常、未选、离线 / 权限受限、来源不可达和失败态，不新增全局工作台。
2. **Obsidian 条件需求**：固定为 Should；写明只读、目录排除、Source / Artifact 指针、分层授权、不写回及 SP-02 / SP-03 双 Pass 条件；失败回退手工导入 / 指针，范围结果需 PM 确认。
3. **SP-01 / SP-03**：共用 3 个个人 Project、跨项目 / 无 Project 材料、版本、候选 / 确认对象、授权组、假模型与故障注入夹具；使用同一对象 ID、版本、Derivation 包络、Feedback、Authorization、墓碑和结果包格式。SP-01 负责可信落盘，SP-03 负责可信身份 / 证据；两者不得各造语义。
