## 1. 结论摘要

**[已验证事实]** 本任务在明确授权范围内创建并复跑了 Python 标准库 + SQLite FTS5 的本地候选实现。固定合成语料含 60 条内容单元、4 个 Project、20 条标注查询，覆盖 Source、Artifact、ArtifactVersion、Derivation、Decision、Action、Link、Feedback、Authorization、AuditEntry 及正常、冲突、不可达、权限排除、撤回、删除、断源、证据失效、旧队列与跨 Project 状态。23/23 项断言通过，P0 失败 0。

**[已验证事实]** FTS + 元数据 / Project / 当前 Authorization / 状态过滤 + 轻量重排在本标注集上达到 Recall@20 1.00、关键查询 Recall@10 1.00、nDCG@10 1.00；权限泄漏为 0，重点结果证据完整性为 100%。deterministic semantic stub 与 hybrid 的 Recall@20 同为 1.00，相对 FTS 增益为 0.00，未超过预设 `> 0.05` 明确增益门槛。

**[结论]** SP-07 判定为 **Pass（严格限 60 条合成语料、内存 FTS5、deterministic stub、单进程候选实现层）**。本证据支持把 FTS + 元数据 + 权限 / 状态过滤 + 轻量重排保留为 V1 可信搜索底线候选，并支持结构化恢复包与 1-3 条有证据的未确认下一步候选。

**[建议｜需 PM 确认]** 向量能力在本次未证明明确增益，V1 应后置向量作为条件能力；后续只有在更真实、更多同义/概念查询的标注集上证明净增益，并同时通过过滤召回、清理、容量与成本验证，才纳入默认路径。该建议不冻结搜索架构、索引、Schema、API、模型、分块或技术栈。

## 2. 验证边界与最小状态模型

最小状态模型将内容单元关联到 Project、Source、Artifact、精确 ArtifactVersion、Derivation、Link、Feedback、Authorization 与 AuditEntry，并保留确认、证据、冲突、来源、墓碑 / 撤回、用途和 queue generation。它用于验证可消费性、追溯与降级，不冻结数据库表或接口。

搜索执行顺序是：当前 Authorization 与用途检查；tombstone / retract、Source、证据与 generation 状态检查；Project 边界与元数据过滤；FTS 或 deterministic semantic 召回；轻量重排；证据包络投影。Project、文件夹、相似内容或 Link 都不能扩权。`local_search` 命中不会自动获得 `project_recovery` 或 `next_step` 用途。

语料为通用合成词汇；SQLite 仅驻留内存。pgvector、ANN、真实 embedding 和真实模型均未验证。

## 3. 查询、标注与检索对比

20 条查询覆盖精确、同义、最近变化、确认 Decision、开放 Action、反馈后候选、冲突、不可达、权限排除、跨 Project 干扰、删除、撤回、断源和旧队列。`golden_labels.json` 保存相关 ID 与预期空结果原因。

FTS-only 使用 SQLite FTS5；metadata 层约束 Project、类型与确认状态；重排组合词项、FTS 次序、元数据与新近度。semantic stub 只用固定同义词和 token Jaccard。hybrid 合并候选后执行相同门控。

| 方案 | Recall@20 | 关键 Recall@10 | nDCG@10 | p95（60 条内存样本） |
|---|---:|---:|---:|---:|
| FTS-only + 过滤 / 重排 | 1.00 | 1.00 | 1.00 | 见机器结果，远低于 300ms |
| semantic-only stub | 1.00 | 1.00 | 1.00 | 见机器结果 |
| hybrid + 过滤 / 重排 | 1.00 | 1.00 | 1.00 | 见机器结果，远低于 2s |

**[推断]** 当前合成需求不需要向量即可达标，但不能外推到真实模糊表达、长文和跨语言查询。stub 增益为 0，且真实 embedding 的隐私、清理与容量未验证，不能作为 V1 默认依赖。

## 4. 权限、删除、撤回与冲突处理

三条消费路径分别按 `local_search`、`project_recovery`、`next_step` 重新判定权限，不能复用较宽结果。测试中权限拒绝、删除、撤回、断源、证据不可用和旧 generation 进入不允许的消费路径合计为 0；跨 Project 串扰为 0。

删除 / 撤回 / 断源内容不进入搜索结果、恢复包活跃区或候选建议。旧队列输出在 generation 不匹配时丢弃。来源不可达不使用旧读取结果生成建议，而返回 `source_unreachable`。唯一证据失效的用户确认对象不删除其历史身份，但只进入 `review_required` 缺口区并退出自动排序。冲突证据允许作为“待复核”结果显示，双分支不自动合并，且不进入下一步建议。

这继承 SP-04 的逐用途授权、SP-05 的提交即阻断和 SP-06 的旧队列非权威。字段级 LWW、旧恢复包或旧队列不能覆盖用户权威状态。

## 5. 精确证据与恢复包

每条重点搜索结果机器检查以下字段均存在：Source、ArtifactVersion、Derivation、Link、用户确认状态、生成时间、证据状态、冲突状态、权限状态与 Authorization。证据完整性为 100%。原文、外部来源、AI 派生、AI 候选和用户确认没有被压成同一身份。

恢复包按 Project 边界从当前可消费对象组装停点、近期 Event、确认 Decision、开放 Action、未处理材料、冲突 / 缺口及反馈入口，每项附证据。Alpha 包因冲突与唯一证据失效标记 `degraded_review_required`。

50 次本地恢复包组装的 p95 远低于 3 秒，但仅对应 60 条内存样本。**[限制]** 这不是 10 万 / 100 万内容规模、磁盘 IO、跨进程或生产 SLA；容量与真实延迟必须交由 SP-09 验证。

## 6. 候选下一步与 AI 身份

deterministic 规则优先从当前确认且开放的 Action 生成候选，没有开放 Action 时才考虑当前未处理材料。每个 Project 最多 3 条；每条标记 `ai_candidate_suggestion / unconfirmed`，含 1-3 条证据、理由、时效、冲突状态、权限缺口、置信边界及 `accept / edit_accept / reject` 反馈入口。

规则不创建或确认 Action、Decision、Link；用户接受后才可创建权威对象。拒绝候选、冲突、失效、搜索专用材料、删除 / 撤回 / 断源与旧队列均未进入建议。

**[推断]** 先结构化检索与门控，再用 AI 组织表达，更容易守住来源、权限和失效边界。本次不证明真实模型的事实一致性或提示注入防御。

## 7. 失败与降级状态

空结果区分 `no_match`、`permission_restricted`、`source_unreachable`、`source_disconnected`、`deleted_or_retracted`、`evidence_unavailable`、`feedback_excluded` 与 `stale_generation`。用户状态分别解释为无匹配、当前权限受限、来源暂不可达、来源已断开、内容已停止使用、证据不可用、已按反馈隐藏、旧状态已丢弃。

冲突不是普通空结果：显示“证据冲突，未自动合并，需要复核”。唯一证据失效显示“保留用户确认历史，但证据不可用”。若未来组装超阈值，应返回 `assembly_delayed`，先显示已有可核对构件，不让 AI 补写缺失上下文。详细样例见 `failed_queries.md`。

## 8. 指标、隐私与可重复性

机器结果记录 Recall、nDCG、首条有效结果率、空结果原因、泄漏、完整性和延迟。日志只含作用域化 ID、动作、结果与政策版本；隐私扫描命中 0。

证据可用一条命令复跑：`python3 lifeos/spikes/SP-07/run_spike.py`。脚本生成语料、标注、三路检索结果、恢复包、候选、矩阵与审计样例。证据包 `README.md` 提供逐文件入口。

## 9. 失败边界、风险与后续影响

**[风险]** 60 条规则化语料存在天花板效应；真实错别字、跨语言、长文和概念查询可能降低 FTS 召回。本次未验证分块、并发、磁盘、10 万 / 100 万规模、中文分词或可访问性。真实 embedding 还会新增失效清理、存储、替换与过滤后 ANN 召回风险。

**[建议]** SP-09 复用并扩充难例，验证规模、索引更新、p95/p99、恢复包和 Source 级删除；再评估向量时先做 exact 对照与过滤后召回，不直接引入独立向量库。
