## 3. 首页渐进披露合同

### 3.1 三层定义

| 层级 | 目的 | 必须表达 | 不应放入 |
|---|---|---|---|
| 首屏必显 | 让用户恢复当前 Project 并决定是否确认下一步 | 当前 Project 及切换入口；停点 / 一项关键变化；内容时效；一个关键证据入口；存在时的关键证据缺口；零或一个候选下一步的“AI 建议 / 未确认”身份、动作、简短理由、时效或关键缺口及主要反馈入口；快速捕获 | 完整来源链、六维授权、模型 / 工作流版本、处理位置细节、审计记录、清理状态机、全局任务 / 日程 / 自动化状态 |
| 详情可达 | 支持用户核对、纠正和理解依据 | 决定理由；完整证据与来源定位；输入范围；支持证据、反证与冲突；生成时间；内容版本；处理位置；适用 Project；确认 / 纠正历史；命令影响预览 | 不得把详情缺失伪装成首屏“可信标签”；详情层仍须区分用户原文、外部来源、AI 派生与用户确认 |
| 仅异常时显 | 让会影响可信恢复或用户控制的异常被及时看见 | 权限失败、来源不可达、证据冲突 / 失效、保存失败、活跃阻断失败、清理失败 / 供应商受限；说明影响范围和安全降级，并提供查看或处理入口 | 正常态不常驻权限矩阵、供应商状态、审计流或清理进度；异常也不得用运维告警墙表达 |

### 3.2 展示规则

1. 首屏的信息预算服务“我在哪个 Project、上次到哪里、现在是否有可靠下一步”，不是完整证明材料的平铺。
2. 关键证据入口必须首屏可见，但完整证据链按需展开；证据不足或冲突影响建议时，缺口升级到首屏，建议降级或不生成。
3. 正常态只显示用户可理解的内容身份和必要状态。授权维度、模型版本、审计、清理阶段等保留在详情；只有其异常实际影响当前内容时才提高显著性。
4. “暂无可靠建议”是合格状态：保留 Project 恢复、手动选择下一步和快速捕获，不以通用建议凑数。

## 4. 四类命令的首页责任边界

首页对每类命令只负责：**语义准确的上下文入口、明确作用对象、执行前影响摘要、流程完成后的最小回执**。范围选择、组合命令、副本保留选择、二次确认、详细进度、重试、失败原因和供应商限制进入详情层 / 专门流程。

| 命令 | 首页入口与影响摘要 | 必须转入详情 / 专门流程 | 首页最小回执 |
|---|---|---|---|
| `revoke_processing` 撤回处理许可 | 从相关 AI 内容 / 权限入口进入；指出将停止的处理及对象 | 扩大到多对象、Project、Source、目的或位置；派生与副本处置；明确确认 | “请求已接受 / 活跃使用已阻断”；若失败仅提示受影响范围并引导查看 |
| `disconnect_source` 断开来源 | 从 Source 上下文进入；说明停止继续读取，不等于删除副本 | 保留或删除既有副本、组合 `delete_content`、重连 / 失败处理；断源并删除副本必须确认 | “来源已断开”及既有内容是否仍保留的简明说明 |
| `delete_content` 删除内容 | 从目标内容菜单进入；显示目标、LifeOS 可控边界及依赖影响 | 所有范围选择、二次确认、外部原件边界、清理进度与失败；不得一击执行 | “删除请求已接受 / 已停止活跃使用”；不虚报外部原件或所有副本已清理 |
| `retract_feedback` 撤回反馈 | 从具体“你已确认 / 拒绝 / 纠正”状态进入；说明重算当前状态 | 选择目标反馈、依赖影响和必要确认；不得与删除、断源混用 | “已追加撤回记录，当前状态已重算” |

组合意图必须显式组合命令。`delete_content`、扩大范围的 `revoke_processing`、断源并删除副本均不得在首页一击执行；`retract_feedback` 始终追加历史，不覆盖或逆写既有 Feedback。首页不展示完整清理状态机，因此不成为权限 / 清理控制台。

## 5. Stitch 继承边界

### 5.1 可以继承

- 单一主画布、克制侧轨、恢复信息作为注意力主角。
- AI 提示低打扰、快速捕获易达、次级信息后置等空间 / 注意力原则。

### 5.2 不得继承

- 现有导航广度，或以“领域”替代当前 Project。
- IT 运维 / Kubernetes 默认样例与后台、开发者工具叙事。
- 全局任务、日程、智能体、自动化或服务运行状态。
- 图片比例、颜色、玻璃效果、尺寸等视觉参数。
- 当前 AI 文案、现有交互实现及任何由静态画面暗示但未经 PRD 定义的行为。

**[建议]** 后续原型主画面至少采用一个非运维 Project；另以空态或“暂无可靠建议”态作为第二组关键画面。运维只能作为普通 Project 样例，不能成为默认首页身份。上述约束不冻结视觉实现，也不授权本任务修改 Stitch。

## 6. Project 选择来源与未选态

| 状态 | 成立条件与页面表达 | 允许行为 | 禁止行为 |
|---|---|---|---|
| 用户本次选择 | 用户在当前会话明确选择；显示 Project 名称并可切换 | 仅在有效授权和该 Project 合法证据内生成恢复 / 建议 | 以 Project 归属代替 Source / Artifact 授权 |
| 最近确认延续 | 沿用最近一次由用户确认的 Project；首屏标明“沿用你上次确认”并可切换 | 作为当前 Project 使用；用户切换后立即以新边界重判 | 将“最近访问”或系统预测冒充用户确认 |
| 系统候选 | 系统依据可说明的授权内证据提出；清楚标为“候选 Project / 待选择”并给出简短理由 | 用户确认后才成为当前 Project；可忽略或手动改选 | 静默生效、预先生成跨 Project 恢复或建议、用候选 Link 扩权 |
| 未选态 | 没有本次选择、可靠的最近确认延续或用户尚未接受候选 | 快速捕获（进入 Inbox 或待归属）、手动选择、查看候选依据 | 生成跨 Project 恢复、跨 Project 建议或全局智能排序 |

页面始终显示当前 Project 或明确的“尚未选择 Project”，并提供切换入口。所有恢复、展示、保存和再派生仍按 `Authorization` 与输入限制重判；Project 是上下文边界，不是授权来源。
