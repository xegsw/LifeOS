# 本地 UI 动态 Evidence 闭环表模板

适用：任务卡要求本地 `file:` UI 的动态或视觉 Evidence 时。执行侧必须在提交 PM 前完成；每一行对应任务卡的一项**具体动态动作**，不可用概括性测试数替代。

| 验收项 ID | 具体动作与前置状态 | 预期可观察结果 | 结构化结果 ID | 视觉／日志 Evidence 路径 | SHA-256 | 状态（PASS / N/A / NOT IMPLEMENTED） | N/A 理由 |
|---|---|---|---|---|---|---|---|
| D-XX |  |  |  |  |  |  |  |

## 强制规则

- `PASS` 必须同时有实际操作、逐项结构化结果、至少一份可复核的视觉或日志 Evidence，以及该 Evidence 的 SHA-256。
- `N/A` 只能在任务卡明确不适用时使用，并写明原因；`NOT IMPLEMENTED` 不得写成 Pass。
- 动作不得相互替代：刷新不证明关闭重开；AX／静态可聚焦不证明实际 Tab／Enter；静态源扫描不证明 Chrome 动态行为。
- 对 `file:` UI，预检、首次、重复／幂等、拒绝／撤回、失败清理、刷新、关闭重开、键盘路径、任务卡列出的页面状态及宽／窄屏都必须各自列行；不适用项仍须显式列行。
- 提交前 runner 或自检脚本必须读取该表／等价 JSON，确认所有必填行均为 PASS 或有任务卡允许的 N/A 理由；否则自检结论只能为 `Not Pass`，并在同一能力包内补齐。
